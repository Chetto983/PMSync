## Critical Gaps (Blockers)

### 1. CONS-02: ConsentGuard Not Applied to AI Routes (HIGH)

**What exists:** `ConsentGuard` + `@RequiresConsent` decorator in `ComplianceModule`. 5 passing tests. `ConsentEnforcementService` with fast consent checks.

**What's missing:** Zero `@UseGuards(ConsentGuard)` or `@RequiresConsent()` decorators on any AI endpoint (`POST /voltagent/chat`, embedding generation, etc.). The guard is never invoked at runtime.

**GDPR Impact:** Users can call AI processing endpoints without having granted consent. Violates GDPR Article 6 (lawfulness of processing).

**Fix:** Add `@RequiresConsent('ai_email_processing')` to VoltAgent chat controller and embedding endpoints. Alternatively, register `ConsentGuard` as a global `APP_GUARD` with `@SkipConsent()` on exempt routes.

### 2. LEGAL-01 / LEGAL-02: LegalAcceptanceGuard Not Mounted (HIGH)

**What exists:** `LegalAcceptanceGuard` with `@SkipLegalCheck` decorator. `register.tsx` calls `acceptLegalDocument()` after registration.

**What's missing:** Guard is NOT registered as `APP_GUARD` in `app.module.ts` and NOT applied via `@UseGuards` on any controller. A user who bypasses registration flow (direct API call, OAuth) has full API access without legal acceptance.

**GDPR Impact:** Terms of Service and Privacy Policy acceptance is not enforced. The acceptance record from registration is fire-and-forget with no runtime enforcement.

**Fix:** Register `LegalAcceptanceGuard` as the second `APP_GUARD` in `app.module.ts` (after `ThrottlerGuard`). Add `@SkipLegalCheck()` to auth routes, health endpoints, and compliance routes.

### 3. DRAFT-01 / DRAFT-02: Phase 19 Not Started (MEDIUM)

**What exists:** Requirement definitions in REQUIREMENTS.md. Phase listed in ROADMAP.md under v3.1.

**What's missing:** No phase directory. No plans. No implementation. Zero code.

**Options:** (a) Implement Phase 19, (b) Defer DRAFT-01/DRAFT-02 to v3.2 by moving them out of v3.1 scope in ROADMAP.md and REQUIREMENTS.md.

### 4. TRIAGE-02: Triage Prompt Quality (MEDIUM)

**What exists:** Full mechanical wiring: Zap button → Zustand store → router.push → useChatController auto-send → TriageRenderer.

**What's missing:** The prompt sent to the LLM is `Apply AI label suggestions to these N emails: [UUID1, UUID2, ...]`. Raw UUIDs give the LLM no email content to analyze. The VoltAgent cannot reliably construct a `bulk_email_actions` call from IDs alone.

**Fix:** Include thread subjects/senders in the prompt, or use a format that instructs the LLM to call a lookup tool first.

### 5. ENC-03: Hash-Based Search Indexes Deferred (LOW)

**What exists:** `hashForSearch()` function in `field-encryption.utils.ts`.

**What's missing:** `hashField: null` for all entries in `encryption.config.ts`. Intentionally deferred — requires search redesign across 17+ query sites before Tier 2 fields can be encrypted.

**Impact:** Low. Only blocks future Tier 2 encryption (from, subject, displayName). No immediate GDPR exposure since Tier 1 body fields are already encrypted.
