Replace that block with just the fallback logic:

The full revised `handleDownloadAttachment` should be:
```typescript
const handleDownloadAttachment = useCallback(async (messageId: string, attachmentId: string) => {
  try {
    const blob = await emailsApi.downloadAttachment(messageId, attachmentId);

    const url = window.URL.createObjectURL(blob);
    const link = document.createElement('a');
    link.href = url;

    let filename = 'attachment';
    if (selectedEmailData) {
      const att = selectedEmailData.attachments?.find(a => a.id === attachmentId);
      if (att) filename = att.name;
    }

    link.setAttribute('download', filename);
    document.body.appendChild(link);
    link.click();

    document.body.removeChild(link);
    window.URL.revokeObjectURL(url);
  } catch (error) {
    // eslint-disable-next-line no-console
    console.error('Download failed', error);
    toast.error(t.common.genericError || 'Download failed');
  }
}, [selectedEmailData, t, toast]);
```

Note: The content-disposition header parsing is removed because `emailsApi.downloadAttachment()` returns `Promise<Blob>` not an Axios response. The filename is derived from the attachment metadata in `selectedEmailData` which is already available in scope.
