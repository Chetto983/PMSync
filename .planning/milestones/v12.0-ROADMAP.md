# Roadmap: PMSync v12.0 — UX Unification (4-Pillar Simplification)

## Overview

Transform PMSync from a 17-item sidebar application into a 4-pillar workspace (Mail, Calendar, Contacts, Tasks) with contextual CRM panels, a unified task system, command palette for power navigation, and AI-driven background automation. The journey starts with the most visible change (sidebar collapse), builds backend infrastructure (unified tasks), layers contextual intelligence (sidebars, hover cards), and caps with AI automation and a smart dashboard.

## Phases

- [ ] **Phase 135: Sidebar Reduction & Route Preservation** - Collapse 17 sidebar items to 4 pillars + Settings; preserve all deep links
- [ ] **Phase 136: Command Palette** - Cmd+K global search, navigation, and action execution across all entities
- [ ] **Phase 137: Unified Task Model (Backend)** - Backend API consolidating follow-ups, reminders, deal/ticket actions, and manual to-dos
- [ ] **Phase 138: Tasks Page & Views** - Frontend Tasks pillar with list/kanban views, filtering, and quick-add
- [ ] **Phase 139: Smart Views & Task Customization** - Saved filter combinations and pinned sidebar views
- [ ] **Phase 140: Email Contextual Sidebar** - Right sidebar showing contact profile, company, deals, and tickets when viewing an email
- [ ] **Phase 141: Contact 360 & Hover Cards** - Activity timeline on contact detail, related entities, and mini-CRM hover cards
- [ ] **Phase 142: AI Background Automation** - Auto-link emails to contacts/deals, auto-categorize by type
- [ ] **Phase 143: AI Suggestions & Actions** - Contextual action suggestions in email sidebar with accept/dismiss
- [ ] **Phase 144: AI Assistant Overlay** - Slide-over AI panel from any screen via keyboard shortcut, context-aware
- [ ] **Phase 145: Smart Today Dashboard** - AI-curated daily view: due tasks, pending replies, deal alerts, upcoming meetings

## Phase Details

### Phase 135: Sidebar Reduction & Route Preservation
**Goal**: Users navigate via 4 clean pillars instead of a cluttered 17-item sidebar, without losing access to any page
**Depends on**: Nothing (first phase of v12.0)
**Requirements**: NAV-01, NAV-06
**Success Criteria** (what must be TRUE):
  1. User sees exactly 4 pillar icons in sidebar: Mail, Calendar, Contacts, Tasks (plus Settings)
  2. User can reach any former CRM/AI page by typing its URL directly in the browser
  3. All existing bookmarks and shared links continue to work (no 404s from route removal)
**Plans**: TBD
**UI hint**: yes

### Phase 136: Command Palette
**Goal**: Users can search, navigate, and execute actions across the entire app without touching the sidebar
**Depends on**: Phase 135
**Requirements**: NAV-02, NAV-03, NAV-04
**Success Criteria** (what must be TRUE):
  1. User presses Cmd+K (or Ctrl+K) and sees a search overlay from any screen
  2. User can type a CRM route name (e.g., "pipelines") and navigate there even though it has no sidebar entry
  3. User can search across emails, contacts, deals, tasks, and KB articles from the palette and see unified results
  4. User can execute actions from the palette: create deal, create task, compose email, navigate to any route
**Plans**: TBD
**UI hint**: yes

### Phase 137: Unified Task Model (Backend)
**Goal**: A single backend API serves all task types (follow-ups, reminders, deal actions, ticket actions, manual to-dos) through one endpoint
**Depends on**: Phase 135
**Requirements**: TASK-01
**Success Criteria** (what must be TRUE):
  1. API returns a unified task list that includes follow-ups, reminders, CRM deal actions, ticket actions, and manual to-dos
  2. Each task carries its source type so the frontend can distinguish origin
  3. Existing follow-up and reminder data appears in the unified task response without migration loss
**Plans**: TBD

### Phase 138: Tasks Page & Views
**Goal**: Users manage all their work items from a single Tasks page with flexible viewing options
**Depends on**: Phase 137
**Requirements**: TASK-02, TASK-03, TASK-06, TASK-07
**Success Criteria** (what must be TRUE):
  1. User sees a Tasks page listing all unified tasks (follow-ups, reminders, deal actions, ticket actions, manual to-dos)
  2. User can create a manual task from Cmd+K or a quick-add button from anywhere
  3. User can filter tasks by type, contact, due date, and status
  4. User can toggle between list view and kanban board view
  5. User can drag tasks between kanban columns to change status
**Plans**: TBD
**UI hint**: yes

### Phase 139: Smart Views & Task Customization
**Goal**: Users save and pin frequently used filter combinations for instant access to their most relevant task slices
**Depends on**: Phase 138
**Requirements**: TASK-04, TASK-05
**Success Criteria** (what must be TRUE):
  1. User can save a filter combination as a named smart view (e.g., "My Follow-ups", "Open Tickets")
  2. User can pin smart views to the Tasks sidebar for one-click access
  3. Pinned smart views persist across sessions
**Plans**: TBD
**UI hint**: yes

### Phase 140: Email Contextual Sidebar
**Goal**: Users see relevant CRM context (contact, company, deals, tickets) alongside any email without navigating away
**Depends on**: Phase 135
**Requirements**: CTX-01, CTX-02, CTX-06
**Success Criteria** (what must be TRUE):
  1. User sees sender's contact profile (name, company, role, photo) in right sidebar when viewing an email
  2. User sees sender's open deals, recent tickets, and company info in the same sidebar
  3. User can collapse the contextual sidebar to reclaim reading space, and it stays collapsed until re-expanded

**UI hint**: yes

  2. User sees related emails, deal history, and upcoming tasks when viewing a contact
  3. User sees a mini-CRM hover card (name, company, deal status, last interaction) when hovering any contact name anywhere in the app

### Phase 142: AI Background Automation
**Goal**: The system automatically links and categorizes incoming emails without user intervention
**Depends on**: Phase 140
**Requirements**: AI-01, AI-02, AI-03
**Success Criteria** (what must be TRUE):
  1. Incoming emails are automatically linked to matching contacts in the background
  2. Incoming emails are automatically linked to relevant deals/tickets based on contact and context
  3. Emails are auto-categorized by type (support, sales, internal, newsletter) and the category is visible in the UI
**Plans**: TBD

### Phase 143: AI Suggestions & Actions
**Goal**: Users receive intelligent action suggestions when reading emails and can act on them with one click
**Depends on**: Phase 140, Phase 142
**Requirements**: AI-04, AI-05
**Success Criteria** (what must be TRUE):
  1. User sees suggested actions after reading an email (e.g., create task, update deal, link to ticket) in the contextual sidebar
  2. User can accept a suggestion with one click and the action executes
  3. User can dismiss a suggestion and it does not reappear for that email

  2. The AI Assistant knows the current context (which email, contact, or deal the user is viewing)
