  <action>
1. **Create `backend/scripts/re-encrypt-cbc-to-gcm.ts`:**
   - CLI script with `--dry-run` flag (via `process.argv.includes('--dry-run')`).
   - Initialize PrismaClient and CryptoService manually (not via NestJS DI).
   - Process 2 tables: `ProviderConfig` and `MfaSecret`.

   **ProviderConfig re-encryption:**
   - Encrypted field pairs: `(accessToken, tokenEncryptionIv)`, `(refreshToken, refreshTokenEncryptionIv)`, `(imapPassword, imapPasswordIv)`, `(smtpPassword, smtpPasswordIv)`, `(caldavPassword, caldavPasswordIv)`, `(carddavPassword, carddavPasswordIv)`.
   - Query in batches of 100: find records where ANY encrypted field does NOT start with `gcm:` and is not null.
   - For each record, for each non-null encrypted field that doesn't start with `gcm:`:
     - `const plaintext = crypto.decrypt(encryptedValue, ivValue)`
     - `const { encrypted, iv } = crypto.encrypt(plaintext)`
     - Collect update data.
   - Wrap each batch in `prisma.$transaction()`.
   - Log progress: batch number, records processed, CBC fields found.

   **MfaSecret re-encryption:**
   - Same pattern: find records where `secret` does not start with `gcm:`.
   - Decrypt with `crypto.decrypt(secret, encryptionIv)`, re-encrypt with `crypto.encrypt(plaintext)`.
   - Batch of 100, transactional.

   **Output summary:**
   ```
   Re-encryption complete:
     ProviderConfig: X records, Y fields re-encrypted
     MfaSecret: X records re-encrypted
     Mode: DRY RUN / LIVE
   ```

   **Idempotency:** The `where` clause filtering out `gcm:` prefix ensures re-running is safe.

   **Error handling:** Catch per-record errors, log the record ID, continue with next record. Exit with non-zero code if any errors occurred.

2. **Remove CBC fallback from `crypto.service.ts`:**
   - Delete the `private decryptCbc(encrypted: string, ivHex: string): string` method entirely.
   - In `decrypt()`, remove the CBC fallback branch. If data doesn't start with `gcm:`, throw an error: `throw new Error('Legacy CBC-encrypted data detected. Run re-encryption script first.')`.
   - Keep the `GCM_PREFIX` constant and `decryptGcm` method.
   - This ensures no future code can silently use insecure CBC decryption.

IMPORTANT: The CBC removal should happen AFTER the script is created and tested. In practice, the executor should run the script first (or verify via --dry-run that no CBC records exist in dev), then remove the CBC code.

1. **Install Knip:**

   ```bash
   cd frontend && npm install -D knip
   ```

2. **Create `frontend/knip.json`:**
   ```json
   {
     "$schema": "https://unpkg.com/knip@5/schema.json",
     "entry": ["pages/**/*.{ts,tsx}", "lib/**/*.ts"],
     "project": ["**/*.{ts,tsx}"],
     "ignoreDependencies": [
       "@next/bundle-analyzer"
     ]
   }
   ```
   Run `cd frontend && npx knip` to identify unused dependencies. Examine the output -- for each flagged package, verify it's truly unused before removal. Remove confirmed unused production dependencies with `npm uninstall`. Add any false positives to `ignoreDependencies`.

   NOTE: Do NOT blindly remove packages. Check each one:
   - Is it imported anywhere? (grep the codebase)
   - Is it used in config files only? (next.config.js, jest.config.js, etc.)
   - Is it a peer dependency of another package?
   - Is it used at runtime but not imported (e.g., PostCSS plugins)?

3. **Add CI bundle budget to `.github/workflows/ci.yml`:**
   After the existing "Jest unit tests" step in the `frontend` job, add two steps:

   ```yaml
   - name: Build Next.js
     run: npm run build
     env:
       NEXT_PUBLIC_API_URL: http://localhost:3000

   - name: Bundle size budget check
     run: |
       SIZE=$(du -sb .next/static/chunks/ | cut -f1)
       SIZE_MB=$(echo "scale=2; $SIZE / 1048576" | bc)
       echo "Bundle size: ${SIZE_MB}MB"
       WARN_LIMIT=9437184
       FAIL_LIMIT=10485760
       if [ "$SIZE" -gt "$FAIL_LIMIT" ]; then
         echo "::error::Bundle size ${SIZE_MB}MB exceeds 10MB budget"
         exit 1
       elif [ "$SIZE" -gt "$WARN_LIMIT" ]; then
         echo "::warning::Bundle size ${SIZE_MB}MB approaching 10MB budget"
       fi
   ```

   Place after the Jest step. The `next build` step is required because the bundle budget reads from `.next/static/chunks/`. Set `NEXT_PUBLIC_API_URL` env var to prevent build failures from missing env.

4. **Verify by running `next build` locally** (if feasible) to confirm current bundle is under 10MB.
