  <implementation>
Create `password-policy.service.ts` as @Injectable() NestJS service:
- Pure validation, no side effects except HTTP call to HIBP
- `validate(password: string): Promise<{ valid: boolean; errors: string[] }>` - check length 15-128, then HIBP if length passes
- `checkBreached(password: string): Promise<{ breached: boolean; count: number }>` - SHA-1 hash, take 5-char prefix, fetch `https://api.pwnedpasswords.com/range/{prefix}` with 3s timeout and `Add-Padding: true` header, parse response to find suffix match, breached if count > 3
- Best-effort: any fetch error returns { breached: false, count: 0 }
- No external dependencies needed (uses built-in crypto.createHash and fetch)

Update ALL THREE DTOs per CONTEXT.md locked decision (15-char minimum per NIST SP 800-63B-4, 128-char maximum to prevent CPU DoS via Argon2id):

- `register.dto.ts`: Change @MinLength(8) to @MinLength(15, { message: 'Password must be at least 15 characters' }), add @MaxLength(128, { message: 'Password must be at most 128 characters' })
- `reset-password.dto.ts`: Change @MinLength(8) to @MinLength(15, { message: 'Password must be at least 15 characters' }), add @MaxLength(128, { message: 'Password must be at most 128 characters' })
- `login.dto.ts`: Change @MinLength(8) to @MinLength(15, { message: 'Password must be at least 15 characters' }), add @MaxLength(128, { message: 'Password must be at most 128 characters' }). CRITICAL: login.dto.ts @MaxLength(128) is essential -- without it an attacker can submit a 1MB password and Argon2id will hash it, causing CPU DoS.

Import `MaxLength` from `class-validator` in all three DTO files.

P48-11 test coverage: write tests for ALL THREE DTOs covering both MinLength(15) and MaxLength(128) validation. Include login.dto.ts explicitly -- it is the primary CPU DoS attack vector.
