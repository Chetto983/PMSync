<objective>
Migrate JWT signing from symmetric HS256 to asymmetric ES256 (ECDSA P-256) with a dual-algorithm grace period for zero-downtime deployment. Include kid header for future key rotation.

Purpose: Asymmetric signing means verifiers (any service) only need the public key, not the signing secret. This is the IETF-recommended approach for 2026.
Output: ES256-configured auth module, dual-algo JwtStrategy, key generation script.
</objective>

**2. Update auth.module.ts JwtModule config**:

Replace the existing `useFactory`:
```typescript
useFactory: (config: ConfigService): JwtModuleOptions => {
  const privateKeyRaw = config.get<string>('JWT_PRIVATE_KEY');
  const publicKeyRaw = config.get<string>('JWT_PUBLIC_KEY');

  // Handle PEM newline escaping from env vars
  const privateKey = privateKeyRaw?.replace(/\\n/g, '\n');
  const publicKey = publicKeyRaw?.replace(/\\n/g, '\n');

  const expiresIn = config.get<string>('ACCESS_TOKEN_EXPIRES_IN') || '15m';

  if (privateKey && publicKey) {
    // ES256 mode
    return {
      privateKey,
      publicKey,
      signOptions: {
        algorithm: 'ES256',
        expiresIn,
        issuer: 'pmsync-auth',
        audience: 'pmsync-api',
        keyid: crypto.createHash('sha256').update(publicKey).digest('hex').substring(0, 8),
      },
    };
  }

  // HS256 fallback (dev/test without ES256 keys)
  const secret = config.get<string>('JWT_SECRET');
  if (!secret || secret === 'secret' || secret.length < 32) {
    throw new Error('FATAL: JWT_SECRET or JWT_PRIVATE_KEY/JWT_PUBLIC_KEY must be configured.');
  }
  return {
    secret,
    signOptions: { expiresIn, issuer: 'pmsync-auth', audience: 'pmsync-api' },
  };
}
```
