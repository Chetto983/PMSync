2. Create `frontend/hooks/use-push-subscription.ts` following the `use-install-prompt.ts` useSyncExternalStore pattern exactly:
- Module-level state: `currentSubscription: PushSubscription | null = null`, `permissionState: NotificationPermission = 'default'`, `listeners: Set<() => void>`, `notify()`, `subscribe()` (for useSyncExternalStore)
- `isPushSupported()` function: returns false if `typeof window === 'undefined'`, false if `!('serviceWorker' in navigator)`, false if `!('PushManager' in window)`, false if `!('Notification' in window)`. On iOS (detect via UA containing iPad/iPhone/iPod or MacIntel+maxTouchPoints>1), also require standalone mode via `navigator.standalone || matchMedia('(display-mode: standalone)').matches`. Otherwise true.
- `getSnapshot()` returns cached `{ isSupported: boolean; isSubscribed: boolean; permission: NotificationPermission }`. Update cached ref only when values change (same pattern as use-install-prompt.ts cachedSnapshot).
- `getServerSnapshot()` returns `{ isSupported: false, isSubscribed: false, permission: 'default' as const }`.
- `initPushState()`: called at module scope if `typeof window !== 'undefined'`. Gets SW registration via `navigator.serviceWorker.ready`, then `reg.pushManager.getSubscription()` to set `currentSubscription`, reads `Notification.permission` to set `permissionState`. Wrap in try/catch.
- `usePushSubscription()` hook: uses `useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)`. Returns `{ ...state, subscribeToPush, unsubscribeFromPush }`.
- `subscribeToPush`: `Notification.requestPermission()` -> if granted, `reg.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: process.env.NEXT_PUBLIC_VAPID_KEY })` -> extract endpoint + keys (p256dh, auth from `sub.toJSON().keys`) -> `pushApi.subscribe(dto)` -> update module state -> `notify()`.
- `unsubscribeFromPush`: `currentSubscription.unsubscribe()` -> `pushApi.unsubscribe(endpoint)` -> set `currentSubscription = null` -> `notify()`.
- Export `_resetForTesting()` that clears all module-level state.

4. Add SW push and notificationclick handlers to `frontend/sw.ts` -- insert BEFORE `serwist.addEventListeners()`:

```typescript
// Push notification handler (PUSH-02)
self.addEventListener('push', (event: PushEvent) => {
  if (!event.data) return;
  const data = event.data.json() as {
    title: string;
    body: string;
    icon?: string;
    url?: string;
    tag?: string;
  };
  event.waitUntil(
    self.registration.showNotification(data.title, {
      body: data.body,
      icon: data.icon || '/icons/icon-192x192.png',
      badge: '/icons/icon-192x192.png',
      tag: data.tag,
      data: { url: data.url || '/' },
    })
  );
});

// Notification click handler -- deep-link to relevant view (PUSH-03)
self.addEventListener('notificationclick', (event: NotificationEvent) => {
  event.notification.close();
  const url = (event.notification.data as { url?: string })?.url || '/';
  event.waitUntil(
    (self as unknown as ServiceWorkerGlobalScope).clients
      .matchAll({ type: 'window' })
      .then((clientList) => {
        for (const client of clientList) {
          if ('focus' in client) {
            (client as WindowClient).focus();
            (client as WindowClient).navigate(url);
            return;
          }
        }
        return (self as unknown as ServiceWorkerGlobalScope).clients.openWindow(url);
      })
  );
});
```

Note: The `self` type declarations at the top of sw.ts will need to be extended to include `clients.openWindow` and WindowClient types. Add the needed type assertions inline.
