## Phase-Specific UI Notes

### What this phase does NOT change visually

1. **Email list component** -- unchanged. TQ persister restores data transparently; the list renders from `useQuery` data as before.
2. **Email detail view** -- unchanged. Same rendering path, data comes from cache on cold offline start.
3. **Offline banner** -- unchanged. Already shows via `useOnlineStatus` hook from Phase 101.
4. **Sign-out button** -- visually unchanged. The `handleLogout` function gains a `clearOfflineData()` call before `authClient.signOut()`, but the button itself and its behavior (menu close, redirect to login) remain identical.

### Interaction contract

| Interaction | Behavior |
|-------------|----------|
| App opened offline after previous online session | Email list and detail views render from IndexedDB-persisted TQ cache. No loading spinner (data is synchronously available from persister). Offline banner visible. |
| App opened offline with no prior cache | Email list shows existing loading/empty state. Offline banner visible. No special "no cached data" state needed -- the existing empty state suffices. |
| User signs out | All IndexedDB data cleared, all SW caches cleared, TQ in-memory cache cleared. Then auth session destroyed. Then redirect to `/auth/login`. Sequence is invisible to user -- same UX as current sign-out. |
| Persister fails (IndexedDB unavailable) | Graceful degradation. App works normally without persistence. No error shown to user. Console warning only. |
| Cache older than 24 hours | Persister `maxAge` expires the entry. On next online visit, fresh data fetched normally. No user-facing notification. |
