## Interaction Contract

### State 1: Online (default)

No visible queue UI. Email actions (mark-read, archive, star) work normally via API.

### State 2: Offline with queued actions

Primary visual anchor: the existing `OfflineBanner` Alert component. When actions are pending, the OfflineBanner is the dominant indicator of offline state. The pending count badge (MUI `Badge` on the `WifiOff` icon, `color="warning"`, `badgeContent={count}`) is a secondary indicator subordinate to the banner, providing at-a-glance queue depth without competing for attention.

- Email actions are optimistic -- UI updates immediately on user tap (existing `onMutate` in `useUpdateEmail`)
- No additional UI feedback beyond existing `OfflineBanner` (already shows "You are offline. Some features may be unavailable.")
- Actions silently queue to IndexedDB in background
- Optional: show pending count as a Badge on the OfflineBanner or next to the wifi-off icon. Use MUI `Badge` with `badgeContent={count}`, `color="warning"`, positioned on the `WifiOff` icon. Only show when count > 0.

### State 3: Reconnection replay

- Toast (MUI Snackbar + Alert): `severity="info"`, auto-hide after 3000ms, shows `offlineQueue.replayStarted`
- On success: toast `severity="success"`, auto-hide after 4000ms, shows `offlineQueue.replaySuccess`
- On partial failure: toast `severity="warning"`, auto-hide after 6000ms, shows `offlineQueue.replayPartialFailure`
- After replay (success or partial), invalidate email list and stats queries to refresh from server

### State 4: TTL expiry (SYNC-03)

- Toast (MUI Snackbar + Alert): `severity="warning"`, auto-hide after 6000ms, shows `offlineQueue.expiredActions`
- Expired actions are removed from IndexedDB, related queries invalidated
- No confirmation dialog -- expiry is automatic per the 30-minute TTL requirement

### State 5: Queue overflow (defensive)

- Toast `severity="warning"`, auto-hide after 5000ms, shows `offlineQueue.queueFull`
- Max 100 queued actions; oldest discarded on overflow

### Toast positioning

All toasts use the existing `getGlobalToast()` system. No new Snackbar mounting. Default position: bottom-left (matches existing sync status Snackbar positioning in Layout.tsx).

Source: RESEARCH.md patterns 1-3, existing `OfflineBanner.tsx`, existing `toast-context.tsx`
