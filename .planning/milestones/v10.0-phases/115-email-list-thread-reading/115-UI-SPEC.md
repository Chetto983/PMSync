# Phase 115 — UI Design Contract

> Visual and interaction contract for the email list and thread reading validation phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase context:** This is a backend-only validation phase. No frontend components are being built, modified, or tested. The phase writes Node.js validation scripts (`scripts/validate-email-read.mjs`) that exercise backend REST API endpoints via Playwright CDP + fetch. REQUIREMENTS.md explicitly states "Frontend UI testing: OUT OF SCOPE." This contract documents the existing visual system solely as reference context for the executor, in case a bug fix during validation touches frontend code.

| Property | Value |

## Interaction Contracts (Reference Only)

Phase 115 validates backend API behavior, not frontend interactions. These contracts document what the validated APIs power, for context only.

### API-to-UI Mapping

| Requirement | API Endpoint | Frontend Component It Powers |
|-------------|-------------|------------------------------|
| READ-01 | `GET /emails?folder=X` | Email list filtered by sidebar folder click |
| READ-02 | `GET /emails?isRead=false&hasAttachments=true&...` | Email list with compound filter toolbar |
| READ-03 | `GET /emails?page=N&limit=M` | Email list infinite scroll / pagination |
| READ-04 | `GET /emails/thread/:threadId` | Thread reading pane with grouped messages |
| READ-05 | `GET /emails/:id` | Single email detail view with full body |

No frontend interaction behavior is being modified or tested in this phase.
