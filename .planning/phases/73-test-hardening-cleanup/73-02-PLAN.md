**Onboarding seed automation:**

In `frontend/e2e/onboarding.spec.ts`, add a reset step at the very beginning of the `test.describe` block, BEFORE the existing `test.beforeAll`. Add a new `test.beforeAll` (first one, runs before the login beforeAll) that uses a direct HTTP API call to the backend to reset the test user's onboarding state. Since we cannot import Prisma from the frontend test, use the approach of calling a backend endpoint or executing a shell command.

The simplest reliable approach: use `execSync` from `child_process` to run a targeted Prisma command. Add at the top of the file:

```typescript
import { execSync } from 'child_process';
```

Then add BEFORE the existing `test.describe`:

```typescript
// Reset onboarding state before the entire suite
test.beforeAll(async () => {
  try {
    execSync(
      `npx prisma db execute --stdin <<< "UPDATE \\"user\\" SET \\"onboardingComplete\\" = false, \\"twoFactorEnabled\\" = false WHERE email = 'test@pmsync.local'; DELETE FROM \\"twoFactor\\" WHERE \\"userId\\" IN (SELECT id FROM \\"user\\" WHERE email = 'test@pmsync.local');"`,
      { cwd: '../backend', stdio: 'pipe', env: { ...process.env, DATABASE_URL: process.env.DATABASE_URL || 'postgresql://postgres:postgres@localhost:5433/pmsync_test' } }
    );
  } catch {
    console.warn('[onboarding] Could not reset onboarding state — test may skip if user already completed onboarding');
  }
});
```

WAIT -- `prisma db execute --stdin` with heredoc may not work on Windows. Instead, use a simpler approach: write a tiny SQL file or use `npx prisma db execute --url ... --file`. Actually, the cleanest cross-platform approach is to use the backend's existing `prisma db seed` which already resets `test@pmsync.local` via `upsert`:

```typescript
import { execSync } from 'child_process';

// Before the test.describe block, add:
test.beforeAll(async () => {
  try {
    console.log('[onboarding] Resetting test user state via prisma db seed...');
    execSync('npx prisma db seed', {
      cwd: require('path').resolve(__dirname, '../../backend'),
      stdio: 'pipe',
      timeout: 30_000,
    });
    console.log('[onboarding] Seed complete — test@pmsync.local reset.');
  } catch (e) {
    console.warn('[onboarding] prisma db seed failed — test may skip if onboarding already completed.', (e as Error).message);
  }
});
```

Place this `test.beforeAll` OUTSIDE the `test.describe('Onboarding wizard', ...)` block but still in the file scope. Actually, Playwright requires `test.beforeAll` inside a `test.describe` or at file scope. Place it at file scope before the describe block.

Also remove the `test.skip` guard inside the existing `test.beforeAll` (lines 51-58) since the seed now resets the state. Keep the guard as a safety net but update its message: the user no longer needs to manually re-seed.
