2. The backend HITL flow works via poll-based approach (NOT assistant-ui native `requires-action`):
   - Backend creates a `PendingAction` record when a destructive tool is invoked
   - Frontend polls for pending actions using the existing `useAiActions` hook
   - Display inline approval card in the message stream

3. Component props: `{ conversationId?: string }` -- filter pending actions by current conversation

4. Implementation:
   - Use `useAiActions()` hook from `@/hooks/ai/use-ai-actions`
   - Filter `pendingActions` by conversationId (if available) and status === 'PENDING'
   - For each pending action, render an inline card:
     - Warning icon (AlertTriangle from lucide-react) + action type label
     - Summary text describing the action
     - Tool name and severity badge
     - Two buttons: Approve (green) and Reject (red)
     - Loading state while approve/reject is processing (use `isApproving`/`isRejecting`)
   - On approve: call `approveAction(action.executionId)`
   - On reject: call `rejectAction(action.executionId)`
   - Use i18n strings for button labels: `t.chat.hitl.approveLabel`, `t.chat.hitl.rejectLabel`, `t.chat.hitl.pendingTitle`

5. Styling:
   - Card: `border-2 border-amber-500/40 rounded-lg p-4 bg-amber-50/5`
   - Approve button: `bg-green-600 hover:bg-green-700 text-white rounded-md px-3 py-1.5 text-sm`
   - Reject button: `bg-red-600 hover:bg-red-700 text-white rounded-md px-3 py-1.5 text-sm`
   - Severity badges: high=red, medium=amber, low=gray
