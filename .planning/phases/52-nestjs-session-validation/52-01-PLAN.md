Note on AuthController: It has mixed auth/unauth routes. The class itself has no class-level @UseGuards, but individual routes @Get('me') and @Post('logout') have @UseGuards(JwtAuthGuard). With global BetterAuthGuard, the class needs @Public() at class level, and those two routes need the guard explicitly re-enabled (remove @Public override or use a different pattern). Alternatively, mark individual unguarded routes as @Public(). The simpler approach: mark the entire AuthController as @Public() since most routes are unguarded, then the two guarded routes already have explicit @UseGuards which won't be needed once BetterAuthGuard is global (they will inherit the global guard). Actually -- with BetterAuthGuard as APP_GUARD, ALL routes get it by default. So AuthController routes that don't need auth need @Public(). The @Get('me') and @Post('logout') routes already work because the global guard covers them. Remove their explicit @UseGuards(JwtAuthGuard).
