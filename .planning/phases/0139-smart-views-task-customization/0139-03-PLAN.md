Then add a new `useEffect` AFTER the existing `// ?action=create triggers dialog` effect block (after line ~119) and BEFORE the `// Sync state -> URL` effect (line ~122). This effect hydrates filter state from a view ID on mount:

```typescript
// Hydrate filters from ?view=<id> on mount (cross-session persistence)
useEffect(() => {
  if (!router.isReady) return;
  const viewId = typeof q.view === 'string' ? q.view : null;
  if (!viewId || !smartViewsData) return;
  const view = smartViewsData.find((v: TaskSmartView) => v.id === viewId);
  if (!view) return;
  const f = view.filters as Partial<ListTasksQuery>;
  setFilterSourceType(f.sourceType?.[0] ?? '');
  setFilterStatus(f.status?.[0] ?? '');
  setFilterPriority(f.priority?.[0] ?? '');
  setFilterDueBefore(f.dueBefore ?? '');
  setFilterDueAfter(f.dueAfter ?? '');
  setFilterContactId(f.contactId ?? '');
  setActiveViewId(view.id);
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [router.isReady, smartViewsData]);
```

The eslint-disable is intentional: we only want this to fire when `router.isReady` transitions to true and when `smartViewsData` first loads (not on every filter change). The `q.view` value is read inside the effect body, not as a dependency — this is correct because we only want initial hydration, not re-hydration on every URL change.
