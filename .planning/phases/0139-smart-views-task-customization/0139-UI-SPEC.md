## Typography

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|---------------------|
| Body | 14px (0.875rem) | 400 (normal) | 1.5 | Popover view names, dialog body text, filter summary caption |
| Label | 12px (0.75rem) | 400 (normal) | 1.5 | Chip labels, "Filters:" caption in save dialog, popover section header |
| Heading | 16px (1rem) | 600 (semibold) | 1.25 | Dialog titles ("Save Current View", "Delete View") |
| Display | not used | - | - | No display text in this phase |

Two weights only: 400 (normal) for Body and Label, 600 (semibold) for Heading. Label is visually differentiated from Body by its smaller 12px size, not by weight.

Source: `design-tokens.ts` typography section. Use MUI `variant` props: `body2` for Body, `caption` for Label, `h6` or `DialogTitle` for Heading.

## Color

| Role | Value (HSL) | Usage in this phase |
|------|-------------|---------------------|
| Dominant (60%) | MUI `background.default` / `background.paper` | Page background, dialog background, popover background |
| Secondary (30%) | MUI `action.hover`, `divider` | Chip outlined borders, popover item hover state, filter summary row |
| Accent (10%) | `hsl(142, 71%, 45%)` — tasks semantic green | Active view chip fill, pin icon when pinned, "Save View" button |
| Destructive | `hsl(0, 84%, 60%)` — status error red | Delete view button (contained, color="error") |

Accent reserved for:
- Active saved view chip (`variant="filled"` + `color="success"` maps to tasks green)
- Pin toggle icon fill when `isPinned === true`
- "Save View" primary CTA button in save dialog

Source: `design-tokens.ts` semantic.tasks = `142 71% 45%` (green). MUI theme maps this. Use MUI `color="success"` for task accent where MUI theme is configured, otherwise use `sx={{ bgcolor: 'success.main' }}`.

## Interaction Contracts

### Save a View
1. User applies filters on Tasks page (source type, status, priority, due date)
2. User clicks Plus (+) button in SavedViewsBar
3. SavedViewDialog opens with current filters shown as caption
4. User types a name, optionally toggles "Pin to sidebar"
5. User clicks "Save View" or presses Enter
6. Chip appears in SavedViewsBar immediately (optimistic via TanStack Query `onMutate`)
7. If pinned, view also appears in PinnedViewsPopover on next open

### Apply a View
1. User clicks a view chip in SavedViewsBar OR clicks a view in PinnedViewsPopover
2. Filter state updates to match saved view filters (partial application, missing keys use defaults)
3. URL updates to include `?view={viewId}` plus filter params
4. Chip becomes active (filled green)
5. Toast: i18n `tasks.smartViews.applied`

### Clear Active View
1. User manually changes any filter while a view is active
2. Active view ID clears, chip reverts to outlined variant
3. `?view=` param removed from URL, filter params remain

### Pin/Unpin a View
1. User right-clicks a chip OR opens a chip menu to toggle pin
2. Alternative: Pin toggle available in SavedViewDialog when editing
3. Backend PATCH `/tasks/views/:id/pin` toggles `isPinned`
4. PinnedViewsPopover updates on next open (query invalidation)

### Delete a View
1. User clicks X on a chip in SavedViewsBar
2. Confirmation dialog opens: "Are you sure you want to delete this saved view?"
3. User confirms -> view removed, chip disappears
4. If deleted view was pinned, also removed from PinnedViewsPopover

### Project-Level Exceptions

| Element | Declared As | Justification |
|---------|-------------|---------------|
| Cancel button (all dialogs) | `common.cancel` = "Cancel" / "Annulla" | Project-wide design system convention. Every dialog in PMSync (30+ dialogs across CRM, email, contacts, calendar modules) uses `common.cancel` for the secondary dismiss action. Changing to context-specific labels (e.g., "Discard View", "Keep View") would break the established pattern and confuse users who expect consistent dialog anatomy. This is a locked project standard, not a per-phase decision. |
