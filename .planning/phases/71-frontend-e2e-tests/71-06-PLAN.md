    Use E2E_NO_WEB_SERVER=1 because the user has already started backend and frontend servers in Task 1.

    If any tests fail, follow this diagnostic loop (max 3 iterations per spec file, per CLAUDE.md 3-STRIKE RULE):

    1. Read the Playwright HTML report or terminal output to identify the failure reason
    2. Classify the failure:
       - Selector mismatch: Element not found, role/text changed. Fix: Update the selector in the spec file to match actual rendered DOM.
       - Timing issue: Timeout waiting for element/navigation. Fix: Add appropriate waitFor calls, increase specific timeouts, or use expect(locator).toBeVisible({ timeout: X }).
       - API contract mismatch: Response shape differs from expected. Fix: Update assertions to match actual API response.
       - Auth/session issue: Login fails, redirect loop. Fix: Check seed data, verify auth.setup files produce valid storageState.
       - State contamination: Previous test left DB in unexpected state. Fix: Add cleanup in afterAll/afterEach, or reorder tests.
    3. Apply the fix to the spec file
    4. Re-run only the failing spec: cd frontend && E2E_NO_WEB_SERVER=1 npx playwright test --project=chromium e2e/{failing-spec}.spec.ts
    5. Repeat until green or 3 strikes reached

    Also fix the known anti-pattern: admin.spec.ts line 44 has page.waitForTimeout(500) -- replace with a proper waitFor condition (e.g., wait for the filtered results to appear or a network request to complete).

    IMPORTANT: Do NOT modify test assertions to make them pass if the underlying feature is broken. If a feature is genuinely broken (not a test issue), document it and skip the test with test.skip() and a clear reason.

    After all specs pass (or have documented skips), run the full suite one final time to confirm:
