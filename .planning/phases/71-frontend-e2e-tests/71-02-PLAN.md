**Test 1 — Create organization:**
- Navigate to `/dashboard/settings` (admin is already authenticated via storageState)
- Click on the "Organizations" tab/section
- Click "Create Organization" (or equivalent button)
- Fill in organization name `ORG_NAME`
- Submit the form
- Wait for the new org to appear in the list
- Extract the org ID from the URL or API response for use in subsequent tests

**Test 2 — Invite member:**
- Navigate to the org admin page (or open the InviteMemberDialog)
- Click "Invite Member" button
- Fill in `MEMBER_EMAIL`
- Select role (if prompted) — use default/member role
- Click "Send Invitation" / "Invite"
- Assert a success toast or confirmation appears
- The invitation is now pending in the backend

**Test 3 — Accept invitation as member:**
- Open a new browser context with `{ storageState: 'playwright/.auth/member.json' }`
- As member: call `page.request.get('/api/auth/organization/list-user-invitations')` to retrieve the pending invitation ID (no real email needed)
  - This is the confirmed path (use-organizations.ts line 66: `getAuthJson('/organization/list-user-invitations')` with `/api/auth` prepended)
  - Alternatively navigate to `/dashboard` and look for the `PendingInvitationBanner` to get the invite details
- Parse `invitations[0].id` from the JSON response
- Navigate to `/dashboard/invitations/accept?id=${invitationId}`
- Wait for redirect to `/dashboard` (invitation accepted)
- Assert the new org appears in the member's org switcher
- Close the second context

**Test 4 — Switch organization:**
- Back in the admin context, navigate to `/dashboard`
- Open the OrgSwitcher (click on the current org name or a switcher button)
- Click on `ORG_NAME` to switch
- Wait for page to settle
- Assert the active org in the header/sidebar shows `ORG_NAME`

**Cleanup (afterAll):**
Wrap in try/finally. As admin: navigate to the org's admin page, find the "Delete Organization" option, click it, confirm. This keeps the DB clean for reruns.

**Important implementation notes:**
- The spec file must NOT import from auth.setup.ts or fixtures.ts for auth — the storageState in playwright.config.ts handles admin auth; member context is opened inline with `browser.newContext`.
- Use `test.use({ storageState: 'playwright/.auth/user.json' })` at describe level if the default project storageState is not sufficient.
- The `list-user-invitations` endpoint is authenticated — the member page.request context carries the member's cookies from storageState.
- Do not use `fullyParallel` implicitly for these tests if they share mutable state (orgId, invitationId) — the `test.describe` block uses serial execution by default when state is shared across tests.
