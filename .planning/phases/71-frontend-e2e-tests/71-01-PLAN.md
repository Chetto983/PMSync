Make targeted changes to `backend/prisma/seed.ts`:

**Change 1 — Fix admin role:**
In the `seedUser` call for `admin@pmsync.local`, change `role: 'admin'` to `role: 'super-admin'`. This is a blocker: the admin panel pages check `user.role !== 'super-admin'` and render "Access denied" for anything else.

**Change 2 — Add seedUser overload for onboardingComplete:**
The `seedUser` function signature currently does not accept `onboardingComplete`. Extend the params type to include `onboardingComplete?: boolean` (default `false`). In the `prisma.user.upsert` create+update blocks, include `onboardingComplete: params.onboardingComplete ?? false`.

**Change 3 — Add member user:**
After the admin user seedUser call, add:
```typescript
const memberUser = await seedUser({
  email: 'member@pmsync.local',
  password: 'MemberPassword123!',
  firstName: 'Member',
  lastName: 'User',
  role: 'user',
  tenantId: defaultTenant.id,
  onboardingComplete: true,
});
console.log(`Created member user: ${memberUser.email}`);
```

Also update the member's `prisma.member.upsert` — the `seedUser` function hardcodes `role: 'admin'` in the member upsert. Change this to `role: params.memberRole ?? 'member'` and add `memberRole?: string` to the params type. Pass `memberRole: 'member'` for the new member user so they do not get org-admin privileges. The existing admin user can continue with the default `'admin'` member role.

**Change 4 — Pin test@pmsync.local onboardingComplete to false:**
The `test@pmsync.local` account is used by the onboarding spec (Plan 04). Its `onboardingComplete` field defaults to `false` in the Prisma schema, but to prevent drift on re-seeds, explicitly set it in the update block. Find the existing `seedUser` call for `test@pmsync.local` (or its equivalent upsert) and pass `onboardingComplete: false`. This ensures repeated `npx prisma db seed` runs never accidentally set this user's `onboardingComplete` to true.

Update the console output section to document all accounts: `admin@pmsync.local / TestPassword123!`, `member@pmsync.local / MemberPassword123!`, and `test@pmsync.local / UserPassword123! (onboardingComplete: false — used by onboarding E2E spec)`.
