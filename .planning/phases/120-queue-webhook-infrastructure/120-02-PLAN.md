  <action>
Create `scripts/lib/validate-webhook-lifecycle.mjs` with a single exported function `validateWebhookLifecycle(context, cookieHeader, csrfToken)` that returns an array of check results.

Follow the exact pattern from `validate-folder-ops.mjs`: import `apiGet`, `assertTrue`, `setResultsCollector` from `./validation-helpers.mjs`.

**INFRA-05 checks (webhook health endpoint -- run first since INFRA-03/04 depend on its data):**

1. `apiGet(context, '/webhooks/health', cookieHeader)` -- assert response has:
   - `status` field equal to `'ok'`
   - `timestamp` field that is a non-empty string
   - `gmail` object present (not null/undefined)
   - `microsoft` object present (not null/undefined)
2. Assert `gmail` stats object has numeric fields: `activeSubscriptions`, `expiringSoon`, `errors`
3. Assert `microsoft` stats object has numeric fields: `activeSubscriptions`, `expiringSoon`, `errors`

**INFRA-03 checks (Gmail Pub/Sub subscription):**

1. Get providers list: `apiGet(context, '/api/v1/providers', cookieHeader)` -- find any provider with `providerType === 'google'`
2. If no Google provider exists: push a SKIP result `assertTrue(true, 'INFRA-03: Gmail Pub/Sub SKIPPED (no Google provider configured)', results)` and skip remaining Gmail checks
3. If Google provider exists:
   - From the webhook health response (already fetched above), check `gmail.activeSubscriptions >= 0` (valid number)
   - Assert `gmail.activeSubscriptions >= 1` OR push a WARN result (subscription may not be active if GOOGLE_PUBSUB_TOPIC is not configured)
   - Check that `gmail.expiringSoon` is a number (0 is OK -- means no subscriptions about to expire)

**INFRA-04 checks (Microsoft Graph subscription):**

1. From the providers list, find any provider with `providerType === 'microsoft'`
2. If no Microsoft provider exists: push a SKIP result and skip remaining Microsoft checks
3. If Microsoft provider exists:
   - From the webhook health response, check `microsoft.activeSubscriptions >= 0`
   - Assert `microsoft.activeSubscriptions >= 1` OR push a WARN result (subscription may not be active if no public webhook URL)
   - Check that `microsoft.expiringSoon` is a number

**Important design decisions:**
- Do NOT attempt to create/renew subscriptions via API from the script. That is dangerous in production.
- Only READ current state via health endpoints.
- Use WARN (not FAIL) for missing subscriptions since they depend on external config (Pub/Sub topic, public URL).
- For WARN results, use `assertTrue(false, 'INFRA-03: Gmail Pub/Sub has active subscription (WARN: may need GOOGLE_PUBSUB_TOPIC)', results)` but catch the error so it doesn't stop execution.

Actually, implement a helper `assertWarn(condition, label, results)` that pushes `{ label, status: condition ? 'PASS' : 'WARN' }` -- does not throw but logs a warning. This differentiates hard failures from expected environment gaps.

Return the results array.
