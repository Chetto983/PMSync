**INFRA-01 checks:**

1. `apiGet(context, '/health/queues/all', cookieHeader)` -- assert response has `queues` array
2. For each of the 7 email queue names (`email-sync-high`, `email-sync-normal`, `email-sync-low`, `email-send`, `provider-sync-back`, `bulk-operations`, `folder-operations`):
   - Assert queue appears in response (find by `q.name === queueName`)
   - Assert queue is not paused (`!queueStatus.paused`)
   - Assert queue has numeric `waiting`, `active`, `completed`, `failed` fields
3. `apiGet(context, '/health/metrics', cookieHeader)` -- response is text. Assert the string contains `bullmq_queue_depth` (Prometheus gauge line). Note: this endpoint returns `text/plain`, so parse as text not JSON. Use `context.request.get()` directly for this one since `apiGet` tries JSON first.

**INFRA-02 checks (pause/resume on email-sync-low):**

1. `apiGet(context, '/health/queues/email-sync-low', cookieHeader)` -- record initial state (waiting count)
2. Note: BullMQ pause/resume is not exposed via REST API in the current backend. The validation must check that the queue infrastructure supports the pause state correctly. Validate by:
   - Calling `/health/queues/email-sync-low` and asserting the response has a `paused` field (boolean)
   - Calling `/health/queues/all` and asserting the summary object has `totalPaused` or equivalent field
   - Asserting no queues are currently in error/auto-paused state via `/health/workers` endpoint (BaseWorker statuses)
3. Worker health check: `apiGet(context, '/health/workers', cookieHeader)` -- assert response has `status` field, `totalWorkers` > 0, `autoPausedCount` === 0

Wrap each assertion in try/catch so one failure does not stop the remaining checks. Use `assertTrue(condition, label, results)` pattern.

Return the results array.

  <action>
Create `scripts/validate-queue-webhook-infra.mjs` following the exact pattern from `validate-folder-ops.mjs`.

Structure:
```javascript
import { connectCDP, getAuthCookies, getCsrfToken, report } from './lib/validation-helpers.mjs';
import { validateQueueHealth } from './lib/validate-queue-health.mjs';
// webhook import will be added by Plan 02

const args = process.argv.slice(2);
const checkFlag = args.find(a => a.startsWith('--check='))?.split('=')[1] || 'all';

async function main() {
  console.log('=== Queue & Webhook Infrastructure Validation ===');
  console.log(`Check: ${checkFlag}\n`);

  const { browser, context } = await connectCDP();
  const cookieHeader = await getAuthCookies(context);
  const { csrfToken, cookieHeader: finalCookies } = await getCsrfToken(context, cookieHeader);

  let results = [];

  if (checkFlag === 'all' || checkFlag === 'queues' || checkFlag === 'pause-resume') {
    const queueResults = await validateQueueHealth(context, finalCookies, csrfToken);
    results.push(...queueResults);
  }

  // Webhook checks will be wired by Plan 02

  const exitCode = report('Queue & Webhook Infrastructure', results);
  await browser.close();
  process.exit(exitCode);
}

main().catch(err => { console.error('Fatal error:', err.message); process.exit(1); });
```

Support `--check=queues`, `--check=pause-resume`, `--check=all` flags. When Plan 02 adds webhook validation, it will add `--check=gmail`, `--check=microsoft`, `--check=webhook-health` support.
