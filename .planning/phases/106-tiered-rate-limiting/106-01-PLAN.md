    Override `canActivate()` in UserThrottlerGuard to filter `this.throttlers` to only the single relevant tier before delegating to the parent's per-throttler loop logic.

    Implementation strategy (based on reading the ThrottlerGuard source):

    The parent `canActivate()` iterates `this.throttlers` and calls `handleRequest()` for each. We override `canActivate()` to:
    1. Call `shouldSkip()` -- if true, return true (preserve existing skip logic)
    2. Determine the tier for this request:
       a. Check `@RateTier` decorator metadata via `this.reflector.getAllAndOverride<RateTier>(RATE_TIER_KEY, [handler, classRef])`
       b. If no decorator, auto-assign: GET/HEAD/OPTIONS -> 'read', everything else -> 'safe-write'
    3. Temporarily replace `this.throttlers` with only the matching throttler
    4. Call `super.canActivate(context)` (which will now only loop over the one tier)
    5. Restore `this.throttlers` to the full list (use try/finally)

    Add imports:
    ```typescript
    import { Reflector } from '@nestjs/core';
    import { RATE_TIER_KEY, RateTier } from '../decorators/rate-tier.decorator';
    ```

    The guard constructor needs `Reflector` -- check if ThrottlerGuard already injects it (it does, as `this.reflector`). So no constructor changes needed beyond what ThrottlerGuard provides.

    Full updated guard body (keep getTracker and shouldSkip unchanged):
    ```typescript
    async canActivate(context: ExecutionContext): Promise<boolean> {
      if (await this.shouldSkip(context)) {
        return true;
      }

      const handler = context.getHandler();
      const classRef = context.getClass();

      // Determine which single tier applies
      const decoratorTier = this.reflector.getAllAndOverride<RateTier>(RATE_TIER_KEY, [handler, classRef]);
      let tierName: string;
      if (decoratorTier) {
        tierName = decoratorTier;
      } else {
        const req = context.switchToHttp().getRequest();
        const method = req.method || 'GET';
        tierName = (method === 'GET' || method === 'HEAD' || method === 'OPTIONS') ? 'read' : 'safe-write';
      }

      // Filter to only the matching tier, then delegate to parent
      const allThrottlers = this.throttlers;
      const matchingThrottlers = allThrottlers.filter(t => t.name === tierName);
      if (matchingThrottlers.length === 0) {
        // No matching tier config -- allow request (fail-open)
        return true;
      }

      this.throttlers = matchingThrottlers;
      try {
        return await super.canActivate(context);
      } finally {
        this.throttlers = allThrottlers;
      }
    }
    ```

    Note: `this.throttlers` is a property set in `onModuleInit()`. Swapping it is safe because NestJS processes requests single-threaded per event loop tick in the guard's synchronous entry, and we restore in `finally`. However, if there's concern about concurrency, an alternative is to copy the parent's canActivate loop inline. Check the parent source -- if `this.throttlers` is used only in the for-loop within `canActivate`, the swap-and-restore is safe since `await` yields only inside `handleRequest` which is per-throttler.

    Actually, the safer approach (no mutation of shared state): Copy the parent's `canActivate` loop logic but only iterate over matching throttlers. This avoids any concurrency concern. Read the full `canActivate` from node_modules and replicate it with the filtered throttler list. This is more code but zero risk.

    Choose whichever approach is cleaner after reading the full source. If the parent's `canActivate` is <30 lines, inline it. If it's complex, use the swap approach.
