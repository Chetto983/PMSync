**scripts/validate-incremental-sync.mjs** (orchestrator):
- Same structure as `validate-full-sync.mjs`: parse `--provider=gmail|outlook|microsoft|imap|all` and `--quick` flags
- Import `connectCDP`, `getAuthCookies`, `getCsrfToken`, `apiGet`, `report` from `./lib/validation-helpers.mjs`

**scripts/lib/validate-gmail-incremental.mjs** (SYNC-04):
Export `async function validateGmailIncremental(context, cookieHeader, csrfToken, providers, quick)` returning `{ name, checks, passed, failed, failures, skipped? }`.

Validation steps:
1. Find Gmail provider (providerType === 'google' || 'gmail'), skip if not found
2. Record pre-sync state: `GET /api/v1/emails?providerId=X&limit=1` to get current email count and most recent email's externalId
3. Record pre-sync lastSyncToken: `GET /api/v1/providers` and extract `provider.metadata.lastSyncToken` for the Gmail provider
4. Assert lastSyncToken exists and is non-empty (prerequisite: full sync must have run -- assertEqual 'Gmail has lastSyncToken', !!token, true)
5. Trigger incremental sync: `POST /api/v1/email-sync/sync/:providerId` (if not quick mode)
6. Wait for sync completion via `waitForSyncCompletion(context, cookieHeader)` (existing helper)
7. Record post-sync state: same queries as step 2
8. Assert: post-sync lastSyncToken is different from or equal to pre-sync token (incremental sync updates token even if no changes -- assertTrue 'lastSyncToken updated or unchanged')
9. Assert: email count is >= pre-sync count (no emails should disappear during incremental -- assertRange)
10. Assert: no duplicate externalIds in latest 100 emails (`GET /api/v1/emails?providerId=X&limit=100`, check uniqueness)
11. Quick mode: skip steps 5-6, only validate existing state (token exists, no dupes)

**scripts/lib/validate-outlook-incremental.mjs** (SYNC-05):
Export `async function validateOutlookIncremental(context, cookieHeader, csrfToken, providers, quick)`.

Same validation pattern as Gmail but:
1. Find provider with providerType === 'microsoft' || 'outlook'
2. lastSyncToken is a JSON string (parse it to verify it contains folder deltaLinks)
3. Assert parsed token has at least INBOX key (assertEqual 'Outlook token has INBOX deltaLink', !!parsed.INBOX || !!parsed.Inbox, true)
4. Trigger incremental sync, wait, verify token updates
5. Verify email count stable, no dupes in 100 emails
6. Quick mode: validate existing state only

**scripts/lib/validate-imap-incremental.mjs** (SYNC-06):
Export `async function validateImapIncremental(context, cookieHeader, csrfToken, providers, quick)`.

Same pattern but:
1. Find provider with providerType === 'imap'
2. lastSyncToken is comma-separated `folder:modseq` pairs. Parse and verify at least one folder entry exists.
3. Assert token contains INBOX entry (assertTrue 'IMAP token has INBOX modseq', token.includes('INBOX:'))
4. Trigger incremental sync, wait, verify token updates
5. Verify email count stable, no dupes in 100 emails
6. Quick mode: validate existing state only

All scripts must:
- Use `setResultsCollector(results)` at start, `setResultsCollector(null)` at end
- Use `assertEqual`, `assertRange`, `assertTrue` from validation-helpers.mjs for all checks
- Handle missing provider gracefully (return `{ ...results, skipped: 'reason' }`)
- Stay under 500 lines per file
