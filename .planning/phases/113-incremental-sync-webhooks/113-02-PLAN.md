**scripts/lib/validate-gmail-webhook.mjs** (SYNC-07):
Export `async function validateGmailWebhook(context, cookieHeader, csrfToken, providers, quick)`.

Validation steps (adapt based on actual API endpoints found in code):
1. Find Gmail provider (providerType === 'google' || 'gmail'), skip if not found
2. Check webhook subscription status via the health/status endpoint discovered in code
3. Assert: Gmail Pub/Sub subscription exists for this provider (assertEqual)
4. Assert: Subscription status is 'active' or equivalent
5. Assert: Subscription expiresAt is in the future (assertTrue 'expiration > now')
6. Assert: lastNotificationAt exists (webhook has received at least one notification -- or skip if subscription is new)
7. If not quick mode: verify that triggering incremental sync after webhook state check still works (validates the webhook->sync pipeline is wired)
8. Check for the `lastSyncToken` on the provider (webhook triggers incremental sync which uses tokens from Plan 01)
9. Quick mode: only validate subscription state (steps 2-6)

**scripts/lib/validate-microsoft-webhook.mjs** (SYNC-08):
Export `async function validateMicrosoftWebhook(context, cookieHeader, csrfToken, providers, quick)`.

Same validation pattern as Gmail but:
1. Find provider with providerType === 'microsoft' || 'outlook'
2. Check Microsoft Graph subscription via the health/status endpoint
3. Assert: Microsoft subscription exists for this provider
4. Assert: Subscription is active
5. Assert: Subscription expiration is in the future
6. Assert: clientState is set (used for notification validation)
7. If not quick mode: verify incremental sync still works for this provider
8. Quick mode: only validate subscription state

All scripts must:
- Use `setResultsCollector(results)` / `setResultsCollector(null)` pattern
- Use `assertEqual`, `assertTrue` from validation-helpers.mjs
- Handle missing provider or missing subscription gracefully (skip with reason)
- Stay under 500 lines per file
- If no webhook API endpoints exist for listing subscriptions, fall back to checking the provider metadata for webhook-related fields, or query the webhook health endpoint from the research notes
