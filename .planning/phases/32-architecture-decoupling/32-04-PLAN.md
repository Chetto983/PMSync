<task type="auto">

  <files>
    .github/workflows/ci.yml
  </files>
  <action>
    **Per CONTEXT.md locked decisions:**
    - GitHub Actions step only -- no pre-commit hook, no local developer friction
    - PR blocked if circular count > baseline
    - Baseline updated when violations are intentionally reduced

    Add a new step to the backend job in `.github/workflows/ci.yml`, AFTER the Jest step:

    ```yaml
    - name: Dependency boundary check
      run: |
        npx depcruise --config .dependency-cruiser.cjs \
          --ignore-known .dependency-cruiser-known-violations.json src
        echo "--- Circular dependency report ---"
        npx madge --circular --extensions ts --ts-config tsconfig.json src || true
    ```

    Key design decisions:
    - dep-cruiser runs first and will FAIL the step if new circular deps are introduced (error severity + baseline)
    - madge runs second with `|| true` -- it's informational (visual report), not a gate
    - If dep-cruiser fails, the CI step fails, the PR is blocked
    - To allow new accepted violations, developer updates the baseline and commits it

    Do NOT add a separate CI job. Add as a step in the existing `backend` job, after tests.
    Do NOT add pre-commit hooks (per user decision).
  </action>
  <verify>
    <automated>grep -q "Dependency boundary check" .github/workflows/ci.yml && echo "CI step exists"</automated>
  </verify>
