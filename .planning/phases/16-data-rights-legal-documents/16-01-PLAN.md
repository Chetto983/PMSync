Add two new models to schema.prisma:

**LegalAcceptance model:**
```prisma
model LegalAcceptance {
  id              String   @id @default(cuid())
  tenantId        String
  userId          String
  documentType    String   // 'TOS' or 'PRIVACY_POLICY'
  documentVersion String   // e.g., '1.0', '1.1'
  acceptedAt      DateTime @default(now())
  ipAddress       String?
  userAgent       String?

  tenant Tenant @relation(fields: [tenantId], references: [id], onDelete: Cascade)
  user   User   @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, documentType, acceptedAt(sort: Desc)])
  @@index([tenantId, documentType])
  @@map("legal_acceptances")
}
```

**DataExportRequest model:**
```prisma
model DataExportRequest {
  id          String    @id @default(cuid())
  tenantId    String
  userId      String
  status      String    @default("PENDING") // PENDING, PROCESSING, READY, EXPIRED, FAILED
  filePath    String?
  fileSize    Int?
  expiresAt   DateTime?
  error       String?
  createdAt   DateTime  @default(now())
  completedAt DateTime?

  tenant Tenant @relation(fields: [tenantId], references: [id], onDelete: Cascade)
  user   User   @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, status])
  @@index([expiresAt])
  @@map("data_export_requests")
}
```

Also add the reverse relations on the User and Tenant models:
- On User model: `legalAcceptances LegalAcceptance[]` and `dataExportRequests DataExportRequest[]`
- On Tenant model: `legalAcceptances LegalAcceptance[]` and `dataExportRequests DataExportRequest[]`

Run `npx prisma validate` and `npx prisma generate` to verify the schema is valid.

**1. Create `legal.constants.ts`:**
- Export `CURRENT_TOS_VERSION = '1.0'` and `CURRENT_PP_VERSION = '1.0'`
- Export `DocumentType` enum or string union: `'TOS' | 'PRIVACY_POLICY'`
- Export `LEGAL_DOCUMENTS` array with `{ type, version, label }` for each document

**2. Create `dto/legal-acceptance.dto.ts`:**
- `AcceptLegalDocumentDto`: `{ documentType: string, documentVersion: string }` with class-validator decorators (@IsString, @IsNotEmpty, @IsIn(['TOS', 'PRIVACY_POLICY']))
- `LegalStatusDto`: response shape `{ tosAccepted: boolean, tosVersion: string, ppAccepted: boolean, ppVersion: string, currentTosVersion: string, currentPpVersion: string }`

**3. Create `services/legal-acceptance.service.ts`:**
- Inject PrismaService and Logger
- `accept(userId, tenantId, documentType, documentVersion, ipAddress?, userAgent?)`: Create LegalAcceptance record. Validate documentType is valid and documentVersion matches CURRENT version for that type. Return the created record.
- `hasAcceptedCurrentVersions(userId, tenantId)`: Check if user has accepted BOTH current TOS and PP versions. Query LegalAcceptance with `userId`, `documentType`, `documentVersion` matching current constants. Return boolean.
- `getStatus(userId, tenantId)`: Return LegalStatusDto with acceptance status for each document type. Query latest acceptance per document type.
- Follow the ConsentService pattern for Prisma queries and error handling.

**4. Create `guards/legal-acceptance.guard.ts`:**
- Follow the exact pattern of `consent.guard.ts` (CanActivate, inject LegalAcceptanceService)
- Extract userId and tenantId from `request.user`
- Call `this.legalAcceptanceService.hasAcceptedCurrentVersions(userId, tenantId)`
- If not accepted, throw `ForbiddenException('You must accept the current Terms of Service and Privacy Policy')`
- Add `@SkipLegalCheck()` decorator using Reflector (same pattern as @SkipConsent if it exists, or create via SetMetadata) to allow bypassing on specific routes (like the legal acceptance endpoint itself, auth endpoints)

**5. Create `controllers/legal.controller.ts`:**
- `@Controller('compliance/legal')` with `@UseGuards(JwtAuthGuard, TenantGuard)`
- `GET /compliance/legal/status` -- returns LegalStatusDto (do NOT apply LegalAcceptanceGuard here -- user needs to check status even if not accepted yet)
- `POST /compliance/legal/accept` -- accepts AcceptLegalDocumentDto, records acceptance. Extract IP from `request.ip` and userAgent from `request.headers['user-agent']`. Do NOT apply LegalAcceptanceGuard here either.
- Add Swagger decorators (@ApiTags, @ApiOperation, @ApiResponse)

**6. Update `compliance.module.ts`:**
- Add LegalAcceptanceService to providers and exports
- Add LegalAcceptanceGuard to providers and exports
- Add LegalController to controllers
- Import any needed modules (PrismaModule should already be imported)

Run `npm run type-check` to verify everything compiles.
