**Step 1: Scan for hardcoded English strings in .tsx files.**
Run these grep patterns to find hardcoded user-visible strings:
```
grep -rn ">[A-Z][a-z]" frontend/src --include="*.tsx" | grep -v "import\|export\|//\|console\|className\|data-\|aria-\|testid\|key=" | head -50
grep -rn "title=\"[A-Z]" frontend/src --include="*.tsx" | head -20
grep -rn "label=\"[A-Z]" frontend/src --include="*.tsx" | head -20
grep -rn "placeholder=\"[A-Z]" frontend/src --include="*.tsx" | head -20
grep -rn "helperText=\"[A-Z]" frontend/src --include="*.tsx" | head -20
```

Also scan the old-style component directories:
```
grep -rn ">[A-Z][a-z]" frontend/components --include="*.tsx" | grep -v "import\|export\|//\|console\|className\|data-\|aria-\|testid\|key=" | head -50
grep -rn ">[A-Z][a-z]" frontend/pages --include="*.tsx" | grep -v "import\|export\|//\|console\|className\|data-\|aria-\|testid\|key=" | head -50
```

**Step 2: For each hardcoded string found, determine if it is user-visible.**
Skip strings that are:
- Component names or technical identifiers (e.g., `>React`, `>MUI`)
- Already wrapped in `t.section.key` or `{t(...)}` calls
- Inside comments or JSX comments
- Inside `console.log` or `console.error`
- Inside `data-testid`, `aria-label` (unless user-visible), `className`
- SVG path data or technical constants

**Step 3: For each genuine user-visible hardcoded string:**
1. READ the .tsx file containing the hardcoded string before editing (CLAUDE.md READ BEFORE EDIT protocol)
2. Add English key to `frontend/locales/en.ts` under the appropriate section (match the component's domain: chat, email, calendar, etc.)
3. Add Italian translation to `frontend/locales/it.ts` under the same path
4. Add type declaration to `frontend/locales/index.ts` under the same path
5. Update the .tsx file to use `t.section.key` via the `useTranslations()` hook

Follow existing i18n patterns in the codebase:
- Hook: `const t = useTranslations();`
- Usage: `{t.chat.someKey}` or `title={t.settings.someLabel}`
- If the component doesn't already import `useTranslations`, add the import

**Step 4: If few or zero hardcoded strings are found (possible -- previous phases may have cleaned these up), document the scan results and mark CLN-02 as satisfied.**
