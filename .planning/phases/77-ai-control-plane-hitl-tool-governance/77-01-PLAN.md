- The `ActionQueue` model (around line 1288)

- All `actionQueue ActionQueue[]` relation fields on `Tenant`, `User`, and `Email` models

Create migration via `cd backend && npx prisma migrate dev --name drop_action_queue`. Since PostgreSQL cannot DROP enum values, the migration must:
1. DROP TABLE `action_queue` (CASCADE)
2. DROP TYPE "ActionType"
3. DROP TYPE "ActionStatus"

If Prisma auto-generates this correctly, no manual SQL needed. If not, write the migration SQL manually with those 3 statements.

**Step 2: Extend IAiTool interface with OPTIONAL governance fields**

In `backend/src/common/interfaces/tool-registry.interface.ts`:
- Add `ToolDomain` type: `'email' | 'calendar' | 'contacts' | 'knowledge' | 'productivity' | 'system'`
- Add `RiskLevel` type: `'LOW' | 'MEDIUM' | 'HIGH'`
- Add to `IAiTool` as OPTIONAL fields: `domain?: ToolDomain`, `riskLevel?: RiskLevel`, `requiresApproval?: boolean`, `inputSchema?: unknown` (zod schema or JSON schema)
- Export `ToolDomain` and `RiskLevel` types
- Keep existing fields (name, description, parameters, execute) unchanged
- The fields are optional in the TypeScript interface so that existing tool services compile without modification. Enforcement happens at RUNTIME in registerTool() (Step 3).
- Do NOT add a separate `registerToolGovernance()` method -- the existing `registerTool(tool: IAiTool)` signature is sufficient since IAiTool now includes governance fields

**Step 3: Add registration-time validation in ToolRegistryService**

In `backend/src/common/modules/tool-registry/tool-registry.service.ts`:
- Update the existing `registerTool()` method to validate that `domain`, `riskLevel`, `requiresApproval`, and `inputSchema` are all present (not undefined) on the incoming `IAiTool`
- If any field is missing/undefined, throw `Error('Tool "${tool.name}" missing required governance metadata: ${missingFields.join(", ")}')`
- This makes tools that skip governance metadata fail at app startup, not at request time
- The fields are optional in the TypeScript type but REQUIRED at runtime -- this is intentional to keep tsc green while Task 2 adds them to all tool services

Run `cd backend && npx prisma generate` after migration.
Run `cd backend && npx tsc --noEmit` to verify no type errors. Since governance fields are optional in the interface, tsc will pass even before Task 2 adds the fields to tool services.
