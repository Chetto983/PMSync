  <action>
Run the validation script against Gmail first (most likely to have data):

```bash
node scripts/validate-email-read.mjs --provider=gmail
```

Analyze the output. For each FAIL result:

1. **Identify root cause**: Is it a script bug (wrong response envelope path, wrong assertion) or a backend bug (incorrect filter logic, missing data)?

2. **Script bugs**: Fix the validation script's response parsing. Common issues:
   - Response envelope path mismatch: try `res?.data?.emails`, `res?.data?.data`, `res?.emails`, `res?.data`
   - Pagination metadata path: try `res?.pagination`, `res?.meta`, `res?.data?.pagination`
   - Thread response shape: could be array directly or `{ data: [...] }`

3. **Backend bugs**: Fix in the backend source. Common issues from research:
   - `buildEmailWhere()` not handling a filter param correctly
   - Thread endpoint not returning body content (lazy-fetch not triggered)
   - Single email GET missing includes (attachments, emailLabels, provider)
   - After ANY backend edit, run `cd backend && npx tsc --noEmit` to verify

4. Re-run after each fix: `node scripts/validate-email-read.mjs --provider=gmail`

5. Once Gmail passes, run for other providers if available:
   ```bash
   node scripts/validate-email-read.mjs --provider=outlook
   node scripts/validate-email-read.mjs --provider=imap
   ```

6. Final full run: `node scripts/validate-email-read.mjs`

Bug fix scope: Only fix what the validation reveals. Do not refactor, do not add features. If a bug requires > 50 lines of change, document it and ask before proceeding.
