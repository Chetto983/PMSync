  <action>
  **1. Add TTL + max size to tool agent pool Maps:**

  Read each tool file. Find the module-level `Map` instances that cache Mistral agents. Add:
  - `MAX_POOL_SIZE = 50` (configurable via env var `AI_AGENT_POOL_MAX_SIZE`)
  - `TTL = 30 * 60 * 1000` (30 minutes, configurable via `AI_AGENT_POOL_TTL_MS`)
  - Wrap the Map in a simple TTL cache helper: store entries as `{ agent, createdAt }`, evict on get if expired, evict oldest on set if over max size
  - Apply to: `web-search.tools.ts`, `analytics.tools.ts`, `document-library.tools.ts`
  - **Why TTL eviction is safe:** Tool agents are stateless per-call. They do NOT maintain conversation history or session state. Each tool invocation creates a fresh request to the Mistral API. Evicting a cached agent simply means the next call will create a new agent instance -- no data loss, no broken conversations.

  Create a shared helper if the pattern repeats identically. Place in `voltagent/tools/utils.ts` (which already exists) or `voltagent/tools/agent-pool-cache.ts`.

  **2. Add query timeout to unified-retriever.ts:**

  After the split (Plan 11-02), the retriever orchestrates vector + keyword search. Add:
  - `RAG_QUERY_TIMEOUT_MS = parseInt(process.env.RAG_QUERY_TIMEOUT_MS || '10000', 10)` (10 second default)
  - Wrap each search call in `Promise.race([searchPromise, timeoutPromise])` where timeout rejects with a descriptive error
  - If one search times out, continue with results from the other (graceful degradation, not full failure)
  - Log a warning when timeout occurs

  **3. Add MISTRAL_API_KEY startup validation:**

  In `ai.config.ts` or `ai.module.ts`, add validation:
  - If `NODE_ENV === 'production'` and `MISTRAL_API_KEY` is not set, throw a clear error at module init
  - If `NODE_ENV !== 'production'`, log a warning but don't crash (dev/test environments may not need it)

  **CRITICAL:** Do NOT break local development. Only fail-fast in production.
  </action>
