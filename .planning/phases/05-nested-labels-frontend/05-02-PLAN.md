**1. LabelTreeDndWrapper (NEW: frontend/components/email/labels/LabelTreeDndWrapper.tsx)**

Create ~200-250 lines. This wraps the label tree in its OWN DndContext (separate from EmailLayout's DndContext to avoid collision — see RESEARCH.md Pitfall 3).

Key architecture (follows official dnd-kit flattened tree pattern):

```typescript
import {
  DndContext,
  closestCenter,
  KeyboardSensor,
  PointerSensor,
  useSensor,
  useSensors,
  DragStartEvent,
  DragMoveEvent,
  DragEndEvent,
  DragOverlay,
  MeasuringStrategy,
} from '@dnd-kit/core';
import {
  SortableContext,
  verticalListSortingStrategy,
  useSortable,
  arrayMove,
} from '@dnd-kit/sortable';
```

Props:
```typescript
interface LabelTreeDndWrapperProps {
  flatItems: FlattenedItem[];
  tree: TreeItem[];
  onItemRender: (item: FlattenedItem) => React.ReactNode;
}
```

State:
- `activeId: string | null` — currently dragged label
- `overId: string | null` — current drop target
- `offsetLeft: number` — horizontal drag offset (drives depth projection)
- `projected: { depth: number; parentId: string | null } | null` — live projection result

Sensors:
- `PointerSensor` with `activationConstraint: { distance: 8 }` (8px drag threshold before activating)
- `KeyboardSensor` with `sortableKeyboardCoordinates`

Handlers:
- `handleDragStart(event: DragStartEvent)`: Set activeId. Collapse the dragged item's children (prevent dragging expanded subtree).
- `handleDragMove(event: DragMoveEvent)`: Update offsetLeft from `event.delta.x`. Compute projection via `getProjection(flatItems, activeId, overId, offsetLeft, INDENT_WIDTH)`.
- `handleDragOver(event: DragOverEvent)`: Update overId.
- `handleDragEnd(event: DragEndEvent)`: If projection is valid, call `useMoveLabel` mutation with `{ parentId: projected.parentId, orderIndex: computedIndex }`. Reset all state. The orderIndex computation: find the position in the sibling list where the item should be inserted.
- `handleDragCancel()`: Reset all state.

Measuring:
```typescript
const measuring = {
  droppable: { strategy: MeasuringStrategy.Always },
};
```

DragOverlay:
- Show a semi-transparent ghost of the dragged label using `LabelTreeItem` with `isDragging={true}` and `opacity: 0.7`.
- If `projected` depth would exceed MAX_DEPTH - 1, show a red tint on the overlay (visual "can't drop here" feedback).

SortableContext items: `flatItems.map(item => item.id)`

For each item, create a `SortableLabelItem` wrapper (similar to SortableFolderItem.tsx) that calls `useSortable` with `id: item.id` and passes `setNodeRef`, `attributes`, `listeners`, `transform`, `transition`, `isDragging` down to `LabelTreeItem`.

The indentation width for projection:
```typescript
const INDENT_WIDTH = 16; // Matches decision: 16px per level for first 2 levels
```

Filtering logic:
```typescript
const filteredFlatItems = useMemo(() => {
  if (!searchQuery.trim()) return flatItems;

  const query = searchQuery.toLowerCase();

  // Find matching label IDs
  const matchIds = new Set(
    userLabels
      .filter(l => l.name.toLowerCase().includes(query))
      .map(l => l.id)
  );

  // Also include ancestor IDs (show path to match)
  const ancestorIds = new Set<string>();
  matchIds.forEach(id => {
    getAncestorIds(userLabels, id).forEach(aid => ancestorIds.add(aid));
  });

  // Filter flat items to only show matches + their ancestors
  const visibleIds = new Set([...matchIds, ...ancestorIds]);
  return flatItems.filter(item => visibleIds.has(item.id));
}, [flatItems, searchQuery, userLabels]);
```
