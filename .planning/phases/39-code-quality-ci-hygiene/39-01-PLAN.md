Three independent fixes in one task:

**Fix 1: Lighthouse CI trigger scope (`.github/workflows/frontend-ci.yml`)**
- Remove the `paths: ['frontend/**']` filter from BOTH the `push:` and `pull_request:` triggers in the `on:` block
- Keep branches filter (`main`, `develop`) unchanged
- Result: Lighthouse CI runs on ALL PRs, including mixed backend+frontend PRs
- This costs ~2 min extra on backend-only PRs but prevents missing regressions on mixed PRs

Before:
```yaml
on:
  push:
    branches: [main, develop]
    paths: ['frontend/**']
  pull_request:
    branches: [main, develop]
    paths: ['frontend/**']
```

After:
```yaml
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]
```

**Fix 2: OpenAPI CI error masking (`.github/workflows/ci.yml`)**
- In the "Generate OpenAPI spec" step, remove the `|| echo "OpenAPI generation requires database -- skipping in CI for now"` fallback
- KEEP `continue-on-error: true` (database genuinely unavailable in CI)
- The downstream steps already check `steps.openapi-gen.outcome == 'success'` so they correctly skip on failure
- The improvement: step now shows as failed (orange) in GitHub Actions UI instead of falsely green

Before:
```yaml
- name: Generate OpenAPI spec
  id: openapi-gen
  run: |
    npx ts-node scripts/generate-openapi.ts || echo "OpenAPI generation requires database -- skipping in CI for now"
  continue-on-error: true
```

After:
```yaml
- name: Generate OpenAPI spec
  id: openapi-gen
  run: npx ts-node scripts/generate-openapi.ts
  continue-on-error: true
```
