**Part A: Investigate and fix chat 403 error**

The chat 403 is caused by the guard chain on `AiChatController`: `JwtAuthGuard -> TenantGuard -> ConsentGuard -> QuotaGuard`. The `@RequiresConsent('ai_chat')` decorator is commented out (line 69 of ai-chat.controller.ts), so ConsentGuard passes. But ConsentGuard is ALSO registered globally as APP_GUARD in AppModule (line 99-102 of app.module.ts), meaning it runs on EVERY route including chat. The global ConsentGuard checks if any `@RequiresConsent()` decorator is present -- since it is commented out, the guard should skip. The likely culprit is QuotaGuard.

1. Read `backend/src/modules/subscription/guards/quota.guard.ts` to understand the 403 conditions
2. Read `backend/src/modules/compliance/guards/consent.guard.ts` to verify global guard behavior
3. Trace the exact 403 path: QuotaGuard calls `subscriptionService.getOrCreateSubscription(tenantId)` -- if subscription creation fails or returns unexpected state, it throws ForbiddenException
4. The fix depends on root cause:
   - If QuotaGuard blocks when no subscription exists for tenant: Fix the auto-creation logic or add a graceful fallback (allow access when subscription is missing/new)
   - If ConsentGuard double-fires (global + controller-level): The global guard should check for decorator presence and skip when absent -- verify this logic
5. After fixing, verify the chat endpoint returns 200 (not 403) by checking the guard logic statically
6. Document the root cause as a code comment where the fix is applied
