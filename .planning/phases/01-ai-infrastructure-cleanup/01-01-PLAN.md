  <name>Task 1: VoltAgent Implementation Audit</name>
  <files>
    .planning/phases/01-ai-infrastructure-cleanup/AUDIT.md
  </files>
  <action>
Conduct comprehensive audit of VoltAgent integration. For each area, document:
- Current implementation (file paths, code snippets)
- Official VoltAgent pattern (from research)
- Deviation analysis (what differs and why it matters)
- Fix recommendation (specific changes needed)

**Areas to audit:**

1. **Agent Creation Pattern** - Check `unified.agent.ts` and `supervisor.agent.ts`:
   - How agents are instantiated
   - Tool loading and registration
   - Memory adapter configuration
   - Hooks setup for observability

2. **Memory/Persistence Layer** - Check `episodic-memory.service.ts`, memory controllers:
   - How conversations are persisted
   - Multi-tenant isolation
   - Race condition handling (is RedisLockService used?)
   - Lost message root cause

3. **Tool Execution** - Check tool files in `voltagent/tools/`:
   - Tool parameter validation (Zod schemas)
   - Error handling in tool executors
   - Timeout handling for slow operations
   - Tool result caching

4. **Chat Flow** - Check `conversation.controller.ts`, `chat-prepare.service.ts`:
   - Request/response flow
   - Context loading latency
   - Streaming vs polling pattern
   - Error recovery

5. **Infrastructure Usage** - Check if existing common services are being used:
   - CircuitBreaker for LLM calls
   - withRetry for transient failures
   - CacheService for response caching
   - RedisLockService for concurrent safety

6. **Known Issues from CONTEXT.md**:
   - Slow chat (measure current latency if possible)
   - Lost messages (trace conversation persistence)
   - Tool call failures (check error handling)
   - Context window issues (check token management)
