**11. WCAG accessibility re-audit (per CONTEXT.md locked decision):**
Audit ALL v3.1 components (phases 13-21) for accessibility compliance:
- **Focus order:** Tab through each page and verify logical focus sequence. Check for focus traps.
- **ARIA attributes:** Grep for missing aria-label/aria-labelledby on interactive elements (buttons, inputs, links without visible text). Check for incorrect roles.
- **Color contrast:** Verify text contrast ratios meet WCAG AA (4.5:1 normal text, 3:1 large text). Check both light and dark themes.
- **Keyboard navigation:** Verify all interactive elements are reachable and operable via keyboard alone (Enter, Space, Escape, Arrow keys). Check modals for focus containment.
- Specific v3.1 areas to check: GDPR consent toggles, data export/deletion panels, WritingStyleSettings (if visible), AI triage chips, draft generation controls, legal acceptance dialogs.
- Document each violation as a bug entry (category: accessibility, fix plan: 04 for frontend, 03 for backend).

**12. OWASP top 10 security scan (per CONTEXT.md locked decision):**
Audit the codebase for common security vulnerabilities:
- **XSS:** Check for dangerouslySetInnerHTML usage in frontend, unsanitized user input in HTML rendering, missing Content-Security-Policy headers.
- **CSRF:** Verify csrf-csrf middleware is active and protecting state-changing endpoints. Check SameSite cookie attributes.
- **SQL injection / Prisma injection:** Grep for raw SQL queries (`$queryRaw`, `$executeRaw`) and verify parameterized queries are used. Check for `$queryRawUnsafe`.
- **Auth bypass:** Check for endpoints missing `@UseGuards(JwtAuthGuard)` that should be protected. Verify LegalAcceptanceGuard and ConsentGuard are correctly mounted.
- **Rate limiting:** Verify ThrottlerGuard is active on sensitive endpoints (login, password reset, AI chat). Check rate limit values.
- **Hardcoded secrets:** Grep for API keys, passwords, tokens hardcoded in source (not .env). Check .env.example matches actual usage.
- **Dependency vulnerabilities:** Already covered by npm audit in step 4.
- Document each finding as a bug entry (category: security, route fixes to Plan 03 for backend, Plan 04 for frontend).

**13. Deep email sync engine audit (per CONTEXT.md locked decision):**
Audit the email sync subsystem for correctness and race conditions:
- **IMAP sync flow:** Read `backend/src/modules/email-sync/services/` -- trace the full sync lifecycle from trigger to completion. Document any error handling gaps.
- **Folder operations:** Read `folder-sync.service.ts` -- check for RC-A1 (missing Redis lock on syncProviderFolders) and RC-A8 (missing Redis lock on folder CRUD). Document current state.
- **Multi-tenant race conditions:** Check for concurrent sync protection. Are Redis locks used correctly? Is there a deadlock risk between folder sync and email sync?
- **P2002/P2034 handling:** Grep for Prisma error code handling in sync services. Is P2034 (deadlock/write conflict) retried? Is P2002 (unique constraint) handled gracefully? Check if `prisma-retry.service.ts` exists in `backend/src/common/services/`.
- **Token expiry handling:** Check OAuth token refresh logic -- what happens if the token expires mid-sync?
- Document each finding as a bug entry (category: sync, fix plan: 03).
