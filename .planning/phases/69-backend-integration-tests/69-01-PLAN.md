Create `backend/test/integration/tenant-isolation.spec.ts`.

This spec proves tenant-scoping isolation across 5 domains. The pattern is always the same: create two tenants, create representative rows for each tenant using factories (which use `withoutTenantScopingAsync` internally — they bypass scoping so the plain client writes succeed), then query via a scoped client wrapped in `CorrelationContext.run({ tenantId }, fn)` and assert zero cross-tenant rows.

**Critical wiring:**
- `getTestPrismaClient()` returns a PLAIN client with NO extension. You MUST apply the extension manually:
  ```typescript
  const baseClient = getTestPrismaClient();
  const scopedClient = baseClient.$extends(createTenantScopingExtension()) as any;
  ```
- All reads on `scopedClient` MUST be wrapped in `CorrelationContext.run({ tenantId: tenantX.id }, fn)` — the extension reads tenantId from this ALS context. Without it, the extension throws `TenantContextRequiredError` (enforce mode, `AUDIT_MODE = false`).
- Writes use the PLAIN `baseClient` with `withoutTenantScopingAsync` (same as factories do internally).
- Do NOT call `cleanupTestData()` (full TRUNCATE CASCADE) in `afterAll` — it causes FK violations in parallel Jest workers. Use targeted deletes keyed by tenantId instead.

**Import paths** (relative to `backend/test/integration/`):
- helpers: `'../helpers/factories'`
- prisma client: `'../helpers/prisma-test-client'`
- extension: `'../../src/prisma/tenant-scoping/tenant-scoping.extension'`
- tenant context: `'../../src/prisma/tenant-scoping/tenant-context'`
- correlation context: `'../../src/common/services/correlation-context.service'`

**Spec structure:**

```
describe('Cross-Tenant Isolation (BINT-01)') {
  // Shared state: two tenants, one user each, scoped client
  let tenantA, tenantB, userA, userB;
  let scopedClient: any;

  beforeAll(async () => {
    const baseClient = getTestPrismaClient();
    scopedClient = baseClient.$extends(createTenantScopingExtension()) as any;
    tenantA = await createTestTenant();
    tenantB = await createTestTenant();
    userA = await createTestUser(tenantA.id);
    userB = await createTestUser(tenantB.id);
  });

  afterAll(async () => {
    // Targeted cleanup — delete in FK-safe reverse order
    const baseClient = getTestPrismaClient();
    await withoutTenantScopingAsync(async () => {
      await baseClient.userLabel.deleteMany({ where: { tenantId: { in: [tenantA.id, tenantB.id] } } });
      await baseClient.calendarEvent.deleteMany({ where: { tenantId: { in: [tenantA.id, tenantB.id] } } });
      await baseClient.contact.deleteMany({ where: { tenantId: { in: [tenantA.id, tenantB.id] } } });
      await baseClient.subscription.deleteMany({ where: { tenantId: { in: [tenantA.id, tenantB.id] } } });
      await baseClient.providerConfig.deleteMany({ where: { tenantId: { in: [tenantA.id, tenantB.id] } } });
      await baseClient.user.deleteMany({ where: { tenantId: { in: [tenantA.id, tenantB.id] } } });
      await baseClient.tenant.deleteMany({ where: { id: { in: [tenantA.id, tenantB.id] } } });
    });
  });

  describe('Labels domain') {
    it('tenant A cannot see tenant B labels') {
      // Create label for tenantB via factory
      // Query via scopedClient as tenantA
      // Assert none have tenantId === tenantB.id
    }
    it('tenant A sees only its own labels') {
      // Create label for tenantA via factory
      // Query via scopedClient as tenantA
      // Assert all results have tenantId === tenantA.id
    }
  }

  describe('Calendar domain') { // CalendarEvent — requires a providerConfig first }
  describe('Contacts domain') { // Contact }
  describe('Providers domain') { // ProviderConfig }
  describe('Subscription domain') { // Subscription — unique per tenant, use fresh tenant per test }
}
```

**Subscription domain note:** `Subscription` has a UNIQUE constraint on `tenantId` (only one per tenant). For the isolation test, create a third tenantC and tenantD specifically for the subscription tests so no unique constraint violation occurs.

**CalendarEvent domain note:** `CalendarEvent` requires a `providerId` FK. Create a `ProviderConfig` row first via `createTestProviderAccount(tenantX.id, userX.id)`, then use its `id` as `providerId` in `createTestCalendarEvent`.

The isolation assertion pattern for every domain:
```typescript
// Create row for tenantB (the "other" tenant)
const labelB = await createTestLabel(tenantB.id);

// Query as tenantA — should get zero rows for tenantB data
const resultsAsA = await CorrelationContext.run({ tenantId: tenantA.id }, () =>
  scopedClient.userLabel.findMany()
);
expect(resultsAsA.every((r: any) => r.tenantId === tenantA.id)).toBe(true);
expect(resultsAsA.some((r: any) => r.tenantId === tenantB.id)).toBe(false);
```
