<objective>
Wire better-auth as a session consumer in NestJS so the backend can validate sessions created by the Next.js auth provider.

Purpose: NestJS needs to validate better-auth session cookies on every authenticated API request. This plan creates the consumer instance and wires it into the NestJS module system. The existing auth guards (JwtAuthGuard, TenantGuard) remain untouched -- they get rewritten in Phase 52. This plan only adds the NEW better-auth consumer alongside.
Output: NestJS better-auth consumer instance that can call `auth.api.getSession()` to validate cookies.

  <action>
    1. Create `backend/src/common/auth/` directory if it does not exist.

    2. Create `backend/src/common/auth/better-auth.instance.ts`:
       ```typescript
       import { betterAuth } from "better-auth";
       import { prismaAdapter } from "better-auth/adapters/prisma";
       import type { PrismaClient } from "@prisma/client";

       export function createBetterAuthInstance(prisma: PrismaClient) {
         return betterAuth({
           database: prismaAdapter(prisma, { provider: "postgresql" }),
           secret: process.env.BETTER_AUTH_SECRET,
           // Mirror session config from Next.js instance exactly
           session: {
             expiresIn: 60 * 60 * 24 * 7,  // 7 days
             updateAge: 60 * 60 * 24,       // refresh daily
             cookieCache: {
               enabled: true,
               maxAge: 5 * 60,              // 5 min
               strategy: "compact",
             },
           },
           user: {
             additionalFields: {
               tenantId: { type: "string", required: false, input: false },
               firstName: { type: "string", required: false },
               lastName: { type: "string", required: false },
               role: { type: "string", required: false, defaultValue: "member" },
               isActive: { type: "boolean", required: false, defaultValue: true },
             },
           },
         });
       }
       ```

       CRITICAL: The session and user.additionalFields config MUST match the Next.js instance exactly. If they diverge, cookieCache validation will fail silently and every request will hit the DB.

       This instance does NOT enable emailAndPassword or hooks — it is read-only for session validation.

    3. Create `backend/src/common/auth/better-auth.module.ts`:
       - Create a NestJS module that:
         a. Provides the better-auth instance via DI (inject PrismaService, call createBetterAuthInstance)
         b. Exports a `BETTER_AUTH` injection token so guards/services can inject it
       - Use a factory provider:
         ```typescript
         {
           provide: 'BETTER_AUTH',
           useFactory: (prisma: PrismaService) => createBetterAuthInstance(prisma),
           inject: [PrismaService],
         }
         ```
       - Export `BETTER_AUTH` token from the module

    4. Wire into `backend/src/app.module.ts`:
       - Import `BetterAuthModule` alongside existing modules
       - Do NOT remove or modify AuthModule — old auth stays until Phase 52 rewrites guards
       - Do NOT set `bodyParser: false` in main.ts — the consumer only reads cookies/headers via `auth.api.getSession()`, no body parsing needed

    5. IMPORTANT: Do NOT use `@thallesp/nestjs-better-auth` AuthModule.forRoot() yet.
       The research flagged uncertainty about its bodyParser behavior (Open Question 4). Instead, create a minimal custom module that just provides the better-auth instance. Phase 52 will decide whether to use the community package or a custom guard.

    6. Add `BETTER_AUTH_SECRET` to `backend/.env.example` if it exists, with a comment explaining it must match the frontend value.
