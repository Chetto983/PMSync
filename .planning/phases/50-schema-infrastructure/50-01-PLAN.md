<task type="auto">
  <name>Task 1: Reshape Prisma schema + install packages + create HIBP utility</name>
  <files>backend/prisma/schema.prisma, frontend/package.json, backend/package.json, frontend/lib/hibp.ts, frontend/lib/__tests__/hibp.test.ts</files>
  <action>
    1. Install packages:
       - `cd frontend && npm install better-auth`
       - `cd backend && npm install better-auth @thallesp/nestjs-better-auth`

    2. Create `frontend/lib/hibp.ts` -- pure HIBP k-anonymity check function:
       - Import `crypto` from Node.js
       - SHA-1 hash the password, split into 5-char prefix + suffix
       - Fetch `https://api.pwnedpasswords.com/range/{prefix}` with `Add-Padding: true` header
       - AbortController timeout at 3000ms
       - Parse response lines, match suffix, return `{ breached: count > threshold, count }`
       - On any error (timeout, network, non-200), return `{ breached: false, count: 0 }` (fail-open, best-effort)
       - Export: `checkHIBP(password: string, threshold?: number, timeoutMs?: number): Promise<{ breached: boolean; count: number }>`
       - Default threshold = 3, default timeoutMs = 3000

    3. Create `frontend/lib/__tests__/hibp.test.ts` -- unit tests for checkHIBP with mocked fetch:
       - checkHIBP("password") with mocked fetch returning a matching hash suffix returns { breached: true, count: N } where N > threshold
       - checkHIBP("s3cur3-un1qu3-p@ss") with mocked fetch returning no matching suffix returns { breached: false, count: 0 }
       - checkHIBP with fetch timeout returns { breached: false, count: 0 } (fail-open)
       - checkHIBP with fetch error (network failure) returns { breached: false, count: 0 } (fail-open)

    4. Reshape `backend/prisma/schema.prisma`:

       **User model changes (line ~60):**
       - Add `name String` field (better-auth core; computed from firstName+lastName)
       - Add `emailVerified Boolean @default(false)` field (better-auth core)
       - Rename `avatarUrl` to `image` (better-auth core) -- or add `image String?` and keep `avatarUrl` as alias. Prefer adding `image` as the better-auth field.
       - Remove `passwordHash` field (password moves to Account table)
       - Remove `isMfaEnabled` field (better-auth 2FA plugin manages this in Phase 55)
       - Change `@@unique([tenantId, email])` to `@unique` on email alone (better-auth requires globally unique emails)
       - Make `tenantId` optional (`String?`) since better-auth creates users before tenant assignment
       - Add `sessions Session[]` relation (already exists)
       - Add `accounts Account[]` relation (new)
       - Keep ALL existing relations (actionQueue, auditLogs, etc.) -- do not remove any FK chains
       - Remove `refreshTokens RefreshToken[]` relation from User

       **Session model changes (line ~238):**
       - Remove `tenantId` field and its relation to Tenant
       - Add `updatedAt DateTime @updatedAt` field
       - Change `@@unique([tenantId, token])` to `@unique` on token alone
       - Remove `lastActivityAt` field (better-auth uses updatedAt)
       - Add `activeOrganizationId String?` (for future Phase 56 org plugin)
       - Remove `@@index([tenantId])` and `@@unique([tenantId, token])`
       - Keep `@@index([userId, token])` or replace with `@@index([userId])`

       **New Account model:**
       ```
       model Account {
         id                    String    @id @default(cuid())
         userId                String
         accountId             String
         providerId            String
         accessToken           String?
         refreshToken          String?
         accessTokenExpiresAt  DateTime?
         refreshTokenExpiresAt DateTime?
         scope                 String?
         idToken               String?
         password              String?
         createdAt             DateTime  @default(now())
         updatedAt             DateTime  @updatedAt
         user User @relation(fields: [userId], references: [id], onDelete: Cascade)
         @@map("accounts")
       }
       ```

       **New Verification model:**
       ```
       model Verification {
         id         String   @id @default(cuid())
         identifier String
         value      String
         expiresAt  DateTime
         createdAt  DateTime @default(now())
         updatedAt  DateTime @updatedAt
         @@map("verifications")
       }
       ```

       **Remove RefreshToken relation from Tenant model** -- remove the `refreshTokens RefreshToken[]` line from Tenant.
       **Remove Session relation from Tenant model** -- remove `sessions Session[]` from Tenant (Session no longer has tenantId).
       **Keep RefreshToken, MfaSecret, MfaBackupCode, TrustedDevice, WebAuthnCredential, PasswordResetToken models AS-IS for now** -- they get deleted in Phase 58 cleanup. Do NOT break existing code by removing them prematurely. Only remove the `refreshTokens` relation from User (since User no longer has that field mapping).

    5. Run `npx prisma validate` from `backend/` to confirm schema is valid.
    6. Run `npx prisma generate` from `backend/` to regenerate the client.

    IMPORTANT: Do NOT run `npx prisma db push` or migrations yet -- schema validation only. The actual DB migration happens when we test the full flow.

    Per research: accept better-auth's default scrypt hashing (Node.js native, no WASM issues on Railway). Do NOT configure custom hash/verify.

<task type="auto">
  <name>Task 2: Mount better-auth instance in Next.js Pages Router</name>
  <files>frontend/lib/auth.ts, frontend/pages/api/auth/[...all].ts, frontend/prisma/schema.prisma, frontend/package.json</files>
  <action>
    1. Create `frontend/lib/auth.ts` -- the better-auth server instance:
       ```typescript
       import { betterAuth } from "better-auth";
       import { prismaAdapter } from "better-auth/adapters/prisma";
       import { createAuthMiddleware, APIError } from "better-auth/api";
       import { PrismaClient } from "@prisma/client";
       import { checkHIBP } from "./hibp";
       ```

       Configuration (from research):
       - `database`: prismaAdapter with PrismaClient, provider "postgresql"
       - `baseURL`: `process.env.BETTER_AUTH_URL` (e.g. "http://localhost:3001")
       - `secret`: `process.env.BETTER_AUTH_SECRET` (new env var, 32+ char random string)
       - `emailAndPassword.enabled`: true (use better-auth default scrypt hashing)
       - `session.expiresIn`: 60 * 60 * 24 * 7 (7 days)
       - `session.updateAge`: 60 * 60 * 24 (refresh daily)
       - `session.cookieCache.enabled`: true
       - `session.cookieCache.maxAge`: 5 * 60 (5 min)
       - `session.cookieCache.strategy`: "compact"
       - `user.additionalFields`:
         - tenantId: { type: "string", required: false, input: false }
         - firstName: { type: "string", required: false }
         - lastName: { type: "string", required: false }
         - role: { type: "string", required: false, defaultValue: "member" }
         - isActive: { type: "boolean", required: false, defaultValue: true }
       - `hooks.before`: createAuthMiddleware that intercepts `/sign-up/email`:
         - Extract `ctx.body?.password`
         - Call `checkHIBP(password)`
         - If breached, throw `new APIError("BAD_REQUEST", { message: "This password has appeared in data breaches and cannot be used" })`

       Use a singleton PrismaClient pattern (avoid creating new clients per request in dev):
       ```typescript
       const globalForPrisma = globalThis as unknown as { prisma: PrismaClient };
       const prisma = globalForPrisma.prisma || new PrismaClient();
       if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;
       ```

       Export: `export const auth = betterAuth({ ... })`

    2. Create `frontend/pages/api/auth/[...all].ts` -- catch-all route:
       ```typescript
       import { toNodeHandler } from "better-auth/node";
       import { auth } from "@/lib/auth";

       export const config = { api: { bodyParser: false } };
       export default toNodeHandler(auth.handler);
       ```

       This gives Next.js full control over `/api/auth/*` routes.

    3. Copy backend schema to frontend for Prisma client generation:

       This ensures the frontend has its own `@prisma/client` generated from the same schema, without cross-package imports or symlink issues.
