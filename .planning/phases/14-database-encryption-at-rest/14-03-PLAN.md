Create `backend/src/scripts/backfill-encryption.ts` (~150 lines):

This is a standalone script runnable via `npx ts-node backend/src/scripts/backfill-encryption.ts`. It does NOT use NestJS — it uses `createPrismaClient()` from `prisma-client.factory.ts` directly.

**Main function: `backfillEncryptEmails()`**

1. Create a PrismaClient via `createPrismaClient()`.
2. Instantiate `TenantKeyService` (uses getConfiguration, no DI).
3. Get all tenant IDs: `await prisma.tenant.findMany({ select: { id: true } })`.
4. For each tenant:
   a. Derive encryption key via `tenantKeyService.getCurrentKey(tenantId)`.
   b. Count total emails for progress: `await prisma.email.count({ where: { tenantId } })`.
   c. Paginate with `skip` + `take` (batch size = 200). Composite @@id prevents cursor-based pagination.
   d. For each batch:
      - Filter records that have at least one plaintext field (use `isEncrypted()` to check).
      - Build update operations for each record that needs encryption.
      - Execute batch updates in a `prisma.$transaction([...updates])`.
      - Log progress: `[Email] Tenant ${tenantId}: ${processed}/${total} records`.
   e. Skip records where ALL target fields are already encrypted or null.

**Generic helper: `backfillEncryptModel()`**

Create a reusable function signature:
```typescript
async function backfillEncryptModel(
  prisma: PrismaClient,
  tenantKeyService: TenantKeyService,
  modelName: string,       // 'email' (Prisma model accessor name, lowercase)
  fields: string[],        // ['bodyText', 'bodyHtml', 'snippet']
  batchSize: number = 200,
): Promise<{ totalProcessed: number; totalEncrypted: number }>
```

This makes it extensible for future models (Contact, CalendarEvent) without rewriting.

**Composite PK update pattern:**
```typescript
prisma.email.update({
  where: { id_tenantId: { id: record.id, tenantId: record.tenantId } },
  data: { bodyText: encryptedBodyText, bodyHtml: encryptedBodyHtml, snippet: encryptedSnippet },
})
```

**CLI entry point:**
```typescript
if (require.main === module) {
  backfillEncryptEmails()
    .then((result) => {
      console.log(`Backfill complete: ${result.totalProcessed} records, ${result.totalEncrypted} encrypted`);
      process.exit(0);
    })
    .catch((err) => {
      console.error('Backfill failed:', err);
      process.exit(1);
    });
}
```

**Safety features:**
- Idempotent: already-encrypted values are skipped (checked via `isEncrypted()`).
- Atomic batches: each batch is a transaction — if one fails, that batch rolls back but prior batches persist.
- Progress logging: per-tenant, per-batch counts.
- Dry-run mode: add `--dry-run` CLI flag that logs what would be encrypted without actually writing.

Export `backfillEncryptModel` and `backfillEncryptEmails` for testing.
