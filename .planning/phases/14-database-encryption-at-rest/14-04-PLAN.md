  <action>
Create `backend/src/prisma/encryption/__tests__/encryption-integration.spec.ts` (~120 lines):

These tests verify the FULL pipeline by simulating the Prisma extension behavior with mock query functions. They do NOT require a running database.

**Test structure:** Create a test harness that simulates what Prisma does:
1. Build the extension via `createFieldEncryptionExtension(getKey, getKeys)`.
2. Simulate write: pass data through the extension's write handler, capture the encrypted args.
3. Simulate read: pass encrypted result through the extension's read handler, verify decrypted output.

**Integration tests (10 tests):**

Group 1: Round-trip verification (ENC-01)
1. "encrypts bodyText on create and decrypts on read" — write plaintext body, verify DB-bound data is enc: prefixed, verify read returns original plaintext.
2. "encrypts bodyHtml on update and decrypts on findFirst" — same for bodyHtml.
3. "encrypts snippet and decrypts correctly" — same for snippet.
4. "preserves non-encrypted fields unchanged" — from, subject, folder pass through unmodified.

Group 2: Tenant isolation (ENC-02)
5. "different tenants produce different ciphertext for same plaintext" — encrypt same bodyText for tenantA and tenantB, verify ciphertexts differ.
6. "tenant A's key cannot decrypt tenant B's data" — encrypt with tenantA key, attempt decrypt with tenantB key, verify failure.

Group 3: Key rotation (ENC-05)
7. "data encrypted with old master key decrypts via keychain" — encrypt with master key v1, configure keychain [v2, v1], verify decryption succeeds.
8. "new writes use current master key" — after rotation, verify new encryptions use the new key (not old).

Group 4: Migration coexistence (ENC-04 compatibility)
9. "plaintext values pass through on read without error" — simulate reading a record where bodyText is NOT enc: prefixed (pre-migration), verify it returns the plaintext unchanged.
10. "mixed encrypted and plaintext fields in same record" — bodyText encrypted, bodyHtml plaintext, verify both return correctly.

**Test key setup:**
```typescript
const MASTER_KEY_V1 = crypto.randomBytes(32);
const MASTER_KEY_V2 = crypto.randomBytes(32);
```

Each test should be self-contained — no shared mutable state between tests.
