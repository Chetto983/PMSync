## Objective

Implement OAuth token revocation when users disconnect email providers to prevent stale token access (SEC-02).

## Context

**Google:**
- Has official revocation endpoint: `POST https://oauth2.googleapis.com/revoke`
- Accepts refresh_token OR access_token in body
- Returns 200 on success, 400 if token already invalid (ignore this)
- Revoking refresh token also invalidates associated access tokens

**Microsoft:**
- NO official token revocation endpoint for OAuth apps
- Best-effort option: `POST /me/revokeSignInSessions` via Graph API
- Invalidates refresh tokens but access tokens remain valid for up to 1 hour
- Requires `User.RevokeSessions.All` permission (may not be granted)

**Implementation Approach:**
- Add `revokeToken()` to GoogleOAuthService (reliable)
- Add `revokeSession()` to MicrosoftOAuthService (best-effort, warn on failure)
- Call from `ProviderConfigService.deleteProviderConfig()` BEFORE database delete
- Never fail the disconnect if revocation fails - log warning and continue

**Action:**

/**
 * Revoke a Google OAuth token (SEC-02)
 * Revoking refresh token also invalidates associated access tokens.
 * @param token - Refresh token or access token to revoke
 */
async revokeToken(token: string): Promise<void> {
  try {
    const response = await fetch('https://oauth2.googleapis.com/revoke', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/x-www-form-urlencoded',
      },
      body: `token=${encodeURIComponent(token)}`,
    });

    if (response.ok) {
      this.logger.log('Google OAuth token revoked successfully');
    } else if (response.status === 400) {
      // 400 = token already invalid/expired - not an error for us
      this.logger.debug('Google token already invalid (ignoring 400)');
    } else {
      this.logger.warn(
        `Google token revocation returned ${response.status}: ${await response.text()}`,
      );
    }
  } catch (error) {
    // Best effort - don't fail disconnect if revocation fails
    this.logger.warn(
      `Google token revocation failed: ${error instanceof Error ? error.message : String(error)}`,
    );
  }
}
```

/**
 * Revoke Microsoft sign-in sessions (SEC-02 - best effort)
 * Note: Microsoft does NOT have a true token revocation API.
 * This invalidates refresh tokens but access tokens remain valid up to 1 hour.
 * @param accessToken - Valid access token to call Graph API
 */
async revokeSession(accessToken: string): Promise<void> {
  try {
    const response = await fetch(
      'https://graph.microsoft.com/v1.0/me/revokeSignInSessions',
      {
        method: 'POST',
        headers: {
          Authorization: `Bearer ${accessToken}`,
          'Content-Type': 'application/json',
        },
      },
    );

    if (response.ok) {
      this.logger.log('Microsoft sign-in sessions revoked');
    } else if (response.status === 403) {
      // Permission not granted - expected for many OAuth apps
      this.logger.debug(
        'Microsoft session revocation not permitted (missing User.RevokeSessions.All)',
      );
    } else {
      this.logger.warn(
        `Microsoft session revocation returned ${response.status}: ${await response.text()}`,
      );
    }
  } catch (error) {
    // Best effort - don't fail disconnect
    this.logger.warn(
      `Microsoft session revocation failed: ${error instanceof Error ? error.message : String(error)}`,
    );
  }
}
```

### Task 3: Wire Revocation into Provider Disconnect Flow

**Files:** `backend/src/modules/providers/services/provider-config.service.ts`

**Action:**

1. Find the method that deletes a provider (likely `deleteProviderConfig` or similar).

2. Add revocation call BEFORE the Prisma delete. The pattern should be:

```typescript
async deleteProviderConfig(tenantId: string, providerId: string): Promise<void> {
  const provider = await this.prisma.providerConfig.findUnique({
    where: { id: providerId, tenantId },
  });

  if (!provider) {
    throw new NotFoundException('Provider not found');
  }

  // SEC-02: Revoke OAuth tokens before deleting
  await this.revokeProviderTokens(provider);

  // ... existing cleanup code (webhooks, sync jobs, etc.) ...

  // Delete from database
  await this.prisma.providerConfig.delete({
    where: { id: providerId, tenantId },
  });
}

/**
 * Revoke OAuth tokens for a provider (SEC-02)
 * Best-effort: failures are logged but do not block deletion
 */
private async revokeProviderTokens(provider: ProviderConfig): Promise<void> {
  try {
    if (provider.type === 'google' && provider.refreshToken) {
      const refreshToken = this.crypto.decrypt(
        provider.refreshToken,
        provider.refreshTokenEncryptionIv!,
      );
      await this.googleOAuth.revokeToken(refreshToken);
    } else if (provider.type === 'microsoft' && provider.accessToken) {
      // Microsoft needs valid access token for session revocation
      const accessToken = this.crypto.decrypt(
        provider.accessToken,
        provider.tokenEncryptionIv!,
      );
      await this.microsoftOAuth.revokeSession(accessToken);
    }
    // IMAP/generic providers: no OAuth revocation needed
  } catch (error) {
    // Never fail disconnect due to revocation failure
    this.logger.warn(
      `Token revocation failed for provider ${provider.id}: ${error instanceof Error ? error.message : String(error)}`,
    );
  }
}
```

**Note:** The exact field names for encrypted tokens may vary. Check the ProviderConfig model in schema.prisma and adjust accordingly.
