## Objective

Harden logging to prevent credential leakage (SEC-03) and enable S3 server-side encryption for attachments at rest (SEC-01).

## Context

**SEC-03 (Log Redaction):**
- `logger.config.ts` already has Pino `redact` configured (lines 109-124)
- Current paths: `authorization`, `cookie`, `password`, `token`, `secret`, `accessToken`, `refreshToken`
- Missing: `apiKey`, `api_key`, `cvv`, `ssn`, `creditCard`, body fields
- Research recommends extending with OWASP-compliant patterns

**SEC-01 (S3 Encryption):**
- `storage.service.ts` uses `@aws-sdk/client-s3` PutObjectCommand
- Currently NO encryption header specified (line 53-58)
- Fix: Add `ServerSideEncryption: 'AES256'` to all putObject calls
- Note: Since Jan 2023, S3 encrypts by default with SSE-S3, but explicit is safer

### Task 2: Add S3 Server-Side Encryption (SEC-01)

**Files:** `backend/src/modules/email/services/storage.service.ts`

**Action:**

1. Modify `putObject()` method (lines 52-59) to include SSE header:

```typescript
async putObject(key: string, body: Buffer, contentType: string): Promise<void> {
  const command = new PutObjectCommand({
    Bucket: this.bucket,
    Key: key,
    Body: body,
    ContentType: contentType,
    ServerSideEncryption: 'AES256', // SEC-01: SSE-S3 encryption at rest
  });
  await this.client.send(command);
}
```

2. Add verification method to confirm encryption on uploaded objects:

```typescript
/**
 * Verify that an object was stored with server-side encryption (SEC-01 audit)
 */
async verifyEncryption(key: string): Promise<boolean> {
  try {
    const response = await this.client.send(
      new HeadObjectCommand({
        Bucket: this.bucket,
        Key: key,
      }),
    );
    const encrypted = response.ServerSideEncryption === 'AES256';
    if (!encrypted) {
      this.logger.warn(`S3 object ${key} is NOT encrypted`);
    }
    return encrypted;
  } catch (err) {
    this.logger.error(`Failed to verify encryption for ${key}: ${err}`);
    return false;
  }
}
```
