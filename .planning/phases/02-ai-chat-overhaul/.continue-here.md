## 2. Tool Parts Persistence Fix (2026-02-07)

**ROOT CAUSE IDENTIFIED**: Tools showed in live streaming but disappeared when loading history because:
- Backend `ConversationManagementService.getConversationWithMessages()` was stripping tool parts
- It only returned `content: string` (extracted text), not the full `parts` array
- Frontend wrapped this single text string into `[{ type: 'text', text: content }]`

**FIX APPLIED** - 4 files modified:

### Backend: `conversation-management.service.ts`
1. Added `MessagePart` interface:
```typescript
export interface MessagePart {
  type: string;
  text?: string;
  toolName?: string;
  toolCallId?: string;
  state?: string;
  input?: unknown;
  output?: unknown;
  errorText?: string;
}
```

2. Updated `ConversationMessageDetail` to include `parts`:
```typescript
export interface ConversationMessageDetail {
  role: 'user' | 'assistant' | 'system';
  content: string;  // @deprecated - kept for backwards compat
  parts: MessagePart[];  // NEW: AI SDK v6 parts array
  createdAt: Date;
}
```

3. Updated mapping in `getConversationWithMessages()` to preserve all parts (text and tool parts)

### Frontend: `lib/api/ai.ts`
Added `MessagePart` type and `parts?: MessagePart[]` to `ConversationMessage` type.

### Frontend: `AiDashboard/index.tsx`
1. Import `UIMessage` type for casting
2. Updated `loadConversation()` to use parts from API:
```typescript
parts: m.parts && m.parts.length > 0
  ? m.parts as unknown as UIMessage['parts']
  : [{ type: 'text' as const, text: m.content }],
```
