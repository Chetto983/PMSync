## Component Inventory

### 1. NotificationSettings (settings page section)

**Location:** `frontend/components/settings/NotificationSettings.tsx`
**Parent:** `Settings.tsx` renders it when `selectedSection === 'notifications'` (new section entry).
**Pattern:** Matches existing settings sections (GeneralSettings, AiSettings, etc.).

**Layout:**
- Section heading: `<Typography variant="h6">` with `Bell` lucide icon (18px) + 8px gap
- Description paragraph: `<Typography variant="body1" color="text.secondary">`
- Switch row: `<Box>` with `<Switch>` + label, vertically centered, 16px vertical padding between rows
- Help text: `<Typography variant="body2" color="text.secondary">` below switch when needed

**States:**
| State | What renders |
|-------|-------------|
| `isSupported === false` | Section hidden entirely (PUSH-04). No placeholder, no message. |
| `permission === 'default'` | Switch OFF + description explaining what push notifications do |
| `permission === 'granted' && !isSubscribed` | Switch OFF + description. Toggling ON subscribes. |
| `permission === 'granted' && isSubscribed` | Switch ON. Toggling OFF unsubscribes + calls backend DELETE. |
| `permission === 'denied'` | Switch disabled + warning Alert: "Notifications blocked. Open browser settings to re-enable." |
| Subscribe loading | Switch disabled + `CircularProgress` (size 20) inline replacing switch temporarily |
| Subscribe error | `Alert severity="error"` below switch row with error message |

**Interaction:**
- Toggle ON: calls `Notification.requestPermission()` (if `'default'`), then `PushManager.subscribe()`, then `POST /api/push/subscribe`.
- Toggle OFF: calls `PushSubscription.unsubscribe()`, then `DELETE /api/push/subscribe`.
- No optimistic update. Wait for async chain to complete before updating switch state.

### 2. UpdateSnackbar (SW update notification)

**Location:** `frontend/components/layout/UpdateSnackbar.tsx`
**Parent:** `Layout.tsx`, placed after `<InstallPromptBanner />` and before `<CookieConsent />`.
**Pattern:** Matches `InstallPromptBanner.tsx` -- uses MUI `<Snackbar>` + `<Alert>`.

**Layout:**
- `<Snackbar open={updateAvailable} anchorOrigin={{ vertical: 'bottom', horizontal: 'center' }}>`
- `<Alert severity="info" icon={<RefreshCw size={20} />}>`
- Message text + "Reload page" `<Button size="small" color="inherit">`
- No dismiss/close button. Snackbar persists until user taps Reload page or the page is closed.

**States:**
| State | What renders |
|-------|-------------|
| No waiting SW | Nothing rendered |
| Waiting SW detected | Snackbar visible with message + Reload page button |
| After Reload page clicked | `postMessage({ type: 'SKIP_WAITING' })` then `window.location.reload()` on `controllerchange` |

**Interaction:**
- "Reload page" button: posts `SKIP_WAITING` to waiting SW, listens for `controllerchange`, then reloads page.
- No auto-dismiss. No timeout. User must act or ignore.

### 3. Settings Sidebar Addition

**Location:** Existing `frontend/components/dashboard/settings/SettingsSidebar.tsx`
**Change:** Add `{ id: 'notifications', label: t.settings?.sections?.notifications || 'Notifications', icon: <Bell size={18} /> }` entry.
**Position:** After "general" section, before "security".

## Interaction Contracts

### Push Subscription Flow (PUSH-01)

```
User opens Settings > Notifications
  IF push not supported -> section hidden
  IF permission === 'denied' -> show blocked warning, switch disabled
  IF permission === 'default' || 'granted':
    User toggles switch ON ->
      switch disabled + loading spinner ->
      requestPermission() (if 'default') ->
        IF denied -> show blocked warning, switch stays OFF
        IF granted -> PushManager.subscribe(vapidKey) ->
          POST /api/push/subscribe ->
            IF success -> switch ON, spinner removed
            IF error -> show error Alert, switch stays OFF, spinner removed
    User toggles switch OFF ->
      switch disabled + loading spinner ->
      PushSubscription.unsubscribe() ->
      DELETE /api/push/subscribe ->
        IF success -> switch OFF, spinner removed
        IF error -> show error Alert, switch stays ON, spinner removed
```

### SW Update Flow (PLSH-01)

```
App loads -> useSwUpdate hook registers for SW events
  IF navigator.serviceWorker.controller exists:
    Listen for 'controllerchange' event
  On registration:
    IF reg.waiting exists -> set updateAvailable = true
    Listen for 'updatefound' on reg ->
      Listen for 'statechange' on reg.installing ->
        IF state === 'installed' && navigator.serviceWorker.controller ->
          set updateAvailable = true
  User clicks "Reload page" ->
    waitingSw.postMessage({ type: 'SKIP_WAITING' })
    navigator.serviceWorker.addEventListener('controllerchange', () => window.location.reload())
```

### Push Notification Display (PUSH-02)

```
SW receives 'push' event ->
  Parse event.data.json() -> { title, body, icon?, url?, tag? }
  self.registration.showNotification(title, {
    body, icon: icon || '/icons/icon-192x192.png',
    badge: '/icons/icon-192x192.png',
    tag, data: { url: url || '/' }
  })
```

### Notification Click (PUSH-03)

```
SW receives 'notificationclick' event ->
  event.notification.close()
  url = event.notification.data?.url || '/'
  Find existing WindowClient with matching origin ->
    IF found -> client.focus() + client.navigate(url)
    IF not found -> clients.openWindow(url)
```
