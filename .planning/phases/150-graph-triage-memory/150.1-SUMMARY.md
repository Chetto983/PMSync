## Findings Addressed

### WR-01 — Graph short-circuit skips EmailLabel junction write (FIXED)

**Before:** `EmailTriageService.triageEmail` graph short-circuit wrote `Email.aiLabels + EmailAnalysis.upsert` but never called `linkEmailToUserLabels`. Every graph-short-circuited email was invisible to `LabelsService.getEmailsForLabel` (which filters on `emailLabels.some`). Hidden at cutoff=9999 (kill-switched default), live at any lower cutoff.

**Fix:** Injected `InsightUtilsService` into `EmailTriageService` (mandatory, not `@Optional` — the service is a provider on `AiModule`, always available). After the `Email.updateMany` + `EmailAnalysis.upsert` + before returning, added:

```typescript
await this.insightUtils.linkEmailToUserLabels(
  tenantId,
  emailId,
  [g.predictedLabelName],
);
```

Parity with `email-analysis.service.ts:268` (the LLM path). Callee resolves label NAMES → UserLabel.id internally via `userLabel.findFirst(insensitive OR)` — no signature change required.

**Spec updates in `email-triage.service.spec.ts`:**
1. Assertion in the existing `short-circuits LLM when graph confidence >= cutoff` test: `expect(insightUtilsMock.linkEmailToUserLabels).toHaveBeenCalledWith('t1', 'e1', ['Work'])`.
2. New negative-case test `does NOT call linkEmailToUserLabels when graph lookup returns no edge` — asserts `.not.toHaveBeenCalled()` so the LLM path's own junction write isn't double-fired.

### WR-03 — Labels mirror writes outside $transaction (FIXED)

**Before:** `LabelsService.{create, delete, bulkDelete}` issued `userLabel.*` writes first, then `graphNode.create|deleteMany` in separate transaction boundaries. A process crash between the two:
- **create:** label exists without mirror (self-heals via promotion's find-or-create, so not catastrophic).
- **delete:** label soft-deleted, mirror + affinity edges survive — graph-lookup returns "Learned pattern" for a deleted label. **No self-heal.** Decay-gc prunes by confidence, not by orphan-detection.
- **bulkDelete:** same failure mode as delete, scaled across N labels.

**Fix:** Wrapped all 3 methods in `prisma.$transaction`. Refactored `upsertLabelNode` + `archiveDescendants` to accept optional `tx: Prisma.TransactionClient` so the SELECT FOR UPDATE + graphNode writes run on the same connection as the outer UserLabel updates. Option B serialization preserved. `bulkDelete` uses `{ timeout: 10_000 }` as the second `$transaction` arg (default 5s insufficient for large descendant trees).

**Specs:**
- New: `backend/src/modules/labels/services/__tests__/labels.service.wr03-atomicity.unit.spec.ts` — 4 it-blocks covering `delete` all-writes-through-tx, `delete` rollback on mirror throw, `create` tx wrapping, `bulkDelete` tx wrapping with 10s timeout assertion. All 4/4 GREEN.
- Updated: `labels.service.cache-invalidation.unit.spec.ts` — 2 tests needed `$transaction` passthrough added to their prisma mocks (create + delete paths).
- Updated: `labels.service.triage.unit.spec.ts` — 1 test (`creates a nested wizard label`) needed `$transaction` passthrough for the `upsertLabelNode` call inside `createFromWizard`.

**Deferred-items note:** The `updates a wizard label` case in the same spec OOMs under `--runInBand` with `max-old-space-size=4096`. Verified via `git stash` to be a PRE-existing issue — NOT introduced by WR-03. Logged to `deferred-items.md`.

// Phase 147 D-12: step function — 1 if <=30d else 0. NOT exponential decay.

### IN-03 — Redundant `as any` cascades on edge.metadata (FIXED)

**Before:** 3 read sites in `triage-decay-gc.helpers.ts` used `(((e as any).metadata as any)?.derivedFromOverrideIds ?? []) as string[]`. Defensive-semantics comment at `:294-296` promised empty-array on corrupt JSON, but the implementation would throw on non-object metadata shapes (e.g., bare string).

**Fix:** New exported helper at top of file:
```typescript
export function readOverrideIds(
  metadata: Prisma.JsonValue | null | undefined,
): string[] {
  if (!metadata || typeof metadata !== 'object' || Array.isArray(metadata)) return [];
  const ids = (metadata as Record<string, unknown>).derivedFromOverrideIds;
  return Array.isArray(ids) ? ids.filter((x): x is string => typeof x === 'string') : [];
}
```

All 3 sites replaced. Override-map + feedbackRows + emails loops also shed their `as any[]` casts by relying on Prisma's generated types. Grep count: `grep -cE 'as any' triage-decay-gc.helpers.ts` = 1 (a single reference inside the JSDoc of the new helper, NOT a live cast).
