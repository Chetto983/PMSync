  <name>Task 2: Implement dynamic import for ComposeEditor (TipTap) within ComposeDialog</name>

  <action>
**ARCHITECTURE NOTE:** ComposeDialog is used in `/pages/dashboard/email/compose.tsx` - a dedicated page.
Next.js already lazy-loads pages by default. The optimization target is ComposeEditor which contains
TipTap (heavy library). We dynamically import ComposeEditor WITHIN ComposeDialog.

1. Open `frontend/components/email/compose/ComposeDialog.tsx`

2. Find the static import of ComposeEditor (line ~44):
```typescript
import ComposeEditor from './ComposeEditor';
```

3. Replace with dynamic import:
```typescript
import dynamic from 'next/dynamic';
import { Box, Skeleton } from '@mui/material';

// Lazy load ComposeEditor - contains heavy TipTap dependencies
const ComposeEditor = dynamic(
  () => import('./ComposeEditor'),
  {
    loading: () => (
      <Box sx={{ p: 2, minHeight: 300 }}>
        <Skeleton variant="rectangular" height={40} sx={{ mb: 1 }} />
        <Skeleton variant="rectangular" height={200} />
      </Box>
    ),
    ssr: false, // TipTap uses browser APIs (window, document)
  }
);
```

4. Remove the static import line for ComposeEditor

5. Verify the change compiles: `npm run type-check`

**WHY THIS WORKS:**
- ComposeDialog renders on the compose page
- ComposeEditor (with TipTap) only loads when dialog content renders
- Users navigating the email list don't download TipTap until they compose
- Next.js creates a separate chunk for ComposeEditor + TipTap dependencies
  </action>

- `npm run type-check` passes
- ComposeEditor import uses `dynamic()` with ssr: false
- Skeleton appears briefly when ComposeDialog first opens
  </verify>
  <done>ComposeEditor (TipTap) loads only when compose dialog renders, not on initial page load</done>
</task>
