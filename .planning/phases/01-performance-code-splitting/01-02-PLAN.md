<task type="auto">
  <name>Task 2: Add Lighthouse CI to GitHub Actions workflow</name>
  <files>.github/workflows/frontend-ci.yml</files>
  <action>
1. Read current frontend-ci.yml workflow

2. Add a SEPARATE `lighthouse` job after the existing build/test jobs. This approach is cleaner
   than inline steps and allows parallel execution with other checks.

3. Add this job to the workflow file:

```yaml
  lighthouse:
    name: Lighthouse CI
    runs-on: ubuntu-latest
    needs: [build]  # Run after build job completes
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json

      - name: Install dependencies
        run: npm ci
        working-directory: frontend

      - name: Build for Lighthouse
        run: npm run build
        working-directory: frontend

      - name: Run Lighthouse CI
        run: npx @lhci/cli autorun
        working-directory: frontend
        continue-on-error: true  # Don't block PRs initially until budgets verified
```

4. The `npx @lhci/cli autorun` command reads configuration from `frontend/lighthouserc.js`
   which was configured in Task 1.

5. `continue-on-error: true` is set initially so CI doesn't fail until we verify budgets
   are achievable. Remove this flag once performance targets are confirmed met.

**WHY SEPARATE JOB:**
- Clearer separation of concerns (build/test vs performance)
- Can run in parallel with other jobs
- Easier to make optional or required independently
- Cleaner logs and failure diagnosis
  </action>
  <verify>
- frontend-ci.yml contains `lighthouse` job
- Job depends on build job (`needs: [build]`)
- Uses `npx @lhci/cli autorun` which reads lighthouserc.js
- working-directory set to `frontend`
  </verify>
  <done>Lighthouse CI integrated as separate GitHub Actions job, runs on every PR</done>
</task>
