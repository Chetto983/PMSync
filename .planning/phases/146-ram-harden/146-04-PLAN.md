**calendar-sync-queue.service.ts:**

1. Update imports: Add `getSharedRedisConnection`, `releaseSharedRedisConnection` from queue config. Keep `getRedisConnectionOptions` import (needed for QueueEvents). Remove `import { Redis } from 'ioredis'` if Redis is no longer instantiated directly (keep if used as type).

2. In init (around lines 91-92): Replace:
```typescript
const redisOptions = getRedisConnectionOptions();
this.redisConnection = new Redis(redisOptions);
```
With:
```typescript
this.redisConnection = getSharedRedisConnection();
```

3. Queue constructors (around lines 102-117): Keep `connection: this.redisConnection` as-is. The three queues (highQueue, normalQueue, lowQueue) all share the connection -- correct behavior.

4. **CRITICAL -- QueueEvents (around lines 133-134):** Currently uses `connection: this.redisConnection`. This MUST change to connection OPTIONS to prevent blocking XREAD conflict:

BEFORE:
```typescript
const queueEvents = new QueueEvents(queue.name, {
  connection: this.redisConnection,
});
```

AFTER:
```typescript
const queueEvents = new QueueEvents(queue.name, {
  connection: getRedisConnectionOptions(),
});
```

This tells BullMQ to create a dedicated connection for QueueEvents, using the same options but a separate TCP connection. QueueEvents owns this connection and will close it when `queueEvents.close()` is called.

5. In onModuleDestroy (around lines 185-209): The existing cleanup code closes QueueEvents first, then queues. Keep that order. Replace the final `.quit()` on Redis:

BEFORE:
```typescript
// ... after closing queueEvents and queues ...
if (this.redisConnection && this.redisConnection.status !== 'end') {
  await this.redisConnection.quit();
}
```

AFTER:
```typescript
// ... after closing queueEvents and queues ...
releaseSharedRedisConnection();
```
