# Phase 149.1 - Email Triage Debug Runbook

## Purpose

This runbook defines the narrowest reliable workflow for reproducing and debugging triage incoherence without mutating production.

Use this before opening a fix phase.

## Environment notes

### Working assumptions

- run from `d:\MailAgent\backend`
- use local code inspection and targeted tests only
- expect test setup to run migrations, seed data, and OpenAPI generation before each narrow Jest invocation

### Important shell note

In the current Windows/PowerShell environment, the `npm test -- ...` wrapper was not reliable for narrow runs because `dotenv-cli` was not recognized. Use the direct Node + Jest entrypoint below as the default.

## Debug checkpoints

Before proposing fixes, answer these explicitly:

1. Where is passive-notification suppression supposed to be authoritative: prompt, score layer, action layer, or a shared helper?
2. Do both `EmailFollowUp` writers still have non-overlapping domains?
3. Is dashboard dedup still the only protection against double-counted follow-up work?
4. Are planning/docs still describing the current architecture truthfully?
5. Is the narrow-test command stable for other engineers on Windows shells?

## Do not do in this phase

- do not mutate production
- do not run broad full-suite verification first
- do not change schemas as part of debugging
- do not assume a docs claim is true without checking code
