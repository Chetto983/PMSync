Extend `scripts/lib/validate-syncback.mjs` to add SYNC-12 and SYNC-13 validation test cases.

**SYNC-12: Delete (soft + permanent)**

For each provider (Gmail, Outlook, IMAP):

1. **Soft delete test:**
   - Find a test email NOT in TRASH via `GET /api/v1/emails?providerId={pid}&folder=INBOX&limit=1`
   - Record the email ID and current folder
   - Call `DELETE /api/v1/emails/{id}` (uses `apiDelete`)
   - Call `GET /api/v1/emails/{id}` — assert `folder` is now `TRASH` (or email is soft-deleted)
   - NOTE: Do NOT restore from trash — we need the email in trash for the hard delete test

2. **Hard delete test (CAREFUL — destructive, use --quick to skip):**
   - If `options.quick` is true, SKIP this test and report as "SKIPPED (--quick mode)"
   - If not quick: the email from step 1 is now in TRASH
   - Call `DELETE /api/v1/emails/{id}` again (second delete = permanent)
   - Call `GET /api/v1/emails/{id}` — expect 404 or empty response (email permanently deleted)
   - Report: "SYNC-12: soft+hard delete on {providerType}"

3. **If not doing hard delete (quick mode):**
   - Move the trashed email back to INBOX via `PATCH /api/v1/emails/{id}` with `{ folder: 'INBOX' }` to restore state
   - Report: "SYNC-12: soft delete on {providerType} (hard delete skipped)"

**SYNC-13: Label add/remove (Gmail only)**

1. Skip if provider is not Google (IMAP and Microsoft don't support label sync-back)
2. `GET /api/v1/labels` — find at least one UserLabel, or create one if none exist
3. Pick a Gmail email via `GET /api/v1/emails?providerId={gmailProviderId}&limit=1`
4. `PATCH /api/v1/emails/bulk/labels/add` with `{ emailIds: [emailId], labelIds: [labelId] }`
5. `GET /api/v1/emails/{id}` — assert the email now has the label in its `emailLabels` or label associations
6. `PATCH /api/v1/emails/bulk/labels/remove` with `{ emailIds: [emailId], labelIds: [labelId] }`
7. `GET /api/v1/emails/{id}` — assert label removed
8. Report: "SYNC-13: label add/remove roundtrip on Gmail"

**Important implementation notes:**
- Use `apiDelete` from validation-helpers.mjs for DELETE calls
- Use `apiPatch` for PATCH calls
- Wrap each test in try/catch — report failures without crashing the whole suite
- For SYNC-12, always use a SEPARATE email from SYNC-09/10/11 tests (don't delete the email used for read/star/move tests)
- Add the new test functions to the existing `validateSyncBack` export — call them after the existing SYNC-09/10/11 tests
