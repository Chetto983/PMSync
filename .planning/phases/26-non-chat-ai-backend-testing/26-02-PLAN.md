Methods:

`async getRelationshipScores(tenantId: string, options?: { limit?: number; minScore?: number })`:
1. Query contacts with email interaction data via Prisma raw query or aggregation
2. For each contact, compute weighted score:
   - Recency (40%): `100 * exp(-daysSinceLast / 30)` -- exponential decay
   - Frequency (30%): `min(100, interactions_90d * 5)` -- normalized count
   - Reciprocity (20%): `100 * (1 - abs(sent - received) / total)` -- balance ratio
   - Trend (10%): Compare last 30d vs prior 30d interaction counts
3. Total = `round(recency * 0.4 + frequency * 0.3 + reciprocity * 0.2 + trend * 0.1)`
4. Return sorted by totalScore descending

To compute interactions, query emails:
```typescript
const interactions = await this.prisma.email.findMany({
  where: { tenantId, OR: [{ from: { contains: contactEmail } }, { to: { has: contactEmail } }], receivedAt: { gte: 90daysAgo } },
  select: { id: true, from: true, to: true, receivedAt: true },
  orderBy: { receivedAt: 'desc' },
});
```

`async getStaleContacts(tenantId: string, options?: { daysSince?: number; limit?: number })`:
1. Default daysSince = 30, limit = 10
2. Query contacts not interacted in daysSince+ days
3. Determine previous interaction frequency from email history
4. Suggest action based on relationship strength
5. Return sorted by daysSinceContact descending

**CalendarConflictService** (calendar-conflict.service.ts, ~100 lines):

```typescript
export interface CalendarConflict {
  eventA: { id: string; title: string; startTime: Date; endTime: Date };
  eventB: { id: string; title: string; startTime: Date; endTime: Date };
  overlapMinutes: number;
  severity: 'hard' | 'soft';  // hard = full overlap, soft = partial
}
```

`async detectConflicts(tenantId: string, options?: { startDate?: Date; endDate?: Date })`:
1. Default: next 7 days
2. Query all events in range via Prisma
3. Sort by startTime, then check pairwise for overlaps: `eventA.endTime > eventB.startTime && eventA.startTime < eventB.endTime`
4. Calculate overlap duration in minutes
5. Classify: hard (one event fully within another) vs soft (partial overlap)
6. Return sorted by overlapMinutes descending

`async prepareMeeting(tenantId: string, eventId: string)`:
1. Load the calendar event: `prisma.calendarEvent.findFirst({ where: { id: eventId, tenantId } })`
2. Parse attendees from JSON field
3. For each attendee email:
   a. Look up contact: `prisma.contact.findFirst({ where: { tenantId, emails: { has: email } } })`
   b. Load recent emails (last 30 days): `prisma.email.findMany({ where: { tenantId, OR: [{ from: { contains: email } }, { to: { has: email } }], receivedAt: { gte: 30daysAgo } }, take: 5, select: { id, subject, receivedAt, snippet } })`
   c. Get relationship score from contact record
4. Build data-driven agenda suggestions from email subjects (no LLM needed -- extract keywords/topics from recent email subjects)
5. Return meeting prep object

NOTE: If meeting prep needs LLM summarization (per research open question #3), this service stays pure-data and the AI module's BriefingService can consume it for LLM-enhanced prep.
