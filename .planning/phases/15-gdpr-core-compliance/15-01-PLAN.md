  <action>
1. Create `dto/consent.dto.ts`:
   - `UpdateConsentDto`: `feature` (string, @IsString), `granted` (boolean, @IsBoolean). Validate with class-validator.
   - `ConsentStateDto`: `feature`, `label`, `description`, `granted`, `lastUpdated` (Date | null), `version` (number | null), `required` (boolean).
   - `ConsentHistoryDto`: `id`, `feature`, `granted`, `version`, `createdAt`, `ipAddress`.

2. Create `services/consent.service.ts` (ConsentService):
   - Constructor injects `PrismaService`.
   - `getCurrentConsents(userId, tenantId)`: Returns `ConsentStateDto[]` by querying `userConsent.findMany` with `orderBy: createdAt desc`, `distinct: ['feature']`, then mapping against `CONSENT_FEATURES`.
   - `updateConsent(userId, tenantId, feature, granted, ipAddress?, userAgent?)`: Creates immutable `userConsent` record with `CURRENT_CONSENT_VERSION`, then calls `syncToPreferences()`.
   - `getConsentHistory(userId, tenantId, feature?)`: Returns last 50 consent records, optionally filtered by feature.
   - Private `syncToPreferences(userId, feature, granted)`: Uses `FEATURE_TO_PREF_MAP` to update the matching `UserPreferences` column. If feature has no mapping (e.g., `email_analytics`), skip silently.

3. Create `services/consent-enforcement.service.ts` (ConsentEnforcementService):
   - Constructor injects `PrismaService`.
   - `hasConsent(userId, tenantId, feature)`: Returns boolean. Queries `userConsent.findFirst` where `userId, tenantId, feature`, `orderBy: createdAt desc`. Returns `record?.granted ?? false`.

4. Create `guards/consent.guard.ts` (ConsentGuard):
   - Follow `FeatureFlagGuard` pattern exactly. Use `Reflector` to read `REQUIRED_CONSENT` metadata key.
   - If no `REQUIRED_CONSENT` on handler, return `true`.
   - Extract `userId` and `tenantId` from `request.user` (using `AuthenticatedRequest` type).
   - Call `consentEnforcementService.hasConsent()`. Return result.
   - If consent missing, throw `ForbiddenException` with message `'Consent required for feature: {feature}'`.

5. Create `decorators/requires-consent.decorator.ts`:
   - `export const REQUIRED_CONSENT = 'requiredConsent';`
   - `export const RequiresConsent = (feature: string) => SetMetadata(REQUIRED_CONSENT, feature);`
   - Follows exact pattern from `feature-flag.decorator.ts`.

6. Create `controllers/consent.controller.ts` (ConsentController):
   - Route prefix: `compliance/consent`
   - Uses `JwtAuthGuard`, `TenantGuard` (same as GdprController).
   - `GET /` -> `getCurrentConsents()`: Returns current consent state for authenticated user.
   - `POST /` -> `updateConsent()`: Accepts `UpdateConsentDto` body. Extracts `ipAddress` from `req.ip`, `userAgent` from `req.headers['user-agent']`. Returns updated consent record.
   - `GET /history` -> `getConsentHistory()`: Optional `?feature=` query param. Returns consent history records.
   - Swagger decorations: `@ApiTags('Compliance')`, `@ApiBearerAuth()`.

7. Update `compliance.module.ts`:
   - Add `ConsentService`, `ConsentEnforcementService` to providers.
   - Add `ConsentController` to controllers.
   - Export `ConsentService`, `ConsentEnforcementService`, `ConsentGuard`.
   - Keep existing `GdprService`, `GdprController`, `forwardRef(() => AiModule)`.
