## Deviations from Plan

### Rule 1 (bug auto-fixed) — jest/ts-jest mock hoisting rule

Plan's test code used bare mock-variable names (`toggleStreamMock`, `completeMutate`, `dismissMock`, `toastInfo`, `filterSpy`, etc.). ts-jest enforces babel-plugin-jest-hoist semantics: out-of-scope references inside `jest.mock(...)` factories MUST start with `mock` (case-insensitive). Copying the plan code verbatim would throw `ReferenceError` at file load.

Renamed across the 3 store-heavy tests:
- `toggleStreamMock` -> `mockToggleStream`, `isToggledReturn` -> `mockIsToggledReturn`
- `completeMutate` -> `mockCompleteMutateAsync`, `dismissMock` -> `mockDismiss`, `restoreMock` -> `mockRestore`, `toastInfo` -> `mockToastInfo`, etc.
- `dismissedIds` -> `mockDismissedIdsSet`, `filterSpy` -> `mockFilterSpy`

Zero behavioural change; purely a hoisting-compliance rename.

### Rule 1 (bug auto-fixed) — Proxy target reassignment in plan WR-04 guard

Plan draft's `TodayDashboard.test.tsx` did:
```js
let dismissedIds = new Set<string>();
jest.mock(..., () => ({ ..., dismissedIds: new Proxy(dismissedIds, {...}) }));
beforeEach(() => { dismissedIds = new Set(); });
```

Reassigning the outer `dismissedIds` binding doesn't change the Set the Proxy already captured. The Proxy keeps pointing at the original (orphaned) Set; `beforeEach` never clears what the mock actually sees. Fixed by keeping one stable `mockDismissedIdsSet` and calling `.clear()` in beforeEach — Proxy target identity is preserved; contents reset between tests as intended.

### Rule 2 (missing critical correctness) — framer-motion mock + store mock must include `useReducedMotion` and new store selectors

Plan's framer-motion mock for TodayStream was correct (added `useReducedMotion: () => false`). Extended the same pattern to `TodayDashboard.test.tsx` because TodayDashboard renders real TodayStream children through STREAM_ORDER — the mock needed to match or the stream bodies would not render the `role="button"` header we assert on.

### Rule 3 (blocking issue auto-fixed) — stale fixtures in use-today.test.ts

`hooks/queries/__tests__/use-today.test.ts` fixture used `tier: 'urgent'` and the pre-Plan-02 counts shape. Without fixing these, Task 4's `tsc --noEmit` gate would NOT exit 0. Plan 04 SUMMARY explicitly hands this file to Plan 05 ("update fixtures in...`use-today.test.ts`"). Migrated to Plan 02 shape.

One latent assertion (`rejects snooze for non-follow-up items`) encoded pre-Plan-02 hook behavior — the hook is now a dispatcher and SHOULD route non-follow-up items to `/tasks/{sourceType}/{id}/snooze`. The code is correct; the test was stale. Rewrote to assert the new dispatcher path with the right payload. This is a latent test-behavior mismatch from an earlier refactor, not a code bug.
