### TanStack hooks — `frontend/hooks/queries/use-today.ts`

Hook signatures:

```typescript
useTodayFeed(opts?: GetTodayFeedQuery): UseQueryResult<TodayFeedResponse>
useCompleteFeedItem():   UseMutationResult<TodayFeedItem, Error, TodayFeedItem, { snapshots: ... }>
useUncompleteFeedItem(): UseMutationResult<void, Error, TodayFeedItem>
useSnoozeFeedItem():     UseMutationResult<void, Error, { item: TodayFeedItem; until: Date }>
useSnoozeTask = useSnoozeFeedItem  // alias re-export
```

**Optimistic-update contract (WR-05 fix).** `useCompleteFeedItem` implements the full cancel/snapshot/restore triad:

1. **`onMutate(item)`** — Cancels all `todayKeys.all` queries to prevent racing refetches. Captures a snapshot of every cache entry matching the prefix. Writes an optimistic update to each cache: `items.filter(i => i.id !== item.id)`. Returns `{ snapshots }` in context.
2. **`onError(_err, _item, ctx)`** — Iterates `ctx.snapshots` and calls `qc.setQueryData(k, d)` to restore the pre-mutate state. Server never wrote; UI reverts.
3. **`onSettled()`** — Unconditionally invalidates `todayKeys.all` so the server becomes the ultimate source of truth (defence against any partial mutation state).

The "Undo" button in the row component (Plan 04) either calls `useUncompleteFeedItem` (if the backend endpoint exists) or relies on the row catching the 404 and falling back to replaying the snapshot restore path. Real undo, not a visual no-op.

**Snooze dispatcher.** `useSnoozeFeedItem` routes on `item.taskSourceType`:
- `follow_up` → `PATCH /ai/follow-ups/{taskSourceId}/snooze` (existing endpoint, preserved — still used by the follow-ups admin page).
- anything else (`manual`, `reminder`) → `PATCH /tasks/{taskSourceType}/{taskSourceId}/snooze` (Plan 01 endpoint).

Both accept `{ dueDate: ISO-8601 }`. `useSnoozeTask` is a zero-overhead alias (`export const useSnoozeTask = useSnoozeFeedItem`) satisfying the CONTEXT.md mandate for a task-specific entry point without duplicating implementation.

**Dismiss stays client-side.** No `useDismissFeedItem` hook — the row component calls `useTodayFeedStore.getState().dismiss(id)` directly. Matches PATTERNS.md watch-out.

### Zustand store — `frontend/stores/today-feed-store.ts`

```typescript
interface TodayFeedState {
  dismissedIds: Set<string>;
  toggledStreams: Set<TodayStream>;           // new
  dismiss: (id: string) => void;
  restore: (id: string) => void;
  isDismissed: (id: string) => boolean;
  toggleStream: (name: TodayStream) => void;  // new
  isToggled: (name: TodayStream) => boolean;  // new
  reset: () => void;
}
```

**`toggledStreams` semantics — critical note for consumers.** The set contains stream names whose expansion state has been FLIPPED from their default (`replies-needed` and `due-today` default to expanded; `waiting-on-others` and `fyi` default to collapsed). A stream IN the set is in the OPPOSITE state of its `defaultExpanded` prop. A stream NOT in the set is in its default state. This is **NOT** a set of "currently collapsed streams" — consumers computing analytics or URL state MUST XOR `isToggled(name)` with the default, not read the set directly. A JSDoc comment above the field documents this to prevent misuse.

Two-argument `reset()` clears both sets. No `persist` middleware, no `zustand/middleware` import, no `createJSONStorage` — session-only by construction, mitigating T-145.1-08 (localStorage info-disclosure threat). `dismissedIds` slice API preserved verbatim; only the new slice was added.
