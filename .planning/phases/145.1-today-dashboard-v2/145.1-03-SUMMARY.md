# Phase 145.1 Plan 03: Leaf + Header Components Summary

## One-liner

5 presentational components for the Today Dashboard v2 — inbox-zero empty state, outlined anchor KPI chip, 24x24 hover-reveal actions trio, 6-option snooze menu with shadow-lg elevation, and a composed header with greeting + localized date + 4 KPI chips — all wired to Plan 02 locales and API types, with WR-06 native-anchor navigation on chips and prefers-reduced-motion fallbacks on every animated surface.

## What shipped

### `TodayEmptyState.tsx` (rewritten — 74 → 27 lines)

Stripped to a single centered card. Removed: `PartyPopper` icon, 80px success-tinted circle, `nextItem` prop + preview row, `Paper` wrapper, `alpha()` tint, `bodyClean` locale key reference (deleted in Plan 02).

Kept only: `<Box maxWidth={480} mx="auto" py={6} textAlign="center">` + one decorative `✨` (aria-hidden) + H5 title + body1 body. Translations consume `t.dashboard.today.empty.{title,body}` only — no conditional `bodyClean` branch.

### `TodayKpiChip.tsx` (new — 71 lines)

Outlined MUI `<Chip component="a" href clickable variant="outlined" size="small">` with icon + count + optional secondary. `Skeleton` fallback during `loading`. Height 32, px 0.5.

WR-06 closure for the KPI strip: native `<a>` means Cmd/Ctrl+click opens a new tab, middle-click opens a new tab, right-click shows the browser context menu — no custom `onClick + router.push` that would break those behaviours. `clickable` is required for MUI's hover styles to apply on an anchored Chip.

Reduced-motion fallback: `@media (prefers-reduced-motion: reduce) { transition: 'none' }` inside the same sx object as `transition: 'all 150ms ease-out'`.

Count digits use `fontVariantNumeric: 'tabular-nums'` so different 1/2/3-digit counts align vertically in the KPI strip.

### `TodayActions.tsx` (new — replaces `TodayQuickActions.tsx`)

3 × `<IconButton size="small" sx={{ width: 24, height: 24 }}>` trio: Check / Clock / X. Wrapped in `<Tooltip enterDelay={800}>`.

Behavioural changes vs old `TodayQuickActions`:

| Field | Old | New |
|---|---|---|
| Idle opacity (desktop) | 0 | 0.5 |
| Button size | 28×28 | 24×24 |
| Tooltip enterDelay | unset (default ~100ms) | 800ms |
| Snooze render | always when `canSnooze` | same (conditional — NOT greyed when false) |
| stop() helper | only `stopPropagation` | `stopPropagation` + `preventDefault` (needed for `<a>` row title click suppression) |
| Translations | `t.dashboard.today.aria.*` (deleted) | `t.dashboard.today.actions.*` |

Hover reveal: idle 0.5 on `sm+`, full 1.0 on parent `.feed-row:hover` or `.feed-row:focus-within`. On `xs`, always 1.0 (touch devices have no hover). Reduced-motion collapses the 120ms opacity transition to `none`.

### `SnoozeMenu.tsx` (extended — 70 → 143 lines)

`SnoozeOption` union widened from 3 to 6: `'quarterHour' | 'oneHour' | 'tonight' | 'tomorrow' | 'nextWeek' | 'custom'`.

`computeUntil(option)` helper:
- `quarterHour` → `addMinutes(now, 15)`
- `oneHour` → `addHours(now, 1)`
- `tonight` → today at 18:00; **edge case**: if `getTime() <= now.getTime()` (already past 6pm), returns tomorrow 9am instead
- `tomorrow` → `startOfTomorrow()` at 9am
- `nextWeek` → `nextMonday(now)` at 9am

`custom` is a stub for MVP: if `props.onCustom` is provided, parent owns the behaviour (for future date-time picker dialog); otherwise fires `toast.info("Custom… — coming soon")` and closes the menu. The MenuItem is rendered regardless so keyboard navigation reaches it.

Shadow-lg elevation: `slotProps={{ paper: { elevation: 16, sx: { boxShadow: 20 } } }}` — MUI's default Menu is elevation=8.

MenuItem style: `{ height: 32, fontSize: 14, fontWeight: 400, '&:hover': { bgcolor: 'action.hover' } }` — no inline hex, all theme-tokens.

Existing `onSnooze(until: Date)` + `anchorEl` + `onClose` prop surface preserved. Icons swapped for the new options: Clock (quarterHour), CalendarClock (oneHour), Moon (tonight), Sun (tomorrow), CalendarDays (nextWeek), CalendarRange (custom).

### `TodayHeader.tsx` (new — 97 lines)

Stack of: greeting Box + 4-chip row.

Greeting Box contains two inert `<Typography>`:
- H1: `fontSize: 24, fontWeight: 600, lineHeight: 1.2, color: 'text.primary'` — greeting string from `pickGreetingKey()` → `t.dashboard.today.greeting.{morning,afternoon,evening}` (bucket boundaries: <12 morning, <18 afternoon, else evening)
- H2: `fontSize: 14, fontWeight: 400, lineHeight: 1.5, color: 'text.secondary'` — `format(new Date(), 'EEEE d MMMM', { locale })` with runtime locale swap: `locale === 'it' ? itLocale : enUS`

No click handlers, no `component="a"`, no `role` on either Typography — greeting and date are inert per UI-SPEC §Click targets.

KPI strip: `<Stack direction="row" spacing={1} flexWrap="wrap" useFlexGap>` hosting 4 `<TodayKpiChip>` instances. Hrefs: `/dashboard/email`, `/dashboard/calendar`, `/dashboard/crm/deals`, `/dashboard/tasks`. Count values fall back to `0` when `counts?.kpi.*` is undefined. `loading` flag passes through to each chip's skeleton.

### `index.ts` (barrel export update)

`export { TodayQuickActions } from './TodayQuickActions'` → `export { TodayActions } from './TodayActions'`.

**Plan 04 will need to add** to the barrel: `TodayHeader`, `TodayKpiChip`. These are NOT yet exported because no in-tree consumer imports them yet — adding unused exports would be dead code. Plan 04's `TodayDashboard` rewrite adds both consumers and the barrel entries in the same commit.

### Reduced-motion compliance (UI-SPEC §Accessibility line 221)

Both animated surfaces introduced in this plan carry the `@media (prefers-reduced-motion: reduce) { transition: 'none' }` block inside the same sx object as the animated rule:

| Component | Animated rule | Reduced-motion override |
|---|---|---|
| `TodayKpiChip` | `transition: 'all 150ms ease-out'` (hover boxShadow + borderColor) | `transition: 'none'` |
| `TodayActions` (outer Box) | `transition: 'opacity 120ms ease-out'` (0.5 → 1.0 reveal) | `transition: 'none'` |

The pattern is deliberately repeated inline in each file (not extracted to a shared mixin) because MUI's sx type narrows better when the media query lives inside the same object — and because these are the only two animated surfaces in the plan, a helper would be over-abstracted.

## Deviations from Plan

### Commit 232adb39 commingled with parallel phase-146 work (infrastructure incident — not a content deviation)

**What happened:** Between Task 2 (`a3fbeb7d`) and Task 4, while Task 3's files were on disk + partially staged (via `git rm TodayQuickActions.tsx` which stages the deletion), a parallel session operating on the same working tree ran `git commit` with a phase-146 test message. That commit swept up the three Task 3 files (`TodayActions.tsx` created, `TodayQuickActions.tsx` deleted, `index.ts` barrel edit) alongside its own `backend/src/common/workers/__tests__/base-worker-isolation.spec.ts` changes under the message `test(146-06): feature-flag hierarchy tests for BaseWorker (D-11/D-12/D-13)`.

**Evidence:** My own `git add + git commit` for Task 3 never ran. The first invocation failed on a `pathspec did not match` (because I'd already `git rm`'d `TodayQuickActions.tsx`), which short-circuited the `&&` chain and aborted the commit step. My retry only ran `git add` + `git status`, not `git commit`. Yet `git log` shows commit `232adb39` containing exactly my Task 3 files plus one unrelated backend test file. Author date on `232adb39` is ~1 hour after my Task 2 commit, from the same local git user. A further post-Task-5 commit (`43bd8a96 test(146-06): direct-Redis QueueHealthService spec`) appeared without any action from this session — confirming an external writer to the branch.

**Impact on Plan 03:**
- Task 3's code IS correctly on disk and in git history — content is right.
- The commit message does NOT reflect Task 3 (says `test(146-06)` not `feat(145.1-03)`).
- The commit contains unrelated backend test code that belongs to a different phase.
- Diff history is harder to audit — a reader looking for Plan 03 work via `git log --grep "145.1-03"` will miss the Task 3 change.

**Why no revert/re-commit:**
- CLAUDE.md forbids destructive git operations (`reset --hard`, `rebase -i`, history rewrites) without explicit user instruction.
- The commit contains legitimate phase-146 work from a parallel agent. Reverting would destroy that work.
- Content correctness is preserved: all Task 3 acceptance criteria verify against the on-disk files, which are correct.

**Recommendation for orchestrator:** Do not run parallel agents on the same working tree. The plan's `<sequential_execution>` block explicitly says "Sequential executor on main working tree" — a second writer violated that contract. Parallel work should use worktrees.
