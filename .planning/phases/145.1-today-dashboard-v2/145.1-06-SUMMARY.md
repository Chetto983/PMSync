## TodayKpiChip extension

```typescript
// Before: no color concept, flat grey outline.
// After:
export function TodayKpiChip({ icon: Icon, count, secondary, label, href, loading, color }: Props) {
  if (loading) return <Skeleton variant="rounded" width={72} height={32} />;
  const tintedBg = color ? `${color}14` : undefined;       // ~8% alpha
  const tintedBgHover = color ? `${color}29` : undefined;  // ~16% alpha
  return (
    <Chip
      component="a"  // ← WR-06 preserved
      href={href}
      /* ... */
      sx={{
        height: 32, px: 0.5,
        bgcolor: tintedBg,
        borderColor: color ? color : undefined,
        transition: 'all 150ms ease-out',
        '@media (prefers-reduced-motion: reduce)': { transition: 'none' },
        '&:hover': {
          boxShadow: 1,
          borderColor: color ? color : 'grey.300',
          bgcolor: tintedBgHover,
        },
        '&:focus-visible': {
          outline: '2px solid',
          outlineColor: color ? color : 'primary.main',
          outlineOffset: 2,
        },
        '& .MuiChip-icon': color ? { color } : undefined,
      }}
    />
  );
}
```

Optional prop + neutral fallback = non-breaking. Existing 4 TodayKpiChip specs stay green without edits.

## TodayRow typeColor() switch statement

```typescript
// BEFORE (Plan 04): flat grey per D-05 "color is garnish".
function typeColor(_type: TodayItemType): string {
  return 'currentColor';
}

// AFTER (Plan 06): semantic per type.
function typeColor(type: TodayItemType): string {
  switch (type) {
    case 'email':
      return pmSyncColors.semantic.email;
    case 'task':
      return pmSyncColors.semantic.tasks;
    case 'deal':
      return pmSyncColors.semantic.contacts;
    case 'event':
      return pmSyncColors.semantic.calendar;
    default:
      return 'currentColor';
  }
}
```

Call-site (`<Icon size={16} color={typeColor(item.type)} aria-hidden />`) unchanged — lucide-react already consumed the return value via its `color` prop, so swapping the body was sufficient.

## TodayActions opacity-fade → color-fade diff

```diff
 <Box sx={{
   display: 'flex',
   alignItems: 'center',
   gap: 0.25,
-  opacity: { xs: 1, sm: 0.5 },
-  transition: 'opacity 120ms ease-out',
+  color: { xs: 'text.primary', sm: 'text.disabled' },
+  transition: 'color 120ms ease-out',
   '@media (prefers-reduced-motion: reduce)': { transition: 'none' },
-  '.feed-row:hover &': { opacity: 1 },
-  '.feed-row:focus-within &': { opacity: 1 },
+  '.feed-row:hover &': { color: 'text.primary' },
+  '.feed-row:focus-within &': { color: 'text.primary' },
 }}>
```

**Why:** At 0.5 opacity on light backgrounds, the 3 action icons were borderline invisible — users couldn't tell what quick actions existed without hovering a row (accessibility regression vs. the original spec intent). Swapping to `text.disabled` (a high-contrast token that MUI calibrates against the theme) keeps the icons always legible and signals their secondary-action role via color rather than ghosting. The hover/focus-within state still lifts them to full `text.primary`, so the affordance pattern is preserved.

**Preserved:** 24×24 IconButton dimensions, 800ms Tooltip `enterDelay`, `stopPropagation + preventDefault` helpers, `item.canSnooze &&` conditional render, always-on Dismiss, `prefers-reduced-motion` fallback (now targets the color transition instead of opacity).
