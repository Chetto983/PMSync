**Step 3: Analyze failures and fix**

For each failing test:
1. Read the error message and identify root cause
2. Check if it's a script issue (wrong endpoint path, wrong response shape) or a backend bug
3. If script issue: fix the validation script to match actual API behavior
4. If backend bug: fix the backend code, run `cd backend && npx tsc --noEmit`, commit, push, redeploy, rerun

Common issues to expect:
- **Response envelope shape mismatch**: The bulk operations may return `{ updated: N, emails: [...] }` or `{ count: N }` or different shapes. Adjust assertions to match actual response.
- **Draft GET response shape**: May return the email object directly or wrapped in `{ data: {...} }`. Adjust.
- **Bulk delete response**: May return `{ deleted: N }` or `{ softDeleted: N, hardDeleted: N }`. Check actual shape.
- **Folder path format**: `bulkMoveToFolder` expects `folder` as a string path. Check whether it wants the folder `name`, `path`, or `id`.
- **Labels endpoint path**: Verify `/api/v1/labels` returns labels correctly. May need provider filter.
- **DELETE body issue**: If Railway proxy strips DELETE body, switch `bulkDelete` to use a workaround (POST to a different endpoint, or adjust apiDeleteWithBody to use a different approach).
