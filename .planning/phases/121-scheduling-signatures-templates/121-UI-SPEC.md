## Phase Classification: Backend Validation Only

This phase has **no frontend UI work**. It validates existing backend APIs (scheduled emails, signatures, templates) via automated Node.js scripts run from the terminal. The REQUIREMENTS.md explicitly lists "Frontend UI testing" as out of scope for v10.0.

All 5 requirements (INFRA-06 through INFRA-10) are backend API integration tests executed via Playwright CDP + fetch calls. No React components, MUI elements, or browser-rendered UI is created or modified.

**Consequence:** The design contract sections below are marked "Not applicable" with justification. The checker should evaluate this phase as a pass-through -- there is nothing to visually validate.

## Color

Not applicable. Terminal output uses ANSI escape codes for pass (green) / fail (red) / info (cyan) consistent with the validation-helpers.mjs `report()` function established in Phases 112-120.

| Terminal Output | ANSI Color | Usage |
|-----------------|------------|-------|
| PASS | Green (32) | Test passed |
| FAIL | Red (31) | Test failed |
| INFO | Cyan (36) | Informational output |
| SKIP | Yellow (33) | Test skipped (infrastructure blocked) |

## Copywriting Contract

No user-facing copy is introduced by this phase. The only text output is terminal validation messages following the established pattern:

| Element | Copy |
|---------|------|
| Schedule send pass | `INFRA-06 Scheduled email sends at correct time: PASS` |
| Schedule cancel pass | `INFRA-07 Cancel prevents scheduled delivery: PASS` |
| Signature CRUD pass | `INFRA-08 Signature CRUD and default selection: PASS` |
| Template CRUD pass | `INFRA-09 Template CRUD, duplicate, and default: PASS` |
| Signature in send pass | `INFRA-10 Sent email includes signature: PASS` |
| Failure format | `{REQ-ID} {description}: FAIL -- {reason}` |
| Summary format | `{passed}/{total} checks passed` |
