**1. Create org management permission guard (ORG-05 enforcement):**

Create `backend/src/common/auth/org-management.guard.ts`:

The auth proxy at `frontend/pages/api/auth/[...all].ts` forwards ALL `/api/auth/*` requests to the backend's better-auth instance directly. This means better-auth's organization management routes (`/api/auth/organization/create`, `/api/auth/organization/invite-member`, `/api/auth/organization/remove-member`, `/api/auth/organization/delete`) are accessible to ANY authenticated user by default, bypassing NestJS guards entirely.

To enforce ORG-05, use better-auth's `organization()` plugin configuration hooks. In the `organization()` plugin config in `better-auth.instance.ts`, add `organizationCreatedHook` and use the `allowUserToCreateOrganization` (already added in Task 1) plus add access control for invite/remove/delete operations.

better-auth's organization plugin supports `ac` (access control) configuration. Use it to restrict org management operations to super-admins:

```typescript
// In the organization() plugin config, add access control:
ac: {
  // Only super-admins can perform these operations
  // The plugin checks user permissions before executing
  member: {
    // Override: allow only super-admin role to manage members
  },
  invitation: {
    // Override: allow only super-admin role to send invitations
  },
},
```

However, if `ac` config is not flexible enough, add a `before` hook or middleware. The most reliable approach: add server-side validation in the better-auth instance itself using the `hooks` option:

```typescript
// In createBetterAuthInstance, add to the better-auth config:
hooks: {
  before: [
    {
      matcher: (context) => {
        // Match org management routes
        const path = context.path;
        const orgMgmtPaths = [
          '/organization/create',
          '/organization/invite-member',
          '/organization/remove-member',
          '/organization/delete',
          '/organization/update',
        ];
        return orgMgmtPaths.some(p => path.includes(p));
      },
      handler: async (context) => {
        // Get the session to check the user's role
        const session = await context.context.getSession(context);
        if (!session?.user) {
          throw new Error('Unauthorized');
        }
        const userRole = (session.user as any).role;
        if (userRole !== 'super-admin') {
          // Return a 403 response
          return {
            response: new Response(
              JSON.stringify({ error: 'Only super-admins can manage organizations' }),
              { status: 403, headers: { 'content-type': 'application/json' } }
            ),
          };
        }
      },
    },
  ],
},
```

Check the better-auth docs/source for the exact hook API. The key requirement: any authenticated user hitting `/api/auth/organization/invite-member`, `/api/auth/organization/remove-member`, `/api/auth/organization/delete`, or `/api/auth/organization/create` who is NOT a super-admin gets a 403 response.

Also create `backend/src/common/auth/org-management.guard.ts` as a NestJS guard that can be applied to any NestJS routes that proxy or interact with org management (for future use if org management moves to NestJS controllers):

```typescript
import { CanActivate, ExecutionContext, ForbiddenException, Injectable } from '@nestjs/common';

/**
 * Guard that restricts org management operations to super-admin users.
 * Enforces ORG-05: API endpoints enforce organization-level permissions.
 *
 * Apply to any NestJS route that performs org management operations.
 * For better-auth routes (proxied via /api/auth/*), enforcement is done
 * via better-auth hooks in better-auth.instance.ts.
 */
@Injectable()
export class OrgManagementGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    const user = request.user;

    if (!user) {
      throw new ForbiddenException('Authentication required');
    }

    if (user.role !== 'super-admin') {
      throw new ForbiddenException('Only super-admins can manage organizations');
    }

    return true;
  }
}
```

```typescript
import { PrismaClient } from '@prisma/client';

const prisma = new PrismaClient();

async function main() {
  const users = await prisma.user.findMany({
    where: { tenantId: { not: null } },
    select: { id: true, tenantId: true },
  });

  let created = 0;
  let skipped = 0;

  for (const user of users) {
    if (!user.tenantId) continue;

    const existing = await prisma.member.findUnique({
      where: {
        organizationId_userId: {
          organizationId: user.tenantId,
          userId: user.id,
        },
      },
    });

    if (existing) { skipped++; continue; }

    await prisma.member.create({
      data: {
        organizationId: user.tenantId,
        userId: user.id,
        role: 'admin',
      },
    });
    created++;
  }

  console.log(`Migration complete: ${created} member records created, ${skipped} skipped`);
}

main()
  .catch(console.error)
  .finally(() => prisma.$disconnect());
```
