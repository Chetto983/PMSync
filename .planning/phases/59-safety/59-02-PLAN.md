    2. Also read `backend/src/modules/subscription/guards/quota.guard.ts` to confirm that QuotaGuard already enforces subscription-tier differentiation (FREE vs PRO). The existing guard chain is: BetterAuth -> Legal -> Consent -> Tenant -> Quota -> Roles. QuotaGuard handles tier-based rate limiting at the subscription level. The @Throttle limits set here are the GLOBAL BASELINE that applies to all users regardless of tier. QuotaGuard then enforces stricter limits for FREE users and more generous limits for PRO users on top of this baseline.

    3. For EACH @SkipThrottle occurrence, determine the endpoint type and apply the correct replacement:

    **READ endpoints (GET):** Simply REMOVE @SkipThrottle(). The global default (100 req/min) is sufficient as a baseline for reads. QuotaGuard already differentiates by subscription tier above this. Only add explicit @Throttle if the endpoint needs a DIFFERENT global baseline than 100 req/min.

    **WRITE endpoints (POST/PUT/DELETE):** Remove @SkipThrottle(). If the endpoint is heavy (creates resources, triggers syncs), add `@Throttle({ default: { limit: 20, ttl: 60000 } })` as a tighter global baseline. QuotaGuard adds tier differentiation on top.

    **Webhook endpoints (POST routes receiving external provider callbacks):** Replace @SkipThrottle() with `@Throttle({ default: { limit: 500, ttl: 60000 } })`. These need high limits because providers send bursts. Webhooks bypass QuotaGuard since they're @Public() and not tied to user subscriptions.

    **Health check endpoints:** Replace @SkipThrottle() with `@Throttle({ default: { limit: 30, ttl: 60000 } })`.

    4. For class-level @SkipThrottle (like health.controller.ts), remove the class-level decorator and add per-method @Throttle only if needed.

    5. Import `Throttle` from `@nestjs/throttler` in any file that doesn't already import it. Remove `SkipThrottle` from imports in files where it's no longer used.

    6. After all changes, run `grep -rn "SkipThrottle" backend/src/ --include="*.ts"` to confirm ZERO remaining occurrences (except possibly in test files, which is fine).

    NOTE: The tiered rate limiting by subscription (FREE vs PRO) per CONTEXT.md is already handled by QuotaGuard in the guard chain. This task's job is to ensure every endpoint falls under the global @Throttle baseline so that QuotaGuard's tier enforcement always has something to layer on. Don't duplicate QuotaGuard logic in @Throttle decorators.
