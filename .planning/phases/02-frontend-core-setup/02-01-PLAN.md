Create `frontend/ARCHITECTURE.md` with the following sections:

1. **Overview** (5-10 lines)
   - Tech stack summary: Next.js Pages Router, React 19, TypeScript
   - Component libraries: MUI 7.3.7 (primary), shadcn/ui (for gaps)
   - State management: TanStack Query (server), Zustand (client)

2. **Component Strategy** (20-30 lines)
   - **MUI primary**: Use for data-heavy components, forms, enterprise patterns
   - **shadcn/ui for gaps**: Command palette, Combobox, lightweight interactions
   - **Rule**: If MUI has it, use MUI. If not, use shadcn.
   - **Compatibility layer**: shadcn Button accepts `fullWidth`, `sx` props for MUI compat
   - **Layout primitives**: MUI Box/Stack (not raw Tailwind flex)
   - **Import paths**: `@/components/ui` for shadcn, direct import for MUI

3. **Data Fetching Patterns** (30-40 lines)
   - **REQUIRED**: All data fetching via TanStack Query hooks
   - **FORBIDDEN**: Direct `apiClient.get()` in components (except in query functions)
   - **Query key factory**: `frontend/hooks/queries/*-keys.ts`
   - **Hook pattern**: `queryOptions()` + `useQuery()` wrapper
   - **Optimistic updates**: Use `onMutate`, `onError`, `onSettled` pattern
   - **Cache configuration**: `staleTime: 5 * 60 * 1000`, `gcTime: 30 * 60 * 1000`
   - Example: Show typical hook structure from `use-emails.ts`

4. **File Organization** (20-30 lines)
   - `components/email/` - Email-specific components
   - `components/ui/` - shadcn components (30+ exist)
   - `components/layout/` - App shell components
   - `hooks/queries/` - TanStack Query hooks and key factories
   - `lib/api/` - API client modules (apiClient, specific APIs)
   - `locales/` - i18n translations (en.ts, it.ts, types)
   - `stores/` - Zustand stores for client state

5. **Routing Conventions** (10-15 lines)
   - Pages Router (not App Router)
   - Main email: `/dashboard/email`
   - Compose: `/dashboard/email/compose`
   - Thread: `/dashboard/email/thread/[threadId]`
   - Layout: 3-panel with Allotment (see EmailLayout.tsx)

6. **Styling Approach** (15-20 lines)
   - MUI `sx` prop for component-specific styles
   - Tailwind utilities for quick adjustments
   - CSS variables for theming (globals.css)
   - Dark mode: CSS variables + `next-themes`
   - **DO NOT**: Mix arbitrary Tailwind with MUI Box (use sx or pure Tailwind)

7. **i18n Conventions** (10-15 lines)
   - All UI strings via `useTranslations()` hook
   - Never hardcode user-facing strings
   - Locales: `en.ts`, `it.ts`
   - Types in `locales/index.ts`

8. **Performance Patterns** (10-15 lines)
   - Virtual scroll: `@tanstack/react-virtual` for lists >50 items
   - Code splitting: `React.lazy()` for non-critical components
   - Prefetch: `queryClient.prefetchQuery()` on hover
   - Optimistic updates for instant feedback

IMPORTANT: Document what EXISTS, not aspirational patterns. Refer to actual files.
