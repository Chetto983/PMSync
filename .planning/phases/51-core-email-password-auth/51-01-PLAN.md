Update `frontend/lib/auth.ts` to add email verification and password reset callbacks. The file is currently 59 lines -- keep it under 100.

1. Add import at top: `import { sendTransactionalEmail } from "./mail";`

2. Replace the existing `emailAndPassword` config with:
   ```typescript
   emailAndPassword: {
     enabled: true,
     requireEmailVerification: true,
     autoSignIn: true,
     sendResetPassword: async ({ user, url }) => {
       void sendTransactionalEmail(
         user.email,
         "Reset your password",
         `<p>Click the link to reset your password:</p><a href="${url}">${url}</a>`,
       );
     },
   },
   ```
   Key points:
   - `requireEmailVerification: true` blocks signin for unverified users (CORE-04)
   - `autoSignIn: true` creates session immediately after signup (before email verified -- better-auth will still block signin on subsequent attempts if not verified)
   - `void` before sendTransactionalEmail to avoid timing attacks (fire-and-forget per better-auth docs)

3. Add `emailVerification` section to the config:
   ```typescript
   emailVerification: {
     sendVerificationEmail: async ({ user, url }) => {
       void sendTransactionalEmail(
         user.email,
         "Verify your email address",
         `<p>Click the link to verify your email:</p><a href="${url}">${url}</a>`,
       );
     },
     sendOnSignUp: true,
     autoSignInAfterVerification: true,
   },
   ```

4. Extend the HIBP hook to also intercept the password reset path. The current hook only checks `/sign-up/email`. Add `/reset-password` to cover CORE-07 on password changes:
   ```typescript
   hooks: {
     before: createAuthMiddleware(async (ctx) => {
       // Intercept sign-up and password-reset to check HIBP
       if (ctx.path === "/sign-up/email" || ctx.path === "/reset-password") {
         const password = (ctx.body?.password ?? ctx.body?.newPassword) as string | undefined;
         if (password) {
           const { breached } = await checkHIBP(password);
           if (breached) {
             throw new APIError("BAD_REQUEST", {
               message: "This password has appeared in data breaches and cannot be used",
             });
           }
         }
       }
     }),
   },
   ```
   Note: better-auth's reset-password endpoint may use `newPassword` as the body field name. Check both `password` and `newPassword` via nullish coalescing.
