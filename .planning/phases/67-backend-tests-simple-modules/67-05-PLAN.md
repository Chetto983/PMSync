For Test 8 (cascade delete): create tenant → parent label via createTestLabel → child via createTestLabel with parentId=parent.id → grandchild via createTestLabel with parentId=child.id. Call service.delete(tenantId, parent.id). Then query prisma.userLabel.findMany({ where: { id: { in: [parent.id, child.id, grandchild.id] } } }) and assert all have isArchived=true.

For Test 9 (circular reference): create tenant → labelA → labelB with parentId=labelA.id. Then call service.update(tenantId, labelA.id, { parentId: labelB.id }). Should throw ConflictException.

Pitfall to avoid (from research): soft-delete renames the slug by appending `-deleted-${Date.now()}`. After delete(), don't try to re-create a label with the same original name in the same test without creating a new tenant — it will succeed because the old slug is freed.

Pitfall to avoid: realtimeEvents calls (emitLabelNew, emitLabelDelete, emitLabelUpdate) happen on the mock — they don't throw. Optionally assert they were called for completeness, but keep assertions light. The goal is DB state, not socket internals.
