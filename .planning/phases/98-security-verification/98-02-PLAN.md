**Script 2: `backend/scripts/audit-redis-pool.ts`**

This script audits Redis connection pool configuration and prints scaling recommendations.

The script must:
1. Read and parse the Redis configuration from environment (same as `getRedisConnectionOptions()` does):
   - `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`, `REDIS_DB`
   - `CACHE_REDIS_CONNECT_TIMEOUT_MS`
2. Enumerate all known Redis connection consumers in the codebase and print their config:
   ```
   REDIS CONNECTION AUDIT
   ─────────────────────────────────────────────────
   Consumer                | Connection Name    | maxRetriesPerRequest | lazyConnect | Notes
   ─────────────────────────────────────────────────
   RedisConnectionService  | shared-service     | 3                    | true        | Shared: throttler, locks, OTP, TOTP, contacts cache, triage
   CacheService            | (inline)           | null                 | false       | Separate cache connection, custom timeout
   BullMQ shared           | bullmq-shared      | null                 | false       | Queue operations
   Socket.IO pub           | (auto)             | null                 | -           | Pub/sub for realtime
   Socket.IO sub           | (auto)             | null                 | -           | Pub/sub for realtime
   Workers (per worker)    | {name}-worker      | null                 | false       | One per BullMQ worker
   QueryEmbeddingCache     | (separate)         | -                    | -           | May use different Redis DB
   ```
3. Print total estimated connection count: `Total Redis connections: ~6 + N workers (where N = number of BullMQ worker types)`
4. Print scaling recommendations:
   - **Connection count warning:** Each ioredis instance is a single TCP connection. With ~6 base connections + workers, a single server instance uses ~10-15 connections. Railway free tier Redis (if applicable) typically limits to ~20 concurrent connections.
   - **maxRetriesPerRequest inconsistency:** RedisConnectionService uses `3` but BullMQ requires `null`. This is correct but should be documented. The `3` on shared-service means the throttler will retry 3 times before giving up (and then fail-open).
   - **No connection pooling:** ioredis does NOT pool connections by default. Each `new Redis()` is one TCP socket. For high-throughput, consider ioredis `Cluster` mode or a connection pool wrapper, but for single-instance Railway deployments this is fine.
   - **Fail-open risk:** RedisThrottlerStorage silently disables rate limiting when Redis is unreachable. Log a warning that this is by design but should be monitored.
   - **lazyConnect:** RedisConnectionService uses `lazyConnect: true`, meaning the connection is not established until the first command. If Redis is slow to respond, the first throttled request will have elevated latency. BullMQ connections use `lazyConnect: false` (connect eagerly).

5. If `REDIS_HOST` is set, attempt a PING to verify connectivity and print latency.
