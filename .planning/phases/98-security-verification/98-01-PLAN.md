<!-- Guard architecture (from source) -->
Global APP_GUARDs in order:
1. UserThrottlerGuard (rate limiting)
2. BetterAuthGuard (session validation, 401 on missing/invalid, @Public() bypass)
3. LegalAcceptanceGuard
4. ConsentGuard

Per-controller guards:
- TenantGuard: validates tenant membership, rejects cross-tenant (403) unless super-admin
- RolesGuard: enforces @Roles() decorator, super-admin always passes

**Script 1: `backend/scripts/verify-tenant-isolation.ts`**

This script verifies SEC-02 (tenant isolation). It requires a running server and two test users in different tenants.

The script must:
1. Accept env vars: `AUDIT_BASE_URL`, `TEST_USER_EMAIL`, `TEST_USER_PASSWORD`, `CROSS_TENANT_ID` (the tenant ID the user does NOT belong to).
2. Authenticate by calling `POST ${BASE}/api/auth/sign-in/email` with `{email, password}` to get a session cookie from the `set-cookie` response header.
3. Make requests to key data endpoints WITH the valid session cookie BUT with `x-tenant-id` header set to `CROSS_TENANT_ID` (a tenant the user is NOT a member of).
4. Test these endpoints for cross-tenant rejection (all should return 403):
   - `GET /api/v1/emails`
   - `GET /api/v1/contacts`
   - `GET /api/v1/calendar/events`
   - `GET /api/v1/labels`
   - `GET /api/v1/reminders`
   - `GET /api/v1/providers`
5. Print pass/fail for each. Exit code 1 if any returns non-403.

If `TEST_USER_EMAIL` is not set, print a message explaining the required env vars and exit with code 0 (graceful skip, since this requires real credentials).

Add `// @ts-nocheck` at top.

**Script 2: `backend/scripts/verify-rbac.ts`**

This script verifies SEC-05 (RBAC). It requires a running server and a member-role user.

The script must:
1. Accept env vars: `AUDIT_BASE_URL`, `MEMBER_USER_EMAIL`, `MEMBER_USER_PASSWORD`.
2. Authenticate the member-role user via `POST ${BASE}/api/auth/sign-in/email`.
3. Hit admin-only endpoints with the member session cookie and verify 403:
   - `GET /api/v1/ai/runs` (@Roles('admin') on AiObservabilityController)
   - `GET /api/v1/tenants` (@Roles('super-admin') on TenantsController)
   - `POST /api/v1/tenants` (@Roles('super-admin') on TenantsController) -- send empty body
   - `POST /api/v1/email-sync/full` (@Roles('admin', 'super-admin') on EmailSyncController)
4. Also verify that the same member CAN access non-admin endpoints (should get 200 or non-403):
   - `GET /api/v1/emails` (no @Roles required on list)
   - `GET /api/v1/contacts` (no @Roles on list)
5. Print pass/fail. Exit code 1 if admin endpoint does NOT return 403, or if non-admin endpoint returns 403.

If `MEMBER_USER_EMAIL` is not set, print a message and exit code 0 (graceful skip).

Add `// @ts-nocheck` at top.

Both scripts use the same axios pattern from audit-deep-api.ts.
