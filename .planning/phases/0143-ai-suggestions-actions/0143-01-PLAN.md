**Part B: Create EmailSuggestionGeneratorService (per D-01, D-02, D-03, D-04)**

Create `email-suggestion-generator.service.ts` in `backend/src/modules/crm/suggestion/services/`. This service:

1. Inject `PrismaService` and `CrmSuggestionService`.
2. Define a `getOrGenerate(tenantId: string, emailId: string)` method:
   - First, query existing pending suggestions: `prisma.crmSuggestion.findMany({ where: { tenantId, sourceEmailId: emailId, status: 'pending' } })`
   - If any exist, return them immediately (per D-03).
   - Also check if ANY suggestions (including dismissed/accepted) exist for this email — if so, don't regenerate (the user already saw suggestions for this email).
   - If none exist at all, load email with triage fields: `prisma.email.findFirst({ where: { id: emailId, tenantId }, select: { id: true, tenantId: true, subject: true, snippet: true, from: true, aiCategory: true, aiActionability: true, aiIntent: true, contactId: true, dealId: true } })`
   - If email not found, throw NotFoundException.
   - Check for linked ticket: `prisma.ticket.findFirst({ where: { tenantId, emailId } })` to know if ticket exists.
   - Run rule engine (see rules below).
   - For each matched rule, call `this.suggestionService.create(tenantId, { type, entityData, sourceEmailId: emailId, sourceType: 'email_triage', confidence })`.
   - Return the created suggestions (filter to pending status).

3. Rule engine (per D-04) — implement as an array of rule objects:
   - **create_ticket**: `aiCategory === 'support'` AND no linked ticket. Confidence 0.8. EntityData: `{ subject: email.subject, sourceEmailId: email.id, contactId: email.contactId, title: 'Create support ticket', reasoning: 'Email categorized as support with no linked ticket' }`.
   - **create_deal**: `aiCategory === 'sales'` AND `!email.dealId`. Confidence 0.7. EntityData: `{ title: email.subject, sourceEmailId: email.id, contactId: email.contactId, title: 'Create sales deal', reasoning: 'Email categorized as sales with no linked deal' }`.
   - **create_task**: `aiActionability === 'todo'`. Confidence 0.75. EntityData: `{ title: email.subject, description: email.snippet, emailId: email.id, contactId: email.contactId, title: 'Create follow-up task', reasoning: 'Email requires action' }`.
   - **link_contact**: `!email.contactId`. Confidence 0.6. EntityData: `{ emailAddress: extractEmailFromHeader(email.from), emailId: email.id, title: 'Link to contact', reasoning: 'No contact linked to this email' }`.

   NOTE: Store `title` and `reasoning` inside `entityData` so the frontend can display them without needing to recompute. Use a helper to extract plain email address from the `from` header (split on angle brackets or use regex).

4. Keep this service under 200 lines. The rule engine is simple array iteration — no need for complex abstractions.
