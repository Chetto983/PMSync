**Step 1: Conversation CRUD (4 endpoints)**

1. `POST /ai/chat/conversations` -- create a new conversation -- expect `{ id: string, title: string, ... }`. Note the returned `id` for subsequent calls.
2. `GET /ai/chat/conversations` -- list conversations -- expect array of conversation objects including the one just created.
3. `GET /ai/chat/conversations/:id` -- get the created conversation -- expect conversation object with `messages: []` (empty since no chat yet).
4. After chat test below, `DELETE /ai/chat/conversations/:id` -- expect 200 success.

**Step 2: Chat SSE streaming**

5. `POST /ai/chat` -- body: `{ messages: [{ role: "user", content: "What emails did I receive today?" }], conversationId: "<id from step 1>" }` -- this returns SSE stream (content-type: text/event-stream). Verify:
   - Response has `Content-Type: text/event-stream` or `text/plain` (AI SDK v6 format)
   - Stream events arrive with assistant message tokens
   - Stream terminates cleanly (no hanging connection)
   - After stream completes, `GET /ai/chat/conversations/:id` shows the conversation now has messages

**Step 3: HITL verification (conceptual)**

The HITL flow requires asking the AI to perform a high-risk action (e.g., "Send an email to test@example.com saying hello"). The 6 tools with `needsApproval`: `send_email`, `delete_email`, `forward_email`, `reply_email`, `delete_event`, `delete_contact`.

- Send a chat message asking the AI to send an email. The response stream should include a tool call with `status: requires-action`.
- This verification is best completed in the frontend browser (Plan 03), but confirm the backend stream includes the `requires-action` status in the SSE events.
