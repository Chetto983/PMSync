1. Create `contact-timeline.dto.ts` with these types:
   - `TimelineEntryType` enum or union: `'email_sent' | 'email_received' | 'deal_activity' | 'task' | 'meeting' | 'ticket' | 'note'`
   - `TimelineEntryDto`: `{ id: string; type: TimelineEntryType; title: string; summary: string | null; date: string; metadata: Record<string, unknown>; entityId: string; }`
   - `TimelineResponseDto`: `{ entries: TimelineEntryDto[]; nextCursor: string | null; total: number; }`
   - `TimelineQueryDto` (validation via class-validator): `cursor?: string; limit?: number` (default 20, max 50)

2. Create `contact-timeline.service.ts` as `@Injectable() ContactTimelineService`:
   - Inject `PrismaService` and `ContactCrudService` (to fetch contact by ID)
   - Method: `async getTimeline(tenantId: string, contactId: string, cursor?: string, limit = 20): Promise<TimelineResponseDto>`
   - Implementation approach (per research, avoid N+1):
     a. Fetch contact, extract email addresses (reuse same pattern from `contact-provider-ops.service.ts`)
     b. If cursor provided, parse it as ISO date string for `date < cursor` filtering
     c. Run 5 parallel queries via `Promise.all`:
        - Emails sent TO contact (Email where `to` hasSome contactEmails, folder in SENT variants) -> map to `email_sent`
        - Emails received FROM contact (Email where `from` contains contactEmail) -> map to `email_received`
        - CRM activities for contact's deals (`CrmActivity` via `DealContact` join) -> map to type based on `CrmActivity.type` (STAGE_CHANGE -> `deal_activity`, NOTE -> `note`, CALL/MEETING -> `meeting`, TASK -> `task`)
        - ManualTasks where `contactId` matches -> map to `task`
        - Tickets where `contactId` matches -> map to `ticket`
     d. **Dedup emails**: CrmActivity with type EMAIL should NOT be included (use actual Email records instead, per research pitfall 5)
     e. Merge all entries into single array, sort by `date` descending
     f. Take `limit + 1` from each source query, then after merge/sort take `limit + 1` total. If extra exists, `nextCursor = entries[limit - 1].date`
     g. For `total`: use a simple count query (or return -1 if too expensive; cursor pagination doesn't strictly need total)
   - Every Prisma query MUST include `tenantId` in the where clause
   - CalendarEvent linking: query `CalendarEvent` where `tenantId` matches, then filter in-app by checking if `attendees` JSON contains any of the contact's email addresses. Limit date range to last 1 year for performance. Map to `meeting` type.

3. Add endpoint to `contacts.controller.ts`:
   - `@Get(':id/timeline')` above the existing `@Get(':id/history')` route (order matters for NestJS route matching)
   - Inject `ContactTimelineService`
   - Method: `async getContactTimeline(@Req() req, @Param('id') contactId: string, @Query() query: TimelineQueryDto)`
   - Extract `tenantId` from `req.user.tenantId`
   - Return `this.contactTimelineService.getTimeline(tenantId, contactId, query.cursor, query.limit)`

4. Register `ContactTimelineService` in `contacts.module.ts` providers array.
