The migration shape (same for all 16 files):

```typescript
// BEFORE
import { google, gmail_v1 } from 'googleapis';          // or calendar_v3 / people_v1
const oauth2Client = new google.auth.OAuth2();
oauth2Client.setCredentials({ access_token: token });
const gmail = google.gmail({ version: 'v1', auth: oauth2Client });

// AFTER
import { gmail as gmailFactory, gmail_v1 } from '@googleapis/gmail';
import { OAuth2Client } from 'google-auth-library';
const oauth2Client = new OAuth2Client();
oauth2Client.setCredentials({ access_token: token });
const gmail = gmailFactory({ version: 'v1', auth: oauth2Client });
```

**Key exports from scoped packages:**
- `@googleapis/gmail` — exports factory `gmail(opts)` and types namespace `gmail_v1` (same shape as old `google.gmail_v1`).
- `@googleapis/calendar` — exports factory `calendar(opts)` and types namespace `calendar_v3`.
- `@googleapis/people` — exports factory `people(opts)` and types namespace `people_v1`.
- `google-auth-library` — exports class `OAuth2Client` (same class that `google.auth.OAuth2` re-exports).

**Aliasing rule:** The exported factory name (`gmail`/`calendar`/`people`) collides with local variable names used throughout the codebase (e.g., `const gmail = ...`). Alias on import to `gmailFactory` / `calendarFactory` / `peopleFactory` to avoid shadowing.

**`as any` cleanup:** Files using `{ auth: auth as any }` (verified sites: `gmail-client-manager.service.ts:88`, `google-oauth.service.ts:423/451/487/541/573/612`) can DROP the `as any` cast — the scoped packages' `auth` parameter accepts `OAuth2Client` directly.

**Stateful type simplification (google.driver.ts only):**
```typescript
// BEFORE (line 57)
private oauth2Client: InstanceType<typeof google.auth.OAuth2> | null = null;
// AFTER
private oauth2Client: OAuth2Client | null = null;
```
