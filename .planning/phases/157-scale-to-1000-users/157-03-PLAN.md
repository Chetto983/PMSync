<objective>
SCALE-04: Build the Artillery load-test rig. This is the pre-work for Plan 04 (baseline execution) and Plan 05 (post-split acceptance test). No load generation happens in this plan — only scenario authoring, processor scaffolding, tenant-seed/cleanup scripts, and the runbook.

Purpose: Deliver a reproducible, native-Socket.IO-capable load generator. k6 is rejected because it does not support Socket.IO at the protocol level (RESEARCH.md §Standard Stack + Socket.IO official load-test guide). Artillery's native `socketio-v3` engine speaks Engine.IO v4 correctly.

**Critical seeding fix (revision v2 — addresses checker blocker #2):**
The original (v1) seed script used `prisma.user.create({ data: { email, tenantId, name } })` — this BYPASSED better-auth's bcrypt password hashing pipeline. Result: every Artillery `/sign-in/email` request would have returned 401 because no `account` row existed with the hashed password. v2 uses `auth.api.signUpEmail({ body: { email, password, name } })` — better-auth's server-side helper that runs bcrypt + writes both the `user` row AND the `account` row with the password hash. The seed task includes a smoke-login validation step proving 10 seeded users can actually authenticate before bulk seeding completes.

**Scope boundaries:**
- This plan INSTALLS Artillery and authors the configs. It does NOT run a baseline measurement (that's Plan 04).
- This plan ADDS `loadtest-tenant` seed/cleanup scripts. It does NOT seed production — the scripts target a staging / Railway-staging environment.
- Dev-only dependency: Artillery must NOT appear in production Docker image (`Dockerfile.railway` already does `npm prune --omit=dev` at line 15 — verified — so devDependencies are stripped post-build).

**Parallelization:** Runs in Wave 2 alongside Plan 02 (delete dead tenantCounters). File sets are now disjoint — Plan 02 v2 no longer touches `backend/package.json` (no LRU install), so this plan owns the package.json edit in Wave 2 exclusively. Both depend only on Plan 01.

3. **Pitfall 7 — per-user RAM slope is dominated by buffer churn.** The runbook must note: take RAM measurements at steady state (5+ min into hold phase), not during ramp.
4. **Security Pattern V7 (RESEARCH.md §Security Domain) — cookie redaction.** `processors/auth.js` MUST have a `redactCookie` hook. If skipped, Artillery's JSON report contains `set-cookie: sess=<real-session>` which ends up in CI artifacts.
5. **The `ensure: { p95: 500 }` number is aspirational (RESEARCH.md §Open Question 1).** Plan 04 will measure the actual baseline; this plan commits to p95: 500 in the YAML but Plan 04's SUMMARY may recommend revising it. Do NOT mark this as "gospel" in the runbook — present as "target, subject to baseline validation".
6. **.env.loadtest is secrets.** `.env.loadtest.example` is committed; `.env.loadtest` MUST be gitignored. Verify `backend/.gitignore` excludes it BEFORE committing.
7. **better-auth password hashing throughput (RESOLVED Open Question #6 in 157-RESEARCH.md).** Bcrypt-ish hashing saturates CPU. Seed script MUST use chunked parallelism — `Promise.all` over chunks of **10** (NOT 50; bcrypt rounds saturate the event loop). Target: < 3 min for 1000 users on a typical dev machine. Sequential would take ~100ms × 1000 = 100s + auth overhead = ~5min; chunks of 10 in parallel reduces wall-clock to ~30-90s.
8. **Bootstrap dependencies for the seed script.** `createBetterAuthInstance(prisma, emailService)` requires both a `PrismaClient` AND an `EmailService` instance. `EmailService` has a no-arg constructor (verified at `email.service.ts:11`) but reads `getConfiguration().email` — the seed must run with env vars present (SENDGRID_API_KEY etc.). Since the seed CALLS signUpEmail which triggers `sendVerificationEmail` (better-auth.instance.ts:418), and that helper logs but does NOT throw on failure (catch at line 422), missing SendGrid creds are tolerable — verification emails will fail to send but signUp will succeed and the seed can proceed to set `emailVerified: true` directly.
9. **Smoke-login validation acceptance criterion.** After seeding the first 10 users, the seed script MUST exercise `POST /sign-in/email` against `LOADTEST_TARGET` for those 10 users and confirm all 10 return HTTP 200. If any return 401, the seed FAILS (exit non-zero) — meaning the seed pipeline broke the auth contract. Bulk 990-user seed only proceeds after the smoke-login passes.

/**
 * SCALE-04 — Seed N synthetic users into the loadtest-tenant via better-auth.
 *
 * IMPORTANT: Uses `auth.api.signUpEmail` (NOT raw prisma.user.create) so bcrypt
 * password hashing runs and the `account` row is written. Without this, every
 * Artillery /sign-in/email request returns 401.
 *
 * After signUp, directly sets `emailVerified: true` to bypass
 * `requireEmailVerification: true` (better-auth.instance.ts:402) — synthetic
 * test users are not real humans; verification flow is irrelevant.
 *
 * Includes a smoke-login validation step: after seeding the first chunk (10 users),
 * the script POSTs to /api/auth/sign-in/email for those 10 users against
 * LOADTEST_TARGET and aborts the bulk seed if ANY return non-200.
 *
 * Run via: npm run load-test:seed
 * Smoke-login only (no seed): npm run load-test:smoke-login
 *
 * Env vars required (see .env.loadtest.example):
 *   LOADTEST_TENANT_ID    (default: loadtest-tenant)
 *   LOADTEST_PASSWORD     (mandatory)
 *   LOADTEST_TARGET       (mandatory; for smoke-login HTTP call)
 *   LOADTEST_USER_COUNT   (default: 1000)
 *   DATABASE_URL          (mandatory; better-auth instance bootstrap)
 *   BETTER_AUTH_SECRET    (mandatory; better-auth instance bootstrap)
 *   FRONTEND_URL          (mandatory; better-auth instance bootstrap)
 *
 * RESEARCH.md §Open Question 6 RESOLVED:
 *   - Chunks of 10 (NOT 50) — bcrypt CPU saturation
 *   - Target: < 3 min for 1000 users
 *   - Smoke-login validation acceptance criterion
 */
import { PrismaClient } from '@prisma/client';
import { createBetterAuthInstance } from '../src/common/auth/better-auth.instance';
import { EmailService } from '../src/modules/email/services/email.service';

const TENANT_ID = process.env.LOADTEST_TENANT_ID || 'loadtest-tenant';
const PASSWORD = process.env.LOADTEST_PASSWORD;
const USER_COUNT = Number(process.env.LOADTEST_USER_COUNT || 1000);
const LOADTEST_TARGET = process.env.LOADTEST_TARGET;
const CHUNK_SIZE = 10; // RESEARCH §Open Q#6 RESOLVED — bcrypt saturates CPU; 10 not 50
const SMOKE_LOGIN_USER_COUNT = 10;

const SMOKE_LOGIN_ONLY = process.argv.includes('--smoke-login-only');

const prisma = new PrismaClient();

async function smokeLoginValidation(emails: string[]): Promise<void> {
  if (!LOADTEST_TARGET) {
    throw new Error('LOADTEST_TARGET must be set for smoke-login validation');
  }
  const url = `${LOADTEST_TARGET.replace(/\/$/, '')}/api/auth/sign-in/email`;
  console.log(`[smoke-login] validating ${emails.length} users against ${url}`);

  const results = await Promise.all(
    emails.map(async (email) => {
      try {
        const res = await fetch(url, {
          method: 'POST',
          headers: { 'content-type': 'application/json' },
          body: JSON.stringify({ email, password: PASSWORD }),
        });
        return { email, status: res.status, ok: res.status === 200 };
      } catch (err) {
        return { email, status: 0, ok: false, error: String(err) };
      }
    }),
  );

  const failed = results.filter((r) => !r.ok);
  for (const r of results) {
    console.log(`[smoke-login] ${r.email} -> HTTP ${r.status}${r.ok ? ' OK' : ' FAIL'}`);
  }

  if (failed.length > 0) {
    console.error(`[smoke-login] FATAL: ${failed.length}/${emails.length} sign-ins failed`);
    process.exit(1);
  }
  console.log(`[smoke-login] PASS — all ${emails.length} sign-ins returned HTTP 200`);
}

async function main(): Promise<void> {
  if (!PASSWORD) {
    console.error('FATAL: LOADTEST_PASSWORD must be set');
    process.exit(1);
  }
  if (USER_COUNT < 1 || USER_COUNT > 10_000) {
    console.error(`FATAL: LOADTEST_USER_COUNT out of range: ${USER_COUNT}`);
    process.exit(1);
  }

  // ---------- SMOKE-LOGIN-ONLY MODE ----------
  if (SMOKE_LOGIN_ONLY) {
    const emails = Array.from(
      { length: SMOKE_LOGIN_USER_COUNT },
      (_, i) => `loadtest+${i}@pmsync.local`,
    );
    await smokeLoginValidation(emails);
    await prisma.$disconnect();
    return;
  }

  console.log(`[seed] target tenant: ${TENANT_ID}`);
  console.log(`[seed] target user count: ${USER_COUNT}`);

  // Bootstrap better-auth instance (factory needs prisma + emailService).
  // EmailService has a no-arg constructor (verified at email.service.ts:11).
  // sendVerificationEmail will fail silently if SendGrid is not configured —
  // tolerable because we set emailVerified=true directly below.
  const emailService = new EmailService();
  const auth = createBetterAuthInstance(prisma as any, emailService);

  // Ensure tenant exists (multi-tenant rule). Use whatever tenant fields the
  // schema requires; the upsert here is the minimal safe shape — adapt to actual
  // Prisma Tenant model if additional required fields exist.
  const tenant = await prisma.tenant.upsert({
    where: { id: TENANT_ID },
    update: {},
    create: {
      id: TENANT_ID,
      name: 'Load Test Tenant',
    },
  });
  console.log(`[seed] tenant ready: ${tenant.id}`);

  const emails = Array.from({ length: USER_COUNT }, (_, i) => `loadtest+${i}@pmsync.local`);
  let created = 0;
  let skipped = 0;
  let smokeLoginRan = false;

  for (let start = 0; start < emails.length; start += CHUNK_SIZE) {
    const chunk = emails.slice(start, start + CHUNK_SIZE);
    const results = await Promise.allSettled(
      chunk.map(async (email) => {
        // Idempotent: skip if user already exists for this tenant.
        const existing = await prisma.user.findFirst({
          where: { email, tenantId: TENANT_ID },
          select: { id: true },
        });
        if (existing) {
          // Ensure idempotent runs also have emailVerified=true (in case a
          // previous run crashed between signUp and the verification update).
          await prisma.user.update({
            where: { id: existing.id },
            data: { emailVerified: true },
          });
          return { email, status: 'skipped' as const };
        }

        // Real signUp — runs bcrypt and writes user + account rows.
        // No headers / cookies needed for server-side signUpEmail.
        await auth.api.signUpEmail({
          body: {
            email,
            password: PASSWORD!,
            name: `Load Test User ${email}`,
          },
        });

        // Look up the created user to set emailVerified + tenantId.
        // (better-auth doesn't expose tenantId in signUpEmail body; we set it after.)
        const created = await prisma.user.findFirst({
          where: { email },
          select: { id: true },
        });
        if (!created) {
          throw new Error(`User row missing after signUpEmail for ${email}`);
        }
        await prisma.user.update({
          where: { id: created.id },
          data: {
            emailVerified: true,
            tenantId: TENANT_ID,
          },
        });
        return { email, status: 'created' as const };
      }),
    );

    for (const r of results) {
      if (r.status === 'fulfilled') {
        if (r.value.status === 'created') created++;
        else skipped++;
      } else {
        console.error(`[seed] error:`, r.reason);
      }
    }
    const done = Math.min(start + CHUNK_SIZE, emails.length);
    console.log(`[seed] progress: ${done}/${emails.length} (created=${created} skipped=${skipped})`);

    // After the FIRST chunk completes, run smoke-login validation BEFORE
    // continuing the bulk seed. If smoke-login fails, abort early so the
    // operator doesn't wait 3 minutes only to discover seeding is broken.
    if (!smokeLoginRan && done >= SMOKE_LOGIN_USER_COUNT) {
      const smokeEmails = emails.slice(0, SMOKE_LOGIN_USER_COUNT);
      await smokeLoginValidation(smokeEmails);
      smokeLoginRan = true;
    }
  }

  console.log(`[seed] done — created=${created} skipped=${skipped}`);
  await prisma.$disconnect();
}

main().catch((err) => {
  console.error('[seed] fatal:', err);
  process.exit(1);
});

## Commands

All commands run from `backend/` directory:

```bash
# Seed 1000 synthetic users in loadtest-tenant via better-auth's signUpEmail
# (proper bcrypt + account row). Runs smoke-login validation on first 10 users
# before bulk-seeding remaining 990 — aborts early if auth is broken.
npm run load-test:seed

# Re-run smoke-login check against existing seeded users (no new users created)
npm run load-test:smoke-login

# 10-VU / 30-s smoke — verifies config loads + auth flow works
npm run load-test:smoke

# Full 100/500/1000 ramp (takes ~22 min total)
npm run load-test:1000

# Generate HTML report from the latest JSON output
npm run load-test:report
# Opens: load-test/report.html

# MANDATORY AFTER EVERY RUN — deletes loadtest-tenant rows
npm run load-test:cleanup
```

**Chain seed → test → cleanup in CI:**
```yaml
- run: npm run load-test:seed
- run: npm run load-test:smoke
- run: npm run load-test:cleanup
  if: always()   # run even if the test failed
```

## Reading the Report

After `npm run load-test:report`, open `load-test/report.html`. Key sections:

| Section | What to look for |
|---|---|
| **Summary** | `http.codes.200` count ≈ `http.requests` count; `errors.*` should be near-zero. |
| **Latency histograms** | `http.response_time.p95` per endpoint. The aggregate p95 is a bad metric — check per-endpoint (plugin `metrics-by-endpoint`). |
| **Phases** | Each phase should show sustained throughput matching its `arrivalRate`. If phase 5 (hold 1000) shows a drop to 700, the server is rejecting requests. |
| **errors.ECONNREFUSED / ETIMEDOUT** | The load generator's network is overwhelmed, not the server. Re-run from a bigger machine. |
| **errors.EHOSTUNREACH** | DNS / Railway service down. Check `LOADTEST_TARGET`. |

## Known Pitfalls (from RESEARCH.md)

1. **Tenant leak (Pitfall 5):** If `load-test:cleanup` is skipped, `loadtest-tenant` rows accumulate and pollute aggregate dashboards. ALWAYS run cleanup after the test. The npm script includes a safety guard that refuses to delete tenants whose ID doesn't start with `loadtest-`.

2. **LRU access-gated TTL (Pitfall 6):** Not relevant to this runbook (and no longer relevant to Plan 02 either after revision v2 deleted the unused tenantCounters Map).

3. **Per-user RAM dominated by buffer churn (Pitfall 7):** Take RAM measurements at STEADY STATE — 5+ minutes into the 1000-VU hold phase — not during the ramp. Ramping allocates transient Buffer objects that skew `rss`; the 15-min hold gives V8's GC time to drain them.

4. **k6 for Socket.IO:** Don't try it. k6's `ws` module speaks raw WebSocket; Socket.IO's framing/heartbeat/ack protocol will not be exercised. Metrics lie.

5. **Load-testing from home Wi-Fi:** Your uplink is ~10 Mbps. Artillery at 1000 VUs × 50 KB/req needs ≥400 Mbps. Use GitHub Actions or an EC2 t3.large.

6. **Missing baseline:** SCALE-05 (Plan 04) runs the CURRENT topology's baseline BEFORE the split. Do not interpret the first post-split run in isolation — always compare before/after.

7. **Seed bypassing better-auth:** v1 of the seed script used `prisma.user.create` directly, which skipped bcrypt password hashing. Result: every Artillery `/sign-in/email` returned 401. v2 (current) uses `auth.api.signUpEmail` and includes a smoke-login validation step against the first 10 seeded users — if that step fails, the seed exits non-zero before bulk seeding the remaining 990. Never revert this without re-validating signUp pipeline.

## Rollback Procedure

If a load test uncovers a regression severe enough to halt the phase:

1. `npm run load-test:cleanup` (delete loadtest-tenant).
2. Revert the most recent phase commits that affect the system under test.
3. Re-run `load-test:smoke` against the reverted state to confirm recovery.
4. Document the regression in a new `.planning/phases/XXX-regression/` directory before resuming phase 157.

The load-test rig itself is reversible: `git revert` the commits from phase 157 plan 03 removes all load-test files. The only out-of-tree artifact is the seeded `loadtest-tenant` — cleanup handles it.
