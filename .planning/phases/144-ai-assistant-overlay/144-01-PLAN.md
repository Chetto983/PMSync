**1. Create `frontend/stores/ai-overlay-store.ts`:**

Create a Zustand store following the exact pattern from `email-ui-store.ts` (devtools + persist middleware). The store manages overlay open/close state and resizable width.

```typescript
import { create } from 'zustand';
import { devtools, persist, createJSONStorage } from 'zustand/middleware';

export const DEFAULT_WIDTH = 420;
export const MIN_WIDTH = 320;
export const MAX_WIDTH = 600;

interface AiOverlayState {
  isOpen: boolean;
  width: number;
  toggleOpen: () => void;
  open: () => void;
  close: () => void;
  setWidth: (w: number) => void;
}

export const useAiOverlay = create<AiOverlayState>()(
  devtools(
    persist(
      (set) => ({
        isOpen: false,
        width: DEFAULT_WIDTH,
        toggleOpen: () => set((s) => ({ isOpen: !s.isOpen })),
        open: () => set({ isOpen: true }),
        close: () => set({ isOpen: false }),
        setWidth: (w: number) =>
          set({ width: Math.max(MIN_WIDTH, Math.min(MAX_WIDTH, w)) }),
      }),
      {
        name: 'pmsync:ai-overlay-width',
        storage: createJSONStorage(() => localStorage),
        partialize: (state) => ({ width: state.width }),
        // isOpen is NOT persisted -- always starts closed (per D-12)
      }
    ),
    { name: 'ai-overlay-store' }
  )
);
```

Per D-10: default 420px, min 320px, max 600px. Per D-11: persist width to localStorage key `pmsync:ai-overlay-width`. Per D-12: `isOpen` is ephemeral (always `false` on page load).

Create `frontend/hooks/use-page-context.ts` -- a reactive hook that reads `next/router` pathname + query parameters and Zustand store selectors to determine the current page context type.

```typescript
import { useMemo } from 'react';
import { useRouter } from 'next/router';
import { useEmailUIStore } from '@/stores/email-ui-store';
import { useContactStore } from '@/stores/contact-store';
import { useCalendarStore } from '@/stores/calendar-store';

export type PageContextType = 'email' | 'contact' | 'deal' | 'calendar' | 'general';

export interface PageContext {
  type: PageContextType;
  entityId: string | null;
  label: string;
  metadata: Record<string, unknown>;
}

const GENERAL_CONTEXT: PageContext = {
  type: 'general',
  entityId: null,
  label: '',
  metadata: {},
};
```

Implementation rules:
- Use `useRouter()` to get `pathname` and `query`
- Use Zustand store hook selectors (NOT `.getState()`) so the hook re-renders when stores change (per D-07: context updates on navigation)
- From `useEmailUIStore`: read `activeThreadId` and `activeEmailId` using a selector `(s) => ({ activeThreadId: s.activeThreadId, activeEmailId: s.activeEmailId })`
- From `useContactStore`: read `selectedContact` using `(s) => s.selectedContact`
- From `useCalendarStore`: read `selectedEvent` using `(s) => s.selectedEvent`

Route matching logic:
1. **Email** (`/dashboard/email` prefix): `type: 'email'`, `entityId` from `query.threadId` (string) or `activeThreadId` from email-ui-store, `label` = active email subject if available from store or empty string, `metadata` = `{ threadId, emailId: activeEmailId }`
2. **Contact** (`/dashboard/contacts/[contactId]`): `type: 'contact'`, `entityId` from `query.contactId` (string), `label` = `selectedContact?.name || selectedContact?.email || ''`, `metadata` = `{ name: selectedContact?.name, email: selectedContact?.email, company: selectedContact?.company }`
3. **Deal** (`/dashboard/crm/deals/` prefix with `query.dealId`): `type: 'deal'`, `entityId` from `query.dealId` (string), `label` = empty string (deal name is not in a Zustand store -- TanStack Query cache; keep label empty and let ContextIndicator handle it), `metadata` = `{ dealId: query.dealId }`
4. **Calendar** (`/dashboard/calendar` prefix): `type: 'calendar'`, `entityId` from `selectedEvent?.id || null`, `label` = `selectedEvent?.title || ''`, `metadata` = `{ title: selectedEvent?.title, start: selectedEvent?.start, end: selectedEvent?.end }`
5. **General** (all other routes): return `GENERAL_CONTEXT`

Wrap the computation in `useMemo` depending on `pathname`, `query`, `activeThreadId`, `activeEmailId`, `selectedContact`, `selectedEvent`.

The hook does NOT make API calls -- it reads existing client-side state only (per D-09). Context gracefully degrades: if an entity ID is detected from the route but no store data is available yet, return the context type with `entityId` set but `label` as empty string. The ContextIndicator component will show the type icon without a label until data loads.

Export: `usePageContext`, `PageContext`, `PageContextType`.
