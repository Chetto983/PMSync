**2. Create `frontend/components/ai-overlay/PageContextInjector.tsx`:**

A zero-UI component that syncs the `usePageContext()` hook output to the module-scoped cache.

```typescript
'use client';

import { useEffect } from 'react';
import { usePageContext } from '@/hooks/use-page-context';
import { setPageContext } from '@/src/components/chat/ChatRuntimeProvider';

/**
 * Syncs usePageContext hook output to the module-scoped cache
 * in ChatRuntimeProvider. Mounted in Layout.tsx alongside
 * AiOverlayDrawer so the transport always has current context.
 */
export function PageContextInjector() {
  const ctx = usePageContext();

  useEffect(() => {
    setPageContext(ctx);
    return () => {
      setPageContext(null);
    };
  }, [ctx]);

  return null;
}
```

This component renders nothing. It exists solely to bridge the React hook world (usePageContext uses useRouter + Zustand hooks) to the module-scoped variable world (transport's prepareSendMessagesRequest reads pageContextCache).

The cleanup function sets `null` on unmount so that if the Layout unmounts (logout), the cache is cleared.

```typescript
// Phase 144: Inject page context from AI overlay into system prompt
if (params.pageContext && params.pageContext.type !== 'general') {
  const pc = params.pageContext;
  const VALID_TYPES = new Set(['email', 'contact', 'deal', 'calendar']);
  if (VALID_TYPES.has(pc.type)) {
    // Sanitize: limit label and metadata values to prevent prompt injection
    const safeLabel = typeof pc.label === 'string' ? pc.label.slice(0, 200) : '';
    const safeMetadata = Object.fromEntries(
      Object.entries(pc.metadata || {}).map(([k, v]) => [
        k.slice(0, 50),
        typeof v === 'string' ? v.slice(0, 500) : v,
      ]),
    );

    systemPromptWithMemory += `\n\n## Current User Context\nThe user is currently viewing a ${pc.type} entity.\n`;
    if (safeLabel) {
      systemPromptWithMemory += `Entity: ${safeLabel}\n`;
    }
    if (pc.entityId) {
      systemPromptWithMemory += `Entity ID: ${pc.entityId}\n`;
    }
    const metaEntries = Object.entries(safeMetadata).filter(([, v]) => v != null && v !== '');
    if (metaEntries.length > 0) {
      systemPromptWithMemory += `Details:\n`;
      for (const [key, value] of metaEntries) {
        systemPromptWithMemory += `- ${key}: ${value}\n`;
      }
    }
    systemPromptWithMemory += `\nUse this context to provide relevant assistance. Reference the entity naturally in your responses when appropriate.`;
  }
}
```

**Security considerations:**
- Only 4 known types are accepted (whitelist via VALID_TYPES set); 'general' is skipped entirely
- Label is truncated to 200 characters to prevent prompt bloat
- Metadata keys truncated to 50 chars, string values to 500 chars
- The context block is appended to the system prompt, not interpolated into it, preventing injection into existing prompt structure

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend -> Backend (pageContext in request body) | Client-supplied context metadata crosses trust boundary into system prompt |
| System prompt -> LLM | Injected context could influence model behavior |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-144-08 | Tampering | pageContext in request body | mitigate | Backend validates pageContext.type against whitelist of 4 known strings; rejects unknown types. Label truncated to 200 chars, metadata values to 500 chars. Context appended as a structured block (not interpolated) to prevent system prompt injection. |
| T-144-09 | Information Disclosure | pageContext metadata in system prompt | accept | Metadata contains only entity IDs and display labels already visible to the authenticated user. Backend does not expose new data -- it receives what the user's browser already has. TenantGuard ensures user can only chat within their tenant. |
| T-144-10 | Elevation of Privilege | pageContext entityId spoofing | accept | The entityId in pageContext is informational only -- the system prompt says "user is viewing entity X" but the AI tools already enforce tenantId-scoped queries independently. A spoofed entityId would mislead the AI's conversational context but cannot grant access to another tenant's data. |
</threat_model>
