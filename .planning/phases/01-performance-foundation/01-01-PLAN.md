Create migration for partial index optimizing "unread emails sorted by date" query:

1. Create migration file `backend/prisma/migrations/20260202_composite_indexes/migration.sql`:
```sql
-- Partial composite index for unread emails sorted by receivedAt
-- Optimizes the most common email list query: WHERE isRead = false ORDER BY receivedAt DESC
-- Using partial index (WHERE isRead = false) reduces index size by ~80% for typical mailboxes
CREATE INDEX CONCURRENTLY IF NOT EXISTS "emails_unread_by_date_idx"
  ON "emails" (tenant_id, received_at DESC)
  WHERE is_read = false;

COMMENT ON INDEX "emails_unread_by_date_idx" IS
  'Partial index for unread emails sorted by date. Covers ~20% of emails, used by inbox list views.';
```

2. Do NOT modify schema.prisma - Prisma doesn't support partial indexes in schema, so we manage this index via raw SQL migration only. The existing `@@index([tenantId, isRead])` remains as-is for other query patterns.

3. Create empty migration.lock file to prevent Prisma from trying to regenerate this migration.
  </action>
