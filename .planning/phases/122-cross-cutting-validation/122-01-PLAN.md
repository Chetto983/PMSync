    **File 1: `scripts/lib/validate-tenant-isolation.mjs`**
    Export: `async function validateTenantIsolation(context, cookieHeader, csrfToken)`
    Returns: array of `{ name, status, detail }` result objects.

    IMPORTANT -- TenantGuard behavior: The guard reads `X-Tenant-ID` header (line 38-43 of tenant.guard.ts) and uses it preferentially over `user.tenantId`. Injecting a non-existent tenant UUID causes "tenant not found" -> 403. Injecting a real but different tenant UUID causes "cross-tenant access" -> 403. Both paths are valid isolation checks.

    Checks (XCUT-01):
    - `XCUT-01a: GET /api/v1/emails rejects cross-tenant header` -- Make GET request to `BACKEND_URL + '/api/v1/emails?limit=1'` with valid cookies but add header `X-Tenant-ID: 00000000-0000-0000-0000-000000000000` (fake UUID). Expect HTTP 403. If 200, FAIL.
    - `XCUT-01b: GET /api/v1/folders rejects cross-tenant header` -- Same pattern with `/api/v1/folders`. Expect 403.
    - `XCUT-01c: GET /api/v1/signatures rejects cross-tenant header` -- Same pattern with `/api/v1/signatures`. Expect 403.
    - `XCUT-01d: GET /api/v1/templates rejects cross-tenant header` -- Same pattern with `/api/v1/templates`. Expect 403.
    - `XCUT-01e: Normal request returns only authenticated tenant data` -- Make GET to `/api/v1/emails?limit=1` with valid cookies, no fake header. Expect 200. Additionally, if `body.data` is a non-empty array, verify every item has a `tenantId` field matching the authenticated user's tenant (extract tenant from the response's `meta` or from a separate `/api/v1/auth/session` call). This confirms Prisma tenant-scoping filters results to the correct tenant.

    Use `context.request` (Playwright APIRequestContext) for all HTTP calls. Import `BACKEND_URL` from `validation-helpers.mjs`.

    **File 2: `scripts/lib/validate-rate-tiers.mjs`**
    Export: `async function validateRateTiers(context, cookieHeader, csrfToken)`
    Returns: array of `{ name, status, detail }` result objects.

    Checks (XCUT-02):
    - `XCUT-02a: Static audit -- all email controllers have TenantGuard` -- Use `execSync` to grep all `*.controller.ts` files under `backend/src/modules/email/` and `backend/src/modules/email-sync/` and `backend/src/modules/labels/` for `@UseGuards(` containing `TenantGuard`. Count controllers found vs expected (11 total: 9 email + 1 email-sync + 1 labels). PASS if all 11 found.

For each `@Delete(` found, verify `@RateTierDecorator` appears within 5 lines above it. Also check `sync-all` and `queues/clear` POST routes. PASS if all destructive endpoints have explicit tier.
    - `XCUT-02c: Static audit -- send endpoints have send tier` -- Grep for `@RateTierDecorator('send')` in email-actions and email-calendar-invite controllers. Expect at least 3 in email-actions (send, reply, forward) and at least 2 in email-calendar-invite. PASS if counts match.
    - `XCUT-02d: Live -- rate limiter returns X-RateLimit headers` -- Make a GET request to `BACKEND_URL + '/api/v1/emails?limit=1'` and check for presence of `x-ratelimit-limit` or `retry-after` response headers (throttler adds these). PASS if header present OR if request succeeds (throttler is active but may not add headers on non-throttled requests -- check `X-Request-ID` as proxy for middleware chain).

    **File 3: `scripts/lib/validate-response-envelope.mjs`**
    Export: `async function validateResponseEnvelope(context, cookieHeader, csrfToken)`
    Returns: array of `{ name, status, detail }` result objects.

    Checks (XCUT-03):
    - `XCUT-03a: Success response has { data, meta } shape` -- GET `/api/v1/emails?limit=1`. Parse JSON. Assert `body.data !== undefined` and `body.meta !== undefined` and `typeof body.meta.requestId === 'string'` and `body.meta.requestId !== 'unknown'` and `typeof body.meta.timestamp === 'string'`.
    - `XCUT-03b: Success response X-Request-ID header matches meta.requestId` -- Same request. Check response header `X-Request-ID` equals `body.meta.requestId`.
    - `XCUT-03c: Error response has { error, meta } shape` -- GET `/api/v1/emails/00000000-0000-0000-0000-000000000000` (nonexistent UUID). Expect 404. Parse JSON. Assert `body.error !== undefined` and `body.error.code !== undefined` and `body.error.message !== undefined` and `body.meta !== undefined` and `typeof body.meta.requestId === 'string'`.
    - `XCUT-03d: Validation error has { error, meta } shape` -- GET `/api/v1/emails?limit=-1` or POST `/api/v1/signatures` with empty body (expect 400/422). Parse JSON. Assert same error envelope shape.
    - `XCUT-03e: Client-provided X-Request-ID is echoed` -- GET `/api/v1/emails?limit=1` with header `X-Request-ID: test-correlation-122`. Assert response header `X-Request-ID` equals `test-correlation-122` and `body.meta.requestId` equals `test-correlation-122`.
