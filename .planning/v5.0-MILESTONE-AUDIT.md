- `frontend/proxy.ts` has correct route protection logic
- But Next.js requires `middleware.ts` with `export function middleware()`
- File has wrong name (`proxy.ts`) and wrong export (`proxy`)
- Impact: Zero server-side route protection — `/dashboard` accessible without auth
- Fallback: Client-side `useSession()` redirects, but with content flash
- Affected: FEUI-04
- Fix: Rename file + function

- `frontend/lib/auth.ts` creates a 2nd server-side instance with different config
- Diverges from backend canonical instance (cookieCache, audit hooks, workspace provisioning)
- Consumed only by `frontend/pages/api/onboarding/create-workspace.ts`
- Risk: Session validation behavior divergence
