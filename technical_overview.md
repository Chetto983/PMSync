# Technical Overview - MailAgent

## Project Architecture

MailAgent is a multi-tenant email management platform with AI-powered features built on a modern NestJS + Next.js stack.

**Framework:** NestJS 11 (Backend) + Next.js 16 (Frontend)

---

## Core Components

### 1. Email Sync System

**Description:** Unified email synchronization across Gmail, Microsoft Outlook, and IMAP providers.

**Key Files:**

- `backend/src/modules/email-sync/drivers/` - Provider-specific drivers
- `backend/src/modules/email-sync/services/` - Sync orchestration
- `backend/src/modules/providers/` - OAuth and token management

**Design Patterns:**

- Interface → Factory → Implementation (IEmailDriver pattern)
- Canonical folder types (INBOX, SENT, TRASH, etc.)
- BullMQ queues for async sync jobs

### 2. VoltAgent AI System

**Description:** Multi-agent AI system for intelligent email operations.

**Key Files:**

- `backend/src/modules/ai/voltagent/agents/` - Agent definitions
- `backend/src/modules/ai/voltagent/tools/` - 35+ AI tools
- `backend/src/modules/ai/voltagent/services/` - HITL, caching, routing

**Design Patterns:**

- Supervisor agent orchestrates sub-agents (email, calendar, contacts)
- Human-in-the-loop (HITL) for high-stakes actions
- Semantic caching for 50-60% cost reduction
- Model routing for intelligent model selection

### 3. Authentication & Multi-Tenancy

**Description:** JWT-based auth with MFA, tenant isolation for all data.

**Key Files:**

- `backend/src/modules/auth/` - Guards, strategies, MFA
- `backend/src/common/services/` - Shared tenant-aware services

**Design Patterns:**

- Every entity has `tenantId` field
- Guards enforce tenant isolation
- OAuth token encryption (AES)

## Component Interactions

### Email Sync Flow

```text
OAuth Callback
  → ProviderTokenService (store encrypted tokens)
  → SyncSchedulerService (queue initial sync)
  → BullMQ Worker
  → EmailDriver (Google/Microsoft/IMAP)
  → PrismaService (persist emails)
  → RealtimeGateway (notify frontend)
```

### AI Chat Flow

```text
User Message
  → VoltAgentController
  → RateLimiterService (check limits)
  → SemanticCacheService (check cache)
  → ModelRouterService (select model)
  → SupervisorAgent (orchestrate)
  → Tool Execution (email/calendar/contacts)
  → HitlService (if approval needed)
  → Response to User
```

### Daily Briefing Flow

```text
BullMQ Scheduler (hourly)
  → DailyBriefingService
  → Check user timezone
  → Get unread emails
  → MistralService (generate summary)
  → CacheService (store in Redis)
  → Available via GET /api/v1/voltagent/briefing
```

## Key Design Decisions

1. **Multi-tenant from day one**: All entities have tenantId, enforced at guard level. Enables SaaS deployment.

2. **Provider abstraction**: IEmailDriver interface allows adding new providers without changing core logic.

3. **BullMQ over in-process**: Sync jobs run in workers for horizontal scaling and fault tolerance.

4. **Redis for everything hot**: Session cache, semantic cache, rate limiting, real-time pub/sub.

5. **HITL for safety**: High-stakes AI actions (send, delete, calendar create) require user approval.

6. **Semantic caching**: Reduces LLM costs by 50-60% by caching similar queries.
