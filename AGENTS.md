## Tech Stack

### Backend (`backend/`)
- **Framework**: NestJS 11
- **ORM**: Prisma with PostgreSQL
- **Queue**: BullMQ with Redis
- **AI**: Mistral AI (LLM) + pgvector (embeddings)
- **Realtime**: Socket.IO

### Frontend (`frontend/`)
- **Framework**: Next.js 16 + React 19
- **State**: TanStack Query + Zustand
- **UI**: Tailwind CSS + MUI
- **API Client**: Custom hooks in `hooks/`

## Code Style Guidelines

**TypeScript:**
- Strict mode enabled
- Use interfaces over types for objects
- Async/await over raw promises

**NestJS:**
- Services in `*.service.ts`, Controllers in `*.controller.ts`
- Use dependency injection
- All queries must be tenant-scoped

**React:**
- Functional components with hooks
- Feature-based component organization
- Use TanStack Query for server state

## Key Patterns

### Multi-Tenant Architecture
Every entity has `tenantId`. NEVER query without tenant filter:
```typescript
// CORRECT
await prisma.email.findMany({ where: { tenantId, ... } });

// WRONG - Security vulnerability!
await prisma.email.findMany({ where: { ... } });
```

### Provider Pattern
All email providers follow: Interface → Factory → Implementation
```
IEmailDriver → EmailDriverFactory → GoogleDriver / MicrosoftDriver
```

### Canonical Folder Types
Normalize folders across providers:
- Gmail labels → INBOX, SENT, DRAFTS, TRASH, SPAM
- Microsoft wellKnownName → Same canonicals

   - Include testing results

4. **Then commit**:

   - Write clear commit message
